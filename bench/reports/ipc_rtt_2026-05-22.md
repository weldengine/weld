## Analyse

- **p50 = 5 µs**, structurellement sous baseline 6 µs. Le swap E2 (Wyhash legacy → RTTI computeSchemaHash) est purement comptime — au runtime, l'IPC ne fait aucun appel hash sur le hot path (la valeur `schema_hash` est bakée dans le binaire). Toute différence runtime est imputable au bruit machine.
- **p99 et max sous baseline aussi** : le run a été particulièrement clean — pas de gros syscall qui accroche le scheduler kernel.
- **stddev 3 µs** : variance dev-mode équivalente à la baseline cold-isolé S6. Le bench loopback `socketpair()` est suffisamment local pour résister à la majorité du bruit OS.

## Gate

**GO**. Le gate de non-régression E2/E6 (p50 ≤ 0.0063 ms — baseline +5 %) est respecté avec marge.

## Comparaison post-swap S6 vs E6 final

| E2 post-swap (5-run dev-mode) | médiane des médianes 8 µs | NOISY — re-bench planifié |

Le bench E2 archivé précédemment (médiane 8 µs) reflétait une session lourdement chargée (build serveur + Claude Code actifs). Cette mesure E6, après libération partielle de la session, retrouve un palier sous-baseline. Confirme la signature « comptime swap, runtime no-op » de E2.

## Conclusion

Non-régression IPC RTT validée pour le tag M0.2. Le verdict GO est robuste : p50/p99/max tous sous baseline cold-isolé S6, malgré le mode dev-mode. La re-bench cold-isolé sur machine vide reste planifiable pré-tag pour formalisation, mais le résultat ne devrait pas dévier.
