## Scope

- **C1 (P1) — identity release must be allocation-free by construction** (`src/core/ecs/entity.zig`, `src/core/ecs/world.zig`). Root cause: `World.despawn` performs `removeSwap` → `entity_locations.remove` → `purgeEntityExtensions` (all non-undoable) *before* the fallible `identity.release`; and the three spawn paths (`spawn`, `spawnDynamic`, `spawnDynamicWithValues`) carry `errdefer self.identity.release(gpa, eid) catch {}` that swallows an `OutOfMemory` from `release`'s internal `ensureUnusedCapacity`, stranding a live slot with no location. Fix — establish the invariant **"an allocated handle can always be released without allocation"** at the identity store: `EntityIdentityStore.allocate` reserves the free-list slot the eventual release will need. The recycled path (`free_indices.pop()`) already frees a slot of free-list capacity for the re-push; the fresh path (`slots.append`) must `free_indices.ensureUnusedCapacity(gpa, 1)` **before** growing `slots` (allocate stays reserve-then-mutate). `release` then becomes infallible `void` (`appendAssumeCapacity`, no `try`), signature changes `WorldError!void` → `void`. Consequently: `despawn` drops the `try` on `release`; the three spawn errdefers become `errdefer self.identity.release(eid)` (no `catch {}`); the in-file test callers drop their `try`. One point of enforcement, no per-call-site ceremony. This subsumes and supersedes the narrower "add `ensureReleaseCapacity` to despawn only" first sketch.

- **C4 (P1) — uniform resource-payload teardown owned by Tier-0 `World`** (`src/core/ecs/world.zig`, `src/etch/interp.zig`). Root cause: `Interpreter.deinit` is the *only* walk that decrefs resource `.string_`/`.array_`/`.map_`/`.set_` slots; it iterates `bridge.resources`. A `World` with no interpreter (e.g. the scene loader over a bare world) and any resource not registered in `bridge.resources` leak. `World.deinit` (`resources.deinit`) does no decref. `persistent.zig` has been Tier-0 since M1.0.5 (`git mv src/etch/ → src/core/memory/`, `loader.zig:36` imports `../memory/persistent.zig`), so Tier-0 already owns the persistent heap — this is *not* a doctrine reversal.

  **Ordering constraint (load-bearing).** `Interpreter.deinit` runs before `World.deinit` and destroys its immortal `persistent_literals` (`interp.zig:~1249`). `persistent.decref` reads the block header immediately (`persistent.zig:210-211`). Moving the walk *only* into `World.deinit` would make `World.deinit` decref a slot still pointing at a *freed* immortal block → use-after-free.

  Fix — add an **idempotent** Tier-0 method `World.releaseResourcePayloads(self: *World, gpa)`: iterate every resource, decref each `.string_`/`.array_`/`.map_`/`.set_` slot via the registry `FieldKind` descriptors, then **zero each slot** (`ptr = 0`) so a second call no-ops. Call it (a) from `Interpreter.deinit` **before** destroying `persistent_literals`; (b) from `World.deinit` **before** `resources.deinit`. Remove the `bridge.resources`-specific walk from `Interpreter.deinit`; **keep** the immortal-literal destruction there (interp is their allocator). Coverage: worlds without an interpreter, and resources outside `bridge.resources`, both handled; no double-decref (idempotent zeroing); no UAF (walk precedes literal destruction on the interp path). Doctrine nuance to record (CLAUDE.md + this brief, NOT a KB spec file — engine-ecs-internals.md carries no teardown/ownership section): Tier-0 `ResourceStore` stays string-agnostic *in write* (`resources.deinit` still only frees byte blocks), but `World` owns the uniform decref walk.

- **C6 (P2) — scene-load rollback must restore the resource dirty bit** (`src/core/ecs/resources.zig`, `src/core/scene/loader.zig`). Direct regression of D2. `getMutResource` (`resources.zig:88`) sets `dirty = true` unconditionally; the D2 rollback path calls it twice per edit (decref + memcpy restore). A rejected scene load therefore leaves touched resources dirty → a spurious `when resource T changed` next tick. Fix — `ResourceEdit` captures the pre-write dirty state (`dirty_before: bool`) at the same point it snapshots the value bytes (before the first mutating write). `rollbackResources` restores it via a new Tier-0 setter `ResourceStore.setDirty(id, value)` (**must be `pub`** for the cross-file loader call — Zig visibility; documented explicitly internal by name + doc-comment). On commit (success) the dirty bit stays `true` (the resource genuinely changed) — no change to the commit path.

- **C2 (P1) — scene `instantiate` must pre-reserve its maps** (`src/core/scene/loader.zig`). `instantiate` does `try world.spawnDynamicWithValues` then `try uuid_to_entity.put` then `try spawned.append`. An OOM on the put/append leaves the just-spawned entity absent from `spawned`, so `loadFromBytes`'s reverse-despawn errdefer never reclaims it → orphan outside the rollback. Fix — the totals are known from the accessor (sum of per-block `entity_count`, and `uuidCount`); pre-reserve `uuid_to_entity.ensureTotalCapacity` and `spawned.ensureTotalCapacity` to those totals once, up front, then use `putAssumeCapacity` / `appendAssumeCapacity` in the loop. The spawn itself stays fallible (it allocates archetype storage); on its failure nothing was inserted, so the existing errdefer covers it. The reservation removes the *post-spawn* fallible inserts that were the orphan window.

- **C3 (P1) — asset `Loader.finish` must reserve the payload slot before allocating the registry handle** (`src/modules/asset_pipeline/loader/Loader.zig`). Pre-existing, out of HF1 scope. `finish` does `registry.allocWithUuid` (succeeds) then `payloads.put` (may OOM) → the catch calls `registry.unload catch {}`, but `unload`→`freeSlot` itself allocates the free-list and can OOM too; the error is swallowed, leaving a live handle with no payload and `raw.bin` already freed — an undischargeable slot. Fix — `payloads.ensureUnusedCapacity(gpa, 1)` **before** `allocWithUuid`; the subsequent `payloads.put` becomes `putAssumeCapacity`, infallible. On the reservation's own OOM, `raw.bin` is freed and the error returned with no handle allocated (reserve-then-mutate). The fragile `unload catch {}` unwind is removed.

- **C5 (P1) — IPC send must not let SIGPIPE kill the process** (`src/core/ipc/transport_posix.zig`). Pre-existing. `writeAll` (`:239`) uses raw `sys.write`, on which `MSG_NOSIGNAL` cannot be set; `MSG_NOSIGNAL` is Linux-only and applies only to `sendmsg`; no `SO_NOSIGPIPE` is set anywhere. A peer close makes the primary `send()` path SIGPIPE-fatal on every POSIX, and `sendWithHandles`'s remainder (which routes through `writeAll`) fatal on BSD/macOS. Fix — (a) `writeAll` uses `sys.send(fd, ptr, len, MSG_NOSIGNAL)` instead of `sys.write` (Linux: flag suppresses the signal); (b) at fd creation (`connect` result and `accept` result) set `SO_NOSIGPIPE` via `setsockopt` on platforms that define it (BSD/macOS) — a best-effort call, ignore `ENOPROTOOPT` on platforms that lack it (Linux, where the flag carries the guarantee). EINTR/`n==0` semantics of the existing loop are preserved verbatim.

**Gate-review addendum (the HF1 process fix — normative for HF2 review).** At every gate, the reviewer crosses the **reserve-then-mutate invariant** against *every composite call surface that reaches the changed leaf*, not the gate's deliverable in isolation. Concretely: E1's review must confirm the invariant holds at `despawn`, `spawn`, `spawnDynamic`, `spawnDynamicWithValues` — not only at `EntityIdentityStore.release`. E3's review must confirm `instantiate` and `loadFromBytes` rollback reach no fallible mutation after the first observable one. E4's review must confirm `finish` reserves before it allocates the handle. The HF1 miss (C1/C2) was precisely a review that verified each leaf against its own change and never re-crossed the invariant against the composite callers.

**C1 invariant statement (normative, for the commit body):** *an allocated handle can always be released without allocation.* `allocate` owns the reservation; `release` is infallible. Recycled-slot allocate frees the capacity its re-push needs; fresh-slot allocate reserves it before growing the slot table.

**C4 ordering (normative, load-bearing):** on the interpreter path, `releaseResourcePayloads` runs **before** `persistent_literals` destruction; `releaseResourcePayloads` zeroes each slot so the subsequent `World.deinit` call is a no-op. Do not reorder — reordering reintroduces the immortal-block UAF.

**C5 testability:** SIGPIPE-on-peer-close and partial `send` cannot be forced portably in a unit test. Acceptance for C5 is the code shape (`send`+`MSG_NOSIGNAL`; `SO_NOSIGPIPE` at fd creation with graceful `ENOPROTOOPT` handling) plus the existing IPC handle round-trip suite staying green. Do not add a flaky signal-based test.

**C6 setter visibility:** `ResourceStore.setDirty` is `pub` solely because the scene loader (a different Zig file) restores the flag on rollback. It is a Tier-0-internal seam, not a public runtime API — name and doc-comment must say so. No Etch surface, no plugin-C surface.

## Recorded deviations

- **B1 (E1, Claude.ai round-trip 2026-07-14) — C1 fresh-path reservation corrected.** The frozen §C1 prescribed `free_indices.ensureUnusedCapacity(gpa, 1)` on the fresh path. That call reduces to `capacity >= 1` (the fresh path is only taken when `pop()` returned null, i.e. `len == 0`) and never establishes the required invariant `free_indices.capacity >= slots.len`; releases overflow `appendAssumeCapacity` (repro: N=1000, overflow at release #33). Corrected mechanism, adopted: on the fresh path, `free_indices.ensureTotalCapacity(gpa, self.slots.items.len + 1)` **before** growing `slots` (reserve-then-mutate: an OOM here mutates nothing observable). Zig std's geometric growth keeps this amortized O(1). The recycled path is unchanged — `pop()` decrements `len` under a capacity already ≥ `slots.len`, so the invariant is preserved trivially. The normative C1 statement becomes: *allocate maintains `free_indices.capacity >= slots.len` at all times; release is infallible `appendAssumeCapacity`.* Acceptance test unchanged (it is exactly what the repro validates).
