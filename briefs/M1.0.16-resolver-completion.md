## Context

Two name-resolution gaps of the C1.6 plan, both at the resolver / type-check layer. **(1) Module-alias qualified access `m.Type`.** `bindImports` already records the whole-module alias binding in `imported_aliases` (for `import a.b` and `import a.b as m`), but that binding is never consumed, AND the qualified syntax itself does not parse: `etch-grammar.md` has no qualified-path production (`base_type` is a single `TYPE_IDENT`; `postfix_op` has `. IDENT` only), while `etch-resolver-types.md §3.1`/§2.3 assume `math.Vec3` is resolvable. `TypeNodeKind.path` is reserved in `ast.zig` but never produced. So volet 1 is a small grammar addition + parser + resolver — not resolver wiring alone. **(2) `private` completion per §10.2.** Today only direct visibility + `E0107 ImportPrivateItem` (on selective import) exist; visibility inheritance and `W0902 PrivateTypeInPublicImpl` are missing. This is a resolver-level milestone: qualified names resolve, type-check, and diagnose correctly under `validateProject`. Runtime cross-module execution is out of scope — the interpreter is single-file (`Interpreter.compile` takes one AST), which applies equally to the already-working selective-import form; the milestone's bar is resolution parity with that form.

## Scope

- **Grammar production (spec + parser).** Add `qualified_path = IDENT , "." , TYPE_IDENT` to the EBNF: reachable in type position (`base_type` alternative) and expression position (`primary_expr` alternative), and as a `struct_literal` head. Parser produces the reserved `.path` `TypeNode` in type position and a qualified reference in expression position. The exact AST shape (produce the reserved `.path` TypeNode with `{ alias, member }`; in expression position reuse `field_access` on the alias ident vs. mint a node) is decided by the E1 recon and recorded in Notes — reuse is preferred, a new node is minted only if reuse forces a worse resolver shape.
- **Volet 1 — qualified member resolution (type position).** `namedTypeToResolved` consumes `imported_aliases`: a `.path` TypeNode `m.Type` resolves `m` against `imported_aliases` (a whole-module alias → target file index), then looks `Type` up in that file's `project.exports`. Diagnostics reuse the `bindImports` selective-lookup branch exactly: member absent → `E0104 UnknownExport`; member present but `.private` → `E0107 ImportPrivateItem`. A receiver ident that is not a module alias (a local, a param, a selective-imported symbol) falls through to existing resolution unchanged — no regression on current `m.lower_field` / `Type.field` paths.
- **Volet 1 — qualified member resolution (expression position).** Expression-position qualified access resolves via the same `imported_aliases` mechanism: `m.Type { … }` (qualified struct literal, typed as `Type`), `m.Type.easy` (qualified head then existing enum-variant postfix), and `m.func()` (free-function call — this form already parses as a `method_call` on the alias ident; only its resolution is added). Same diagnostics (`E0104` / `E0107`). Unknown alias / unresolved receiver → existing `E0102 UndefinedSymbol`.
- **Volet 2 — `private` visibility inheritance (§10.2).** The `impl` and methods of a `private` type inherit the type's visibility (implicitly private): the resolver does not treat a private type's methods as exported/public surface. Cross-module access already fails (the private type is unnameable → `E0104`/`E0107`); this ensures no path leaks it as public.
- **Volet 2 — `W0902 PrivateTypeInPublicImpl`.** New warning: `impl PublicTrait for PrivateType` (a trait impl whose target type is `private` and whose trait is public/imported) emits `W0902` (warning, not error — legitimate for internal use). Detection iterates `impl_decls` with `trait_name != 0`, checks the target type's visibility (private) and the trait's visibility (public). New code added to `diagnostics.zig` (`W0902`, spec-assigned by `etch-resolver-types.md §10.2` and `etch-diagnostics.md §21.1`).
- **Acceptance corpus.** Zig driver tests under `validateProject` over multi-file `ProjectFile` fixtures (the `tests/etch/import_resolve_test.zig` M1.0.7 pattern) — the single-file `etch_test` shim is not the vehicle (`bindImports` is a no-op when `project == null`).
- **KB reconciliation (Step 4, delivered by Claude.ai as complete re-uploadable files).** `etch-grammar.md` gains the `qualified_path` production; `etch-resolver-types.md §3.3` refines `resolve_path` to distinguish absent (`E0104`) from present-but-private (`E0107`) instead of the conflating `lookup_export`, and §3.1 notes the grammar production now exists; `etch-diagnostics.md §25` adds `W0902` to the Phase 1 coverage list.

## Out of scope

- **Runtime cross-module execution.** The interpreter is single-file (`Interpreter.compile(ast, world)`). Executing a cross-module call/type at runtime is not a v0.6 concern for either import form; the bar is resolution parity with the selective-import form under `validateProject`. Not parked debt — a documented layer boundary.
- **Uppercase associated access `Type.CONST`** (e.g. `Vec3.UP`, `Color.WHITE`). This is a separate latent grammar gap (a `TYPE_IDENT . TYPE_IDENT` postfix, unrelated to module aliases). Do not touch it here. The `qualified_path` production added here is `IDENT . TYPE_IDENT` (alias `.` Type) only.
- **Multi-segment module sub-paths** (`m.sub.Type`, `core.math.Vec3` as a runtime path). Etch modules are flat files; alias-qualified access is a single `alias . member` step. `resolve_path`'s deeper walk is not exercised by aliases.
- **Broader "private in public signature" leakage** (a public component field, or a public `fn` param/return, referencing a private type — Rust `private_in_public`). Ruled out for v0.6 (decided with Guy: §10.2 literal). `W0902` on trait impls is the spec's mechanism for the "private type exposed by a public signature" criterion. Explicitly refused, not deferred.
- **`W0901 UnusedThrowsDeclaration` / `W0903 DeprecatedItem`** — other codes in the W09xx block; not this milestone.
- **The LR(1) grammar generator / DSL** (`src/etch/parser/grammar/`, `tools/etch_lr_gen`, `zig build parser-gen`, `tests/grammar_consistency.zig`). These are the planned parser architecture (`etch-parser.md §4`) and do not exist at this tag. The parser is the hand-written `src/etch/parser.zig` (recursive descent + Pratt). The grammar change is EBNF (`etch-grammar.md`) + hand-edit of `parser.zig`; do not scaffold the generator.

## Notes

**Gate breakdown (E1–E3, gate-by-gate review protocol):**

- **E1 — Recon + qualified path (type position) + resolver.** In-repo recon first (mandatory, findings journaled in the Execution log): (a) the AST representation choice — produce the reserved `.path` TypeNode as `{ alias: StringId, member: StringId }` for type position; for expression position, whether `field_access` on the alias ident can carry `m.Type` cleanly (including the `m.Type { … }` struct-literal head) or a dedicated node is warranted; (b) `namedTypeToResolved`'s current handling of an unknown named type, and how a type-checker in pass 2 reaches `project.exports[file_idx]` from an `imported_aliases` target; (c) confirm `m.Type` is a hard parse error today (not a mis-resolved node) in both positions; (d) the receiver-disambiguation order so an alias lookup never shadows a legitimate local/param/selective-symbol receiver. Then: EBNF `qualified_path` (type position), `.path` TypeNode in `ast.zig`, `parseBaseType`, `namedTypeToResolved` consuming `imported_aliases`, diagnostics `E0104` / `E0107` / `E0102`.
- **E2 — Qualified access (expression position).** `parsePrimary` / `continuePostfix` accept `TYPE_IDENT` after an alias dot; `parseStructLiteral` qualified head; resolver expression synth consuming `imported_aliases` for `m.Type { … }`, `m.Type.variant`, and `m.func()` (alias-receiver recognition on the already-parsing `method_call`); same diagnostics.
- **E3 — `private` completion (§10.2).** Visibility inheritance (a private type's `impl`/methods are not surfaced as public/exported) + `W0902 PrivateTypeInPublicImpl` over `impl_decls` (trait impl, private target type, public trait). Add `W0902` to `diagnostics.zig`.

**Traps and constraints:**

- **Multi-file test vehicle.** Qualified imports require a project: `bindImports` is a no-op when `project == null` (single-file mode). Tests build a `ProjectFile` set and call `validateProject` (the `import_resolve_test.zig` pattern). The `etch_test` single-file shim cannot exercise this.
- **Diagnostic reuse.** `E0104` (absent) and `E0107` (present-but-private) mirror the `bindImports` selective-import branch exactly — the qualified path checks the same `project.exports` entry (`buildExports` records private entries with `visibility == .private`). Do not mint a code for these. `W0902` is the only new code, spec-assigned.
- **No parser generator at this tag.** The parser is hand-written `src/etch/parser.zig` (RD + Pratt). Grammar changes are the EBNF in `etch-grammar.md` + hand-edits to `parser.zig`. Do not scaffold `src/etch/parser/grammar/` or `tools/etch_lr_gen` — those are the planned architecture (`etch-parser.md §4`), out of scope.
- **Receiver disambiguation (no regression).** An ident `m` may be a module alias, a local/param, or a selective-imported symbol. Qualified resolution fires only when `m` is a whole-module alias in `imported_aliases` and not shadowed by a local in scope. Field/method access on non-alias receivers must resolve exactly as before.
- **String discipline (M1.0.14/15 lesson).** Resolution operates on interned `StringId`s and export entries, not on heap `Value`s, so the UAF surface is minimal — but any name/message copied into a diagnostic that outlives interpreter scratch memory goes through the `stringNeedsOwning` / deep-copy discipline.
- **Module rooting (Zig 0.16 lazy analysis).** `tests/etch/qualified_import_test.zig` must be transitively reachable from its test root or its `test` blocks silently skip (cf. `engine-zig-conventions.md §13`). Verify real execution, not mere presence.

**Rejected alternatives (recorded):**

- **Minting a dedicated qualified-path node** for both positions instead of using the reserved `.path` TypeNode + reusing `field_access`: rejected as the default — the `.path` TypeNode was reserved for exactly this, and `field_access` already carries receiver + member. A new node is minted only if the E1 recon shows reuse forces a worse resolver shape (recorded in Notes if so).
- **Broadening §10.2 to full `private_in_public`** (diagnose a private type in any public field / param / return): rejected for v0.6. `W0902` on trait impls is the spec's concrete mechanism for the criterion; a general signature-traversal check is a non-spec extension.
- **Extending `etch_test` to a project mode** to test qualified imports through the shim: rejected — `validateProject` is the correct, existing cross-module test vehicle.
