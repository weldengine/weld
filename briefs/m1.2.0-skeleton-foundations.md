## Context

Kinesis does not exist. Measured at `2006ed0`: no `src/modules/kinesis/`, no `src/interfaces/AnimationModule.zig`, and every occurrence of `skeleton` under `src/` means "code skeleton". Of the eleven frame-pipeline stages of `engine-animation-kinesis.md` §4, zero are implemented. This milestone opens the module and delivers the bottom of the dependency chain: a skeleton asset, its hierarchy, its bind pose, forward kinematics, and the one addressing type through which every later bone reference must pass.

It also settles a decision that becomes expensive seven sub-milestones from now. `PoseBuffer` crosses `sampleClip`, `blendPoses` and `additivePose`, so it freezes with `AnimationModule` at M1.2.7, and it is snapshotted by rollback. Its memory layout — AoS or SoA — was asserted in three documents and measured in none. **This milestone decides it by benchmark, at the first gate, before any consumer exists.** Changing it later is a re-opened frozen interface plus a save-format migration.

## Scope

- `Mat4` descends into `src/foundation/math/mat4.zig` and `src/core/rtti/type_info.zig` imports it. The type already exists in `rtti` with a frozen layout — `extern struct { m: [16]f32 }`, column-major, 64 bytes pinned by test — and a twin in the plugin C surface (`WeldMat4`, `src/core/plugin_loader/desc.zig`). **The layout and the twin are preserved byte for byte; only the declaring file moves.** No second `Mat4` is created: `core` imports `foundation` and never the reverse, so a mathematical type declared in the reflection module is at the wrong tier, beside `Mat3` which is already at the right one.
- `Mat4` operations, generic over the scalar on the `Mat3(T)` pattern: multiply, TRS composition, affine inverse, transpose, and conversion from a `(translation, rotation, scale)` triple. Column-major storage, matching `Mat3` and the existing `Mat4`.
- A micro-benchmark deciding the `PoseBuffer` layout: N-bone pose blend, AoS against SoA, on `src/foundation/simd/`. **The measured number decides, and it is published in the gate and written into `engine-animation-kinesis.md` §2 by a Claude.ai round-trip.** Both variants are implemented for the measurement; only the winner survives the gate.
- The Kinesis Tier 1 module: `src/modules/kinesis/`, `init` / `deinit` taking `*core.ModuleContext`, component and resource registration through `world` and nothing else, system registration through `ctx.system_scheduler`.
- `src/interfaces/AnimationModule.zig` in partial form, **explicitly not frozen**: the entries this milestone implements are asserted, the rest are typed stubs returning `error.NotImplemented`. The freeze is M1.2.7 (`engine-phase-1-criteria.md` C1.0); this file carries a marker saying so, so that no reader mistakes an existing file for a frozen signature.
- The skeleton asset format: header, bone count, parent index array, bind pose, inverse bind pose, optional `SkeletonProfile` block. Loading **rejects** a malformed hierarchy rather than repairing it: out-of-range parent index, cycle, a parent appearing after its child, more than one root.
- The topological order is an **asset invariant checked at load**, not a runtime tolerance: parents precede children, which is what makes forward kinematics a single linear pass with no sort and no recursion.
- Forward kinematics: local poses → world poses, composing `Transform` through the parent chain, non-uniform scale included. Inverse bind pose stored and exposed; it is the input `getSkinMatrices` will need at M1.2.3.
- `BoneRef`, `BoneRole` and `resolveBone` (`ARCH-033`). A `BoneRef.role` whose role is unmapped resolves to **absence**, never to an arbitrary bone. A skeleton with no `SkeletonProfile` stays fully usable through `BoneRef.name`.
- Counter-proofs shipped by the gate that introduces each guarantee, each paired with a positive witness in the same run. For `resolveBone`, the attack is written **before** the counter-proof (`D37`).

## Out of scope

- Clip sampling and the Cinch v0 codec — M1.2.1. This milestone loads a skeleton, not an animation.
- Blending, additive layers, bone masks — M1.2.2. The pose blend written here exists **only** as a benchmark body and is deleted at the gate unless the layout ruling keeps one variant of it.
- `getSkinMatrices` and the GPU-facing matrix palette — M1.2.3.
- `anim_graph` descriptor execution — M1.2.4. The construct is parsed, validated and serialised already (`src/etch/descriptor.zig`); nothing consumes it, and nothing here starts to.
- AnimNotifies, sockets, montages, IK, motion matching, ragdoll, procedural animation, facial — M1.2.5 and later.
- The skeleton importer from glTF or FBX, and `SkeletonProfile` inference from bone names — M1.6.0. Test skeletons are authored by hand in the test fixture format; that is enough to exercise every rejection path.
- Any change to `src/core/ecs/`. The pose storage lives **outside** the ECS, reached through a handle, on the `PhysicsWorldRef` precedent (`src/modules/forge/sync.zig`). If a design pressure appears to change Tier 0 ECS, **stop and report** — that would pull the derived job-body guard into this milestone, which is a Claude.ai round-trip and not a gate judgement.
- The `Transform` proliferation. Three distinct `Transform` types coexist in the tree (`src/core/ecs/components.zig`, `src/modules/forge/api/types.zig`, `src/modules/render/instancing/batcher.zig`). Kinesis uses the Tier 0 one, as Forge does. Consolidating them is neither this milestone's object nor its cost to pay.

## Acceptance criteria

### Tests

- `tests/foundation/math/mat4_test.zig` — `test "Mat4 keeps its committed layout and its C twin"` — `@sizeOf` is 64, alignment unchanged, and the field-by-field equality with `WeldMat4` is asserted structurally, so that moving the declaration cannot silently change the ABI
- `tests/foundation/math/mat4_test.zig` — `test "TRS composition matches the reference product"` — including non-uniform scale, against a hand-computed matrix
- `tests/foundation/math/mat4_test.zig` — `test "the affine inverse round-trips a TRS matrix"` — with non-uniform scale; the positive witness without which the rejection tests below are vacuous
- `tests/kinesis/skeleton_test.zig` — `test "world transforms of a three-level chain are correct"` — a hand-computed expected pose, non-uniform scale on at least one bone
- `tests/kinesis/skeleton_test.zig` — `test "forward kinematics is a single linear pass"` — asserted by the topological invariant, not by timing
- `tests/kinesis/skeleton_test.zig` — four rejection cases, each its own test — out-of-range parent index, cycle, parent after child, multiple roots. Each paired, in the same run, with a well-formed skeleton that must load
- `tests/kinesis/skeleton_test.zig` — `test "inverse bind pose composed with the bind pose yields identity"` — within a stated epsilon
- `tests/kinesis/bone_ref_test.zig` — `test "a mapped role resolves to its bone index"` — the positive witness
- `tests/kinesis/bone_ref_test.zig` — `test "an unmapped role resolves to absence, not to a neighbouring bone"` — the attack is written first: a fixture whose profile maps every role EXCEPT one, asserting the unmapped one returns null while its neighbours still resolve. A test that only checks `null` on an empty profile measures nothing
- `tests/kinesis/bone_ref_test.zig` — `test "a skeleton with no profile resolves by literal name"` — `ARCH-033` conformance test 4
- `tests/kinesis/bone_ref_test.zig` — `test "a role ordinal is never reassigned"` — the enum's ordinals pinned by value, so an insertion in the middle fails the suite
- `tests/kinesis/bone_ref_counterproof/` — the harness distinguishes an EXPECTED compilation failure from a failure for any other cause by matching the diagnostic text, and runs a control case that must compile in the same execution

## Notes

**The gate order, and why it is this one.**

- **G1 — `Mat4` descends, and the pose layout is decided.** The benchmark needs `Vec`, `Quat` and `Mat4` and nothing else: not the module, not the asset, not FK. Placing the most structuring decision at the cheapest gate is deliberate — every later gate consumes its result, and taking it after the FK is written means writing the FK twice. The gate publishes both layouts' numbers on blend AND on FK, then states the ruling and its margin. **If the two measurements disagree** — blend favouring SoA and FK favouring AoS by comparable margins, which is the expected shape — the gate reports and stops: arbitrating a split verdict is a design call weighted by how often each runs in the frame, and that belongs to Claude.ai.
- **G2 — the module and its interface file.** Registration through `ModuleContext` and its four fields; no second route to component registration, no `registrar`, no `event_bus`. The interface file exists but carries a not-frozen marker.
- **G3 — the asset format and its rejections.** Before any runtime hierarchy, because the rejections define what the runtime is allowed to assume. A loader that repairs a malformed hierarchy makes every downstream invariant untestable.
- **G4 — hierarchy, bind pose, inverse bind, forward kinematics.** On the layout G1 decided. Non-uniform scale is exercised in the FK test and not deferred: it is the case that separates a correct composition from one that happens to work on unit scale.
- **G5 — `BoneRef`, `BoneRole`, `SkeletonProfile`, `resolveBone`.** The attack before the counter-proof, stated as an order and not as a preference.

**Three spaces, named, because confusing them is the classic bug of this module.**

Local (a bone's transform relative to its parent), skeleton-relative (relative to the skeleton root, what FK produces), and world (skeleton-relative composed with the entity's `Transform`). `Skeleton.current_pose` holds the first, `Skeleton.world_pose` the second. The entity transform enters at the consumer — `getSkinMatrices` at M1.2.3, `getSocketTransform` at M1.2.6 — and **not** inside FK. Writing FK so that it bakes the entity transform in makes both later entries wrong in a way that looks right on an entity at the origin.

**Pose lifetime.**

A `PoseBuffer` is variable-length; a component is a POD `extern struct` (`engine-zig-conventions.md` §16). The buffer therefore lives outside the ECS, in module-owned storage allocated from `ctx.persistent_allocator`, and the `Skeleton` component carries a handle. The precedent is `PhysicsWorldRef` in `src/modules/forge/sync.zig`: the world lives outside, a resource carries the pointer, the ECS knows nothing of it. **Do not reach for a Tier 0 ECS change to store poses.**

**Traps recorded.**

`Mat4` exists already. The first recon of this milestone claimed it existed nowhere, having grepped `src/foundation/` and `src/modules/render/` while asserting something about the whole tree — `D36`, the selector wider than its subject, found by external review. It is in `src/core/rtti/type_info.zig:175`, it is column-major, it is 64 bytes pinned by a test at line 208, it is mirrored by `WeldMat4` in `src/core/plugin_loader/desc.zig:84`, and `src/core/rtti/comptime_builder.zig:134` maps it to `.mat4`. **Moving it must change no byte of its layout and no behaviour of the reflection path.**

The type of a pose has borne three names across three documents — `PoseBuffer`, `BonePose`, `SoaTransform` — and two contradictory layouts. The corpus was unified on `PoseBuffer` on 2026-09-13. If any spec read at step 2 still says otherwise, the corpus copy is stale: stop and report rather than implementing what it says.

`ARCH-033` names one exception: the `on_bones` production of the `anim_graph` construct takes literal strings, ratified in M0.8 and carried by `src/etch/ast.zig` (`AnimLayerProp`). It is not a violation to fix, and this milestone does not touch it.

A counter-proof suite is green when nothing compiles at all. Every non-compilation case is paired, in the same execution, with a case that must compile and whose success is asserted.
