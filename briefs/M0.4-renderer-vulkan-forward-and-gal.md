## Context

M0.4 advances criterion C0.3 (minimal Vulkan forward renderer) by designing the GAL (GPU Abstraction Layer) on day 1 to accommodate Metal + D3D12 + WebGPU without a Phase 2+ refactor, and by delivering an operational Vulkan forward renderer on top of it. The GAL is the engine's architectural bifurcation point — freezing its public surface now avoids a refactor 5-10× more costly in Phase 2. The milestone absorbs in parallel 6 S2 debts on the Vulkan path (PPM capture, dispatch bypass, whitelist closure, VkResult aliases, `*Raw` variants, removal of the `vk_frame.zig` spike). This is the **first milestone applying rule §4.5.1** (mandatory semantic runtime CI + manual GPU validation on the 3 configs).

## Scope

- **Frozen public GAL interface** in `src/modules/render/gal/` — WebGPU-like surface (Device, Queue, CommandEncoder, RenderPassEncoder, ComputePassEncoder, BindGroup, BindGroupLayout, RenderPipeline, ComputePipeline, Buffer, Texture, TextureView, Sampler, Fence, Semaphore) with Phase 0 escape hatches pre-wired for `TimelineSemaphore`, `BarrierExplicit`, `DescriptorIndexing` (types present, minimally functional on Vulkan, no-op on Null, used Phase 1+). Auto-tracking of barriers by default, opt-in `BarrierExplicit` mode. Input pipeline = binary SPIR-V only (no HLSL/WGSL source).
- **Vulkan backend** in `src/modules/render/gal/vulkan/` — full implementation of the Phase 0 GAL concepts (Buffer, Texture, Pipeline, RenderPass, swapchain, sync). No direct access to `vk.device_dispatch.*` from code outside `gal/vulkan/`. Two distinct selection flags: `--gpu-prefer=<discrete|integrated|index:N>` unchanged vs S2 (hardware selector), new `--vulkan-driver=<auto|hardware|software>` (Vulkan implementation selector: `auto` default = enumerate all devices and apply `--gpu-prefer`, `hardware` = filter out `CPU` devices before applying `--gpu-prefer`, `software` = force lavapipe or equivalent and ignore `--gpu-prefer`).
- **Null backend** in `src/modules/render/gal/null/` — no-op stubs that satisfy the comptime interface check, used in headless CI for API consistency tests.
- **Minimal render graph** in `src/modules/render/render_graph/` — declarative DAG with 3 Phase 0 passes: Depth prepass (D32_SFLOAT, no stencil) → Forward opaque (depth test on, depth write on, front-to-back sort by `(mesh_id, material_id)` bucket) → Conditional capture (blit-to-buffer post-present, enabled by `--smoke-test`). No transparent pass.
- **Shader pipeline** in `src/modules/render/shader_pipeline/` — offline GLSL → SPIR-V compilation via spawning the `glslc` CLI, disk cache hashed on `(source + defines + glslc_version)`, runtime hot-reload via filewatch + re-spawn `glslc` in a dedicated thread. Target hot-reload latency < 200 ms. No shaderc / glslang binding. SPIR-V committed in `assets/shaders/`, opt-in regeneration via `zig build shaders`.
- **CPU-side ECS instancing + batching** in `src/modules/render/instancing/` — bucketing by `(mesh_id, material_id)` via `std.HashMap`, upload of Transform into a per-bucket instance buffer, one instanced drawcall per bucket. Front-to-back sort by the depth of the bucket centroid.
- **Removal of `src/spike/ppm.zig`** (debt D-S2-ppm). Frame capture routes via an offscreen render target R8G8B8A8_UNORM in the GAL, CPU readback + conversion → PPM RGB in `--smoke-test` mode. Lifecycle: created in capture mode, freed at teardown.
- **Extension of `tools/vk_gen/` — `*Raw` variants emitter** (debt D-S2-dispatch-bypass). For each Vulkan function where at least one parameter is not cleanly exposed by the idiomatic wrapper (optional sentinel pointer, pNext chain), emit two variants: the idiomatic wrapper + a `*Raw` that exposes all raw parameters. Explicit target: `vkAcquireNextImageKHR`, `vkQueuePresentKHR`, `vkAcquireNextImage2KHR`. Migration of render code to the idiomatic wrappers only.
- **Extension of `tools/vk_gen/` — transitive whitelist closure** (debt D-S2-vk-whitelist). Reachability fixed-point algorithm from the set of whitelisted functions/extensions. Filtering at emission of unreachable types and enum variants. Target: `src/core/platform/vk.zig` lines post-closure **≤ 50 % of the pre-closure baseline** (baseline measured at the start of the milestone). Adjustment clause: if the post-implementation measurement reveals a technical floor (impossible to go below the threshold without breaking a whitelisted feature), document the measurement and the reason for the floor in `Notable items for review` of the squash commit, adjust the threshold via an acted deviation in the LIVING SECTION (no mid-milestone re-spec).
- **VkResult aliases moved into the enum** (debt D-S2-vkresult-aliases). Complete removal of the module-scope `pub const VK_*: Result = .xxx`. Mechanical migration of call sites to `vk.Result.success`, `vk.Result.error_out_of_host_memory`, etc.
- **Removal of `src/spike/vk_frame.zig`** absorbed by `gal/vulkan/swapchain.zig` + `gal/vulkan/frame.zig`. **Removal of `src/main.zig`** (the Weld engine is consumed as a lib + tools, not as a root binary). The public GAL demonstration lives in `examples/triangle/` (standalone sub-project with its own `build.zig` that consumes Weld via `b.dependency("weld", ...)` — a living architectural test of the public API from an external consumer's point of view). If M0.8 (vertical slice) needs a binary, it lives in `examples/vertical_slice/` (consistent with `engine-phase-0-criteria.md §C0.8`).

## Scope — Post-Review Complement

*Added after review of the initial M0.4 PR (cf. the 2026-05-26 log). The initial PR delivered a GAL cabinet (design + Vulkan backend + Null backend + render graph + shader pipeline + instancing + 6 S2 debts) but did not deliver the operational end-to-end pipeline — `examples/triangle/` runs on Null for lack of the window→surface helper. The 5 deliverables below complete the initial scope to make criterion C0.3 "minimal Vulkan forward renderer" effectively demonstrable. No widening of scope relative to the initial mandate — only the finalization of contracts already implicit in the brief.*

- **Helper `src/modules/render/gal/vulkan/surface.zig`** — creation — converts a Tier 0 `*platform.window.Window` to a `gal.types.SurfaceHandle` via `vkCreateWin32SurfaceKHR` (Windows) or `vkCreateWaylandSurfaceKHR` (Linux), comptime dispatch by platform. Exposed via the public GAL surface as a `Device.createSurfaceFromWindow(window: *platform.window.Window) !SurfaceHandle` method. Lifecycle managed by the Device (destruction at teardown). No `vk.device_dispatch.*` access outside `gal/vulkan/` (the linter rule must keep passing).
- **Wireup `examples/triangle/src/main.zig`** — edit — switch the default backend from Null to Vulkan as soon as a window is opened. The `--vulkan-driver=software` mode stays functional for CI (lavapipe). The binary effectively displays a triangle (or simple cube, choice left to Claude Code) animated via the Vulkan GAL on the reference machine. The brief's §Observable behavior made operational.
- **`bench/render_instancing.zig`** — creation — bench of 100k entities (Mesh + MaterialInstance + random Transform on a grid) over 100 distinct (mesh, material). Measurements: sustained FPS over 60s, GPU frame time p50/p99 via Vulkan timestamp queries, drawcalls/frame post-batching, GPU memory allocated. The golden is generated once on lavapipe + headless weston, visually validated by Guy, and committed. The test runs `examples/triangle` in `--smoke-test --vulkan-driver=software --capture-frame=10` mode, reads the produced PPM, computes the PSNR against the golden, fails if < 40 dB.
- **`tests/render/shader_hot_reload.zig`** — creation — filewatch → full recompile latency test < 200 ms. Starts the filewatch, touches `assets/shaders/triangle.frag.glsl`, measures the elapsed time until the recompilation finishes. Skips with `error.SkipZigTest` if `glslc` is absent from the PATH.
- **CI step `runtime-smoke-test`** — creation of a Linux GitHub Actions workflow — `apt install weston mesa-vulkan-drivers` + launching `weston --backend=headless-backend.so` in the background + `WAYLAND_DISPLAY=wayland-1 zig build run-example-triangle -- --smoke-test --vulkan-driver=software`, reading the produced PPM, comparing PSNR ≥ 40 dB vs `tests/golden/smoke_test_software.ppm`. **Blocking** step (PR red on failure). Expected cost: 30-60s added to Linux CI.

## Out-of-scope

- **V-Buffer (Visibility Buffer)** — Phase 1. The GAL must accommodate it without a refactor, but the implementation stays classic forward in M0.4.
- **Facet (virtual geometry, Nanite-like)** — Phase 3+.
- **Radiance (GI)** — Phase 1+ (BakedLightmaps), 2+ (RadianceCascades, SurfelGI), 3+ (PathTracer).
- **Stochastic visibility / shadows** — Phase 1+. No shadow map in Phase 0 (the M0.4 scene has no shadows).
- **Post-process pass** — Phase 2+. No bloom, tone mapping, motion blur, etc.
- **Transparent pass** — Phase 1+. The M0.4 scene is 100 % opaque.
- **MSAA** — Phase 1+ in Forward+ mode. Sample count fixed at 1× in M0.4 (the `sample_count` field is present in `TextureDescriptor` / `RenderPipelineDescriptor` on the public API side but any value > 1 returns `error.Unsupported` in Phase 0).
- **Bindless descriptors / descriptor indexing used** — escape hatch declared on day 1 in the GAL surface, **not exploited** in Phase 0 (fixed bind groups only).
- **Indirect draw / GPU-driven culling** — Phase 1+.
- **Mesh shaders, task shaders** — Phase 3+ (Facet).
- **Ray tracing** — Phase 2+ (optional GI).
- **Executed compute shaders** — the GAL exposes `ComputePipeline` and `ComputePassEncoder` on day 1, but no compute usage is delivered in M0.4 (first usage Phase 1 culling/GI).
- **Metal, D3D12, WebGPU backends** — types and interfaces declared on day 1 (respective escape hatches on each backend's contract), implementation Phase 2-3.
- **Etch Shader compiler** — Phase 1+. The M0.4 shaders are written in GLSL and compiled via the `glslc` CLI. The canonical Etch Shader → SPIR-V pipeline only activates in Phase 1+; at that point it feeds the GAL with SPIR-V — the GAL API on the shader input side does not change.
- **C binding for `shaderc` or `glslang`** — refused. The list of 7 C keepers stays unchanged (cf. `engine-c-bindings.md §6.4` + §Notes analysis).
- **Runtime reflection of SPIR-V** — no runtime SPIRV-Cross. The UBO/SSBO/texture layouts are declared explicitly in `PipelineDescriptor` (WebGPU pattern).
- **SPIRV-Cross / DXC invocation for MSL/DXIL/WGSL** — Phase 2+ (offline cooking when the corresponding backends are introduced).
- **macOS / iOS / Android / Web** — Phase 2+. `src/core/platform/window/stub.zig` continues to return `error.UnsupportedPlatform`.
- **Refactor of the asset pipeline** — M0.5. The GLSL→SPIR-V compilation in M0.4 is a standalone `tools/shader_compiler/` invoked by `build.zig`, not an integration into the canonical asset pipeline.
- **Material Instances, MaterialGraph, multiple shading models** — Phase 1+. Phase 0: a single trivial shader (standard vertex + fragment) for the demo triangle/cube and the instancing benchmark.
- **Modification of the Tier 0 `Window` interface** — delivered in M0.3, not touched in M0.4.

## Notes

**Acted architectural decisions (summary of the 10 axes handled in the Claude.ai conversation of 2026-05-26)**:

1. **WebGPU-like GAL + escape hatches pre-wired on day 1**: the public surface accommodates `TimelineSemaphore`, `BarrierExplicit`, `DescriptorIndexing` from M0.4 onward (types present, minimally functional on Vulkan, no-op on Null). Without this Phase 0 pre-wiring, the Phase 1+ addition would force a refactor of the whole surface — violates the guiding principle "design on day 1".
2. **Auto-tracking of barriers by default, `BarrierExplicit` opt-in**: Phase 0 has 2 passes + 1 conditional blit, auto-tracking is largely sufficient. In Phase 1+ the render graph DAG will need the explicit mode for pass merging and resource aliasing.
3. **SPIR-V only as GAL input**: no HLSL/WGSL source, no runtime SPIR-V reflection (layouts declared explicitly, WebGPU pattern). HLSL/WGSL source deferred to Phase 2+ and only on documented external demand.
4. **M0.4 backends: Vulkan + Null. Metal/D3D12/WebGPU = day 1 in the design (types + interfaces), not in the implementation.**
5. **Render graph 3 Phase 0 passes**: Depth prepass (D32_SFLOAT, no stencil) → Forward opaque (front-to-back sort by bucket) → Conditional capture (post-present). No MSAA. No transparent.
6. **Frame capture format R8G8B8A8_UNORM** (not BGRA) — trivial CPU conversion to PPM RGB (drop alpha, write RGB byte by byte).
7. **Shader compilation: GLSL → `glslc` CLI spawn + hashed disk cache + filewatch + re-spawn for hot-reload. No shaderc / glslang binding.** The rule "7 C keepers final target" stays unchanged. Criterion §6.4 #3 (consumed by the shipping game runtime) fails for shaderc, which would be dev-only conditional. Hot-reload latency of a `glslc` spawn ~100 ms per shader, below the 200 ms human friction threshold.
8. **Long-term canonical target pipeline: Etch Shader → SPIR-V (Phase 1+ via the Etch compiler)**. M0.4 uses GLSL because the Etch compiler does not exist yet. The GAL API on the shader input side is `createShaderModule(spirv_bytes: []const u8)` — it does not change when the Etch compiler arrives in Phase 1+, only the SPIR-V producer changes.
9. **CPU-side ECS batching mandatory in Phase 0**: without batching, 100 k entities at 60 FPS is out of reach (CPU/driver overhead per drawcall ~3-10 µs caps at ~5-15 k drawcalls/frame). Phase 0 algorithm: bucketing by `(mesh_id, material_id)` via HashMap, one instanced drawcall per bucket. No GPU-driven (Phase 1+).
10. **No reactive split trigger** (non-negotiable rule cf. userMemories). If a context/scope overrun is observed by Claude Code during a session, the default position = continue in the same session. An M0.4.X.1 hotfix is possible **after the merge** if there is an urgent regression, not during.
11. **Two distinct Vulkan selection flags** (post-Axes decision, 2026-05-26): `--gpu-prefer=<discrete|integrated|index:N>` unchanged vs S2 (hardware selector), `--vulkan-driver=<auto|hardware|software>` new (implementation selector). Composability: `--vulkan-driver=hardware --gpu-prefer=integrated` is a valid use case ("force iGPU, never lavapipe fallback"). Merging into a single widened flag rejected because it is unable to express this conflict cleanly. Explicit conflicts logged as warn, not as error.
12. **Removal of `src/main.zig`, standalone `examples/triangle/` structure** (post-Axes decision, 2026-05-26): the Weld engine is consumed as a lib + tools, not as a root binary. The GAL demonstration lives in an `examples/triangle/` sub-project with its own `build.zig` that consumes Weld via `b.dependency("weld", ...)`. Triple benefit: (a) living architectural test of the external consumability of the GAL API from day 1, (b) public usage reference for future consumers, (c) closure of the "src/main.zig S2 spike" debt without keeping it indefinitely. Pattern to generalize for M0.8 `examples/vertical_slice/`.
13. **Whitelist closure threshold ≤ 50 %** (post-Axes decision, 2026-05-26): the 60 % threshold rejected as too lax (1 % margin over the M0.3 notable-item target of ~3500 lines saved). 50 % forces a rigorous transitive propagation algorithm. Adjustment clause by tracked deviation in the LIVING SECTION if a technical floor is documented.

**Volume estimate** (indicative, to be refined): 8 100 - 12 100 lines added (~2-3× M0.3). Sub-deliverables: GAL interface + types ~1500-2000, Vulkan backend ~2500-3500, Null backend ~300-500, render graph ~800-1200, shader pipeline ~400-600, instancing ~500-800, 6 bindgen debts ~600-1000, tests + benchmarks ~1500-2500, `examples/triangle/` (build + main + manifest) ~250-350.

**Committed generated-artifacts pattern** (consistent with the Vulkan/Wayland bindings):
- SPIR-V of the engine shaders committed in `assets/shaders/*.spv`
- Opt-in regeneration via `zig build shaders`
- `glslc` is a peer dependency **only** for `zig build shaders` (regeneration) or for the dev runtime hot-reload. The standard `zig build` build does not depend on `glslc`.

#### Lesson learned

The initial M0.4 PR removed `src/spike/` (S2) by absorbing its features into the GAL — without empirical proof of behavioral parity. The GAL code compiled, the unit tests passed, Vulkan init/teardown did not crash. But no consumer ran the **full path** (window + surface + swapchain + pipeline + drawcall + present + capture) on **real hardware**. The post-review continuation delivered this consumer (`examples/triangle/` Vulkan path), exposing 8 cascading bugs. Seven of the eight are of the "written code looks correct but Vulkan refuses at runtime" kind — invisible until the path is exercised.

Rule for Phase 1+: do not remove a functional spike until the successor code has demonstrated behavioral parity on the same hardware. The comptime `interface.checkBackend` discipline + unit tests is not enough — an **end-to-end consumer running on real hardware** is required before removal. For S2 → GAL, the right order would have been: (1) deliver GAL + Null backend + Vulkan backend, (2) make S2 go through the GAL (`src/spike/main.zig` consumes the GAL instead of raw Vulkan), (3) validate that S2-via-GAL runs identically to raw S2 on the 3 GPU configs, (4) THEN remove `src/spike/` and adopt `examples/triangle/` as the replacement. The post-review continuation effectively performed steps (2) + (3) + (4) compressed into a single session on Fedora 44, but with 8 cascading bugs to diagnose — a higher cost than a staged migration.

8 `var = undefined` or `@ptrCast` or type-inference bugs hidden by Zig 0.16 lazy analysis this session (beyond those of the initial PR).
