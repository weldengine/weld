## Context

This is the **last sub-milestone of the M1.0 series**; it closes the C1.6 core-language execution surface (the Etch core language is frozen at this tag). It delivers the §30.5 **compile-time (cook) warning**: when a scene instance activates two or more `extends` extensions that declare the same component, the cook emits a **non-fatal** warning (`W1791`) and still produces a valid `Cooked` result (last-extension-wins resolution, unchanged). The dangerous *runtime* case is already rejected at scene load by `error.ExtensionComponentConflict` (Tier-0 `src/core/scene/loader.zig`, §30.5 reject policy); this milestone adds the earlier, author-facing warning so the conflict is surfaced at cook time rather than only discovered at load.

## Scope

- A **non-fatal warning channel** in `src/etch/scene_cook.zig`. Today `diag_out: ?*[]const u8` is fatal-only (one static message set by `fail()`, always paired with a returned `CookError`). Add a warning accumulator carried on the cook result: a list of `{ code, message, span }` warnings that do **not** abort the cook. The existing fatal `diag_out`/`fail()` path is untouched.
- **Additive-conflict detection at cook.** For each cooked scene instance (or entity) whose `extensions:` clause lists two or more active extensions, resolve each extension's declared component set (reuse the existing prefab `entity { … }` component-block resolution) and detect any component declared by two or more of those extensions. Emit exactly one `W1791` per `(instance, conflicting-component)` pair.
- **New diagnostic `W1791 ExtensionAdditiveConflict`** registered in `src/etch/diagnostics.zig` (enum variant + `"W1791"` code string + name string), in the prefab warning range (`W1790` is `RESERVED` for `PrefabRemoveBaseComponent`; `W1791` is the first free code).

## Out of scope

- The **runtime reject** (`ExtensionComponentConflict`, `src/core/scene/loader.zig`) — already delivered, Tier-0/M1.6 territory. Do not touch it, do not duplicate its logic.
- The **`@exclusive_with(…)` attribute** (a future §30.5 resolution mechanism). Not implemented here. The warning only informs; it does not offer or require a fix.
- Any change to the **last-extension-wins** resolution semantics for additive conflicts. Unchanged. The warning is informational only and never alters the cooked output.
- **Emitting the warning from the validator** (`src/etch/types.zig`). Decided cook-side (the additive conflict needs resolved cross-prefab component sets, which the cook resolves and the validator does not — validator prefab handling is relation-only, cross-file deferred). Do not add this check to the validation layer.
- **Advancing cross-file project-graph extension resolution** beyond what the cook already does. If an extension name does not resolve to a prefab within the current cook unit, that is an existing condition handled by existing code — do not extend it for this warning.
- Editing `etch-diagnostics.md` or any `engine-*.md` / `etch-*.md` spec doc — those are KB-only, owned by Claude.ai (re-uploaded by Guy). The `W1791` doc reconciliation is handled at milestone close by Claude.ai, not by Claude Code.

## Acceptance criteria

### Tests

- `tests/scene/extensions_test.zig` — `test "cook warns W1791 when two extensions declare the same component"` — a scene instance activating two `extends` prefabs that both declare component `Inventory` → cook **succeeds** (returns a valid `Cooked`, no `CookError`) **and** the warning list contains one `W1791` naming `Inventory`.
- `tests/scene/extensions_test.zig` — `test "cook emits no warning when extensions declare disjoint components"` — two active extensions with no shared component → empty warning list, cook succeeds.
- `tests/scene/extensions_test.zig` — `test "cook emits one W1791 per conflicting component"` — three active extensions where exactly two share `Inventory` and two (a different pair) share `Weapon` → exactly two `W1791` entries, one per conflicting component, not one per extension pair.
- `tests/scene/extensions_test.zig` — `test "W1791 is non-fatal — cooked output applies last-extension-wins"` — with a conflict present, the cooked instance still carries the conflicting component from the **last** extension in the list, and the cook did not abort.
- `tests/scene/extensions_test.zig` — `test "single extension declaring a component emits no warning"` — one active extension → no `W1791`.
