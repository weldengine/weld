## Context

M1.0 exposes the M0.1 ECS infrastructure to the Etch tree-walking interpreter; M1.0.0/M1.0.1 wired filtered queries and change detection. This milestone wires the two remaining reactive mechanisms: **events** (`emit` + `@on_event` rules) and **structural observers** (component add/remove/replace + entity spawn/despawn hooks). The event core was delivered as a sub-slice of M0.8 (E3) and is already dispatched inside `runRule`; this milestone verifies and hardens it. Structural observers have **no Etch surface yet** — `engine-ecs-internals.md` §8 shows an `observer` keyword construct that was never carried into the grammar, the lexer, the reference, the resolver, or the validation specs (it is stale illustrative prose). This milestone introduces structural observers as **annotation-routed rules** (`@on_added(T)` …), consistent with the existing `@on_event(T)` mechanism, and completes the Tier-0 observer registry to feed them.

## Scope

The milestone is executed in three staged sub-scopes with a STOP-for-review gate between each (cf. Notes › Staging).

**E1 — Events: verification and hardening (interpreter, no Tier-0 change).**
- Discriminating tests proving the delivered `emit`/`@on_event` path against the World-integrated interpreter (see Acceptance criteria › Tests, E1 block).
- Fix-as-you-go for any defect surfaced by those tests, in `interp.zig` only.

**E2 — Observer Etch surface as annotation-routed rules.**
- 5 new `AnnotationKind` variants and `fromName` entries: `on_added`, `on_removed`, `on_replaced`, `on_spawned`, `on_despawned`.
- Annotation argument shape enforced: `@on_added(T)` / `@on_removed(T)` / `@on_replaced(T)` carry exactly one `TYPE_IDENT` component argument; `@on_spawned` / `@on_despawned` carry no argument.
- AST/descriptor routing mirroring the existing `@on_event` → `RuleDesc.event_type` path: an `ObserverKind` enum + the resolved target `ComponentId` (null for spawned/despawned) recorded on the rule descriptor; an `observerAnnotation(rule)` AST helper analogous to `onEventAnnotation`.
- Observer-rule signature validation (new E12xx diagnostics, allocated in the `E1208`+ range, registered in `etch-diagnostics.md` §14):
  - `@on_added(T)` requires a `(entity: Entity, component: T)` shape; `@on_replaced(T)` requires `(entity: Entity, old: T, new: T)`.
  - `@on_removed(T)` requires `(entity: Entity, old: T)`.
  - `@on_spawned` / `@on_despawned` require `(entity: Entity)`.
  - The annotation component type `T` must be a declared `component` and must equal the relevant param type.
  - An observer rule must carry exactly one lifecycle annotation; combining a lifecycle annotation with `@on_event`, with another lifecycle annotation, or with a `when` clause is an error (the annotation's component type is the sole trigger filter — observer rules do not iterate entities and take no `when`).

**E3 — Tier-0 observer-registry completion + interpreter bridge.**
- `ObserverFn` signature evolves to a uniform shape carrying a context pointer and old/new value pointers:
  `*const fn (ctx: ?*anyopaque, world: *World, entity: EntityId, component_id: ?ComponentId, old_value: ?*const anyopaque, new_value: ?*const anyopaque, deferred: *CommandBuffer) anyerror!void`.
  Conventions: `on_added` → `new_value` set, `old_value` null; `on_removed` → `old_value` set, `new_value` null; `on_replaced` → both set; `on_spawned`/`on_despawned` → both null, `component_id` null.
- `on_replaced` registry list (`AutoHashMapUnmanaged(ComponentId, Listeners)`) + `World.registerOnReplaced`; `registerOnAdd/Remove/Spawned/Despawned` extended to thread `ctx`.
- Replace detection in `applyWithObservers`' `.add_component` branch: applying `add_component(entity, cid)` on an entity that **already has** `cid` is a replace — capture the old value before overwrite, apply, then fire `on_replaced[cid]` with old+new; otherwise fire `on_add[cid]` with new. (Replace is triggered solely by add-on-present; no separate command, no new construct.)
- Old-value capture for `on_removed`: the removed component's value is read before the `remove_component` / `despawn` apply and passed as `old_value`.
- Interpreter registration: at world bind, observer rules are **excluded from the per-tick rule dispatch list** (they never run in `runRule`) and instead registered into the `ObserverRegistry` via `World.registerOn*`, each with a per-rule context (`{ interp, rule_desc_idx }`) allocated for the lifetime of the binding and a top-level trampoline matching `ObserverFn`.
- Observer body execution: a tree-walker path that binds `entity` and the component value(s) — `component`/`new` from `new_value` (or `world.get` for `on_added`), `old` from `old_value` — using the existing component-read path, then runs the rule body. Structural mutations issued by an observer body are routed to the registry's deferred command buffer (the existing no-recursion contract is preserved).

## Out-of-scope

- `@networked` events and any Relay integration (Phase 1.4+).
- Resolver `RuleEffects.emits` / `structural` tracking for the scheduler — specced as **not implemented in Phase 1** (`etch-resolver-types.md` §9.5 / §12.3). No change here.
- Observer dispatch in the codegen / shipping path (the `subscribe`/poll event-bus drain). Interpreter-only: codegen rejects observer rules as `UnsupportedConstruct`, mirroring the async-rule treatment (Phase 2+).
- Observer `when` clauses and entity-iterating observers. The annotation component type is the sole trigger filter.
- Any `replace`/`set_component` command or construct, and any replace trigger other than add-on-present.
- General user-facing generics work beyond the single component-type binding the annotation requires (no `<T>` parameterisation surface).
- Editing the specs in the KB (`engine-*.md`, `etch-*.md`): they are not in the repo and are reconciled by Claude.ai. Claude Code does not touch them.

## Acceptance criteria

### Tests

**E1 — events (interpreter):**
- `src/etch/interp.zig` — `test "@on_event(T) fires exactly once per emit T in the tick"` — N emits of `T` in a tick → the `@on_event(T)` rule body runs exactly N times.
- `src/etch/interp.zig` — `test "@on_event discriminates event types"` — `emit A` does not trigger an `@on_event(B)` rule and vice-versa.
- `src/etch/interp.zig` — `test "event emitted earlier in the tick reaches a later-declared @on_event"` — a rule emitting `T` ordered before the `@on_event(T)` drainer delivers the event same-tick.
- `src/etch/interp.zig` — `test "event string payload survives to drain and not past tick boundary"` — a string field set in `emit` is readable in the `@on_event` body within the tick; the per-tick event store is reset at the tick boundary.

**E2 — observer surface (validation):**
- `src/etch/interp.zig` — `test "observer annotation signature mismatch is rejected"` — `@on_removed(Poisoned)` without an `old: Poisoned` param, and `@on_spawned` with extra params, each raise the allocated E12xx code.
- `src/etch/interp.zig` — `test "observer annotation requires a component type"` — `@on_added(NotAComponent)` is rejected.
- `src/etch/interp.zig` — `test "observer rule rejects when clause and conflicting lifecycle annotations"` — `@on_added(Health)` with a `when` clause, and a rule carrying two lifecycle annotations, are each rejected.

**E3 — Tier-0 + bridge (behavioral):**
- `src/core/ecs/observers.zig` inline — `test "add on entity already having the component fires on_replaced with old and new"`.
- `src/core/ecs/observers.zig` inline — `test "on_removed receives the pre-removal value"`.
- `src/etch/interp.zig` — `test "@on_added(T) fires at flush when T is added via command buffer"` — an Etch `@on_added(Health)` rule body runs once, with `entity` and `health` bound, when a `Health` is added and the buffer is flushed; it does not run during the emitting rule's body.
- `src/etch/interp.zig` — `test "@on_removed(T) binds the correct old value"`.
- `src/etch/interp.zig` — `test "@on_spawned and @on_despawned fire on spawn/despawn"` — `@on_despawned` runs before destruction (entity components still readable).
- `src/etch/interp.zig` — `test "observer body structural mutation is deferred (no recursion)"` — a structural change issued from an observer body is applied at the next flush, not re-entrantly.

## Notes

**Staging (STOP-for-review).** Implement E1, then E2, then E3. At the end of each stage, with its tests green, emit `étape E<n> terminée, prêt pour review`, commit + push, and **wait for an explicit GO** before starting the next stage. A context overflow inside a stage is not a stop condition — continue in the same session; only the STOP-for-review gate halts.

**Terminology landmine.** In the existing code, "observer" already denotes the `@on_event` drain (`interp.zig: runObserver`). The structural hooks introduced here are a different mechanism that fires at command-buffer flush. Keep the names distinct in new code (`runObserver` stays the event drain; structural-observer functions get a clearly different name).

**Why annotation-routing, not the §8 `observer` keyword.** Etch annotations are open (`@` + IDENT + args), and `@on_event(T)` already routes a lifecycle hook onto a rule with zero lexer/grammar-declaration cost. Reusing that path for structural observers avoids a new keyword and a new top-level declaration form. The `observer` keyword in `engine-ecs-internals.md` §8 is stale and is reconciled by Claude.ai; it is not implemented.

**`on_replaced` is in scope** (full Tier-0 list + dispatch + the `old`/`new` signature). Replace is triggered exclusively by `add_component` on an entity that already has the component.

**Design-deferral rationale for the `ObserverFn` signature change.** `on_removed`/`on_replaced` must deliver `old` (a pre-mutation value the current `component_id`-only signature cannot provide). Building these without old-value capture now would force a later refactor of the signature, the dispatch, and the interpreter marshalling — so the uniform ctx + old/new signature is done now, not later. `on_added`'s value remains fetchable post-apply via `world.get`; the explicit `new_value` is provided uniformly to avoid special-casing.

**Dispatch ordering (from §8, do not re-derive).** `on_spawned` fires after spawn apply, then `on_add` for each initial component; `on_removed` (pre-apply) then `on_despawned` on despawn; `on_despawned` runs before destruction with the entity's components still readable.
