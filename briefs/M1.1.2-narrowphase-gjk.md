## Context

Third sub-milestone of M1.1 (Forge 3D rigid branch, comptime core arc M1.1.0–15). Delivers the first narrowphase layer: distance-based GJK detection between convex shapes (sphere/box/capsule), consuming the candidate pairs produced by the M1.1.1 broadphase. GJK runs on the shapes' convex **cores** (point / segment / box) with an inflation radius carried alongside — the Jolt convex-radius architecture — so the plan's touch/no-touch acceptance is `distance(cores) ≤ r_a + r_b`. EPA + contact manifold is the NEXT sub-milestone (M1.1.3); pair-type fast paths are M1.1.4. Algorithm scope is Jolt-inspired (GJK closest-point, Voronoi-region simplex solver), not a clone.

## Scope

- **E1 — Support shapes + support functions.** `src/modules/forge/forge_3d/pipeline/narrowphase.zig` created, generic over `comptime T: type`, importing `foundation` (math) only (same dependency discipline as `broadphase.zig`). `SupportShape(T)` = `{ core: Core, radius: T }` with `Core = union(enum) { point, segment: T, box: Vec3 }` (see Notes for the exact freeze). Local support function `support(core, dir) Vec3` per core variant with fixed tie-breaks (see Notes). Relative-pose precompute: GJK evaluates in the frame of shape A — `rot_rel = conj(rot_a)·rot_b`, `pos_rel = conj(rot_a)·rotate(pos_b − pos_a)` — computed once per pair; A's support needs no rotation. Unit tests: extremal points per core on cardinal and oblique directions, and through non-trivial relative rotations.
- **E2 — Simplex solver (Voronoi regions).** Origin-closest-point on point / segment / triangle / tetrahedron as pure functions (Ericson-style case analysis), each returning the closest point, the barycentric coordinates, and the reduced supporting feature (which simplex vertices survive). Simplex vertices are triplets `(w = a − b, support_a, support_b)` so closest points on A and B are reconstructible from the barycentrics. Fixed region-evaluation order (deterministic tie-breaks). Exhaustive unit tests per case: interior / face / edge / vertex regions, plus degenerate inputs (duplicated vertices, collinear triangle, coplanar tetrahedron).
- **E3 — GJK loop + result.** Iterative descent on the Minkowski difference of the two cores: `support_{A−B}(d) = support_A(d) − support_B(−d)` (B's support through the relative pose). Bounded iterations (named constant, 32) and a named relative termination tolerance; termination on lack of progress, never on exact float equality. `GjkResult(T)` with `status: enum { separated, shallow, deep }`: `separated` (core distance strictly greater than `r_a + r_b`) and `shallow` (cores disjoint, inflated shapes touching or overlapping) both carry the core distance and the closest points on both cores re-expressed in **world** space; `deep` (cores intersect) carries the terminal origin-enclosing simplex (EPA seed for M1.1.3) and no distance. The plan's touch/no-touch = `status != .separated`. Tests: all 6 type combinations (ss, sb, sc, bb, bc, cc) in all 3 regimes with non-trivial rotations; distances checked against analytic values; returned closest points consistent (their separation equals the returned distance; each lies on its core); determinism (two runs, identical results); adversarial convergence case (near-parallel box faces) terminates within the iteration bound.
- **E4 — forge_3d integration.** `shape.zig`: `supportShape(shape: Shape) SupportShape(Real)` conversion (sphere → point + r, capsule → segment(half_height) + r, box → box(half_extents) + 0). `body_manager.zig`: safe getter `rotation(id) ?Quatr` (symmetric to `position`), and `gjkPair(store: *const ShapeStore, a: BodyId, b: BodyId) ?GjkResult` — resolves both bodies' pose + support shape and runs GJK; null on any stale handle. `root.zig` re-exports at `Real` (`SupportShape`, `GjkResult`, plus what naming conventions require) + comptime test pins. Integration test: bodies via `BodyManager`, proxies via `Broadphase(Real)` (M1.1.1 pattern), `computePairs` → unpack `user_data` as `BodyId` → `gjkPair` per candidate; fat-AABB false positives (AABBs overlap, shapes don't) come back `.separated`. Full suite green at f32 and under `-Dphysics_f64=true` (local). `CLAUDE.md` updated per §3.4.

## Notes

- **Dependency discipline.** `pipeline/narrowphase.zig` imports `foundation` (math) only — never `weld_forge`, never `body*.zig`, never `config.zig`, never `broadphase.zig`. The scalar arrives as the comptime parameter `T`; forge_3d instantiates at `config.Real`. The `Shape → SupportShape` conversion and the `BodyId`-level `gjkPair` adapter live on the forge_3d side (`shape.zig`, `body_manager.zig`), mirroring the broadphase `user_data` discipline.
- **Distance-based GJK, not boolean GJK.** The boolean variant (origin-enclosure only) uses a simplified simplex walk that never computes closest points — upgrading later means rewriting the core. EPA (M1.1.3) seeds from the terminal simplex, the manifold and the character controller (M1.1.12) need closest points/distance, so the simplex stores `(w, support_a, support_b)` triplets from day one.
- **Cores + inflation radius (Jolt convex-radius architecture).** GJK never sees a curved surface: sphere = point, capsule = segment, box = full box (radius 0). Touch test = `dist(cores) ≤ r_a + r_b`. Fast convergence, no simplex degeneracy near contact, and it makes EPA rarely needed in M1.1.3 (shallow contacts resolve from distance + closest points).
- **`SupportShape(T)` freeze:**
  ```zig
  pub fn SupportShape(comptime T: type) type {
      return struct {
          core: Core,
          /// Inflation radius around the core (0 for box in M1.1.2).
          radius: T,
          pub const Core = union(enum) {
              /// Sphere core: the local origin.
              point,
              /// Capsule core: Y-axis segment, ±half_height.
              segment: T,
              /// Box core: half-extents (full box, no shrink).
              box: math.Vec(3, T),
          };
      };
  }
  ```
  Future shapes (cylinder, convex hull — M1.1.19) are new `Core` cases, purely additive.
- **Simplex solver: Voronoi-region case analysis (Ericson), not Johnson, not signed-volumes.** Johnson's subalgorithm has known determinant degeneracies; signed-volumes (Montanari 2017) has a thin f32 validation corpus. Explicit closest-point-to-origin on point/segment/triangle/tetrahedron with feature reduction is the Jolt lineage: each case is a pure, unit-testable function. Region evaluation order is fixed (first matching region wins) — a determinism tie-break.
- **Computation in the frame of A.** B is pre-transformed relative to A once (`rot_rel = conj(rot_a)·rot_b`, `pos_rel = rotateByConj(rot_a, pos_b − pos_a)`); A's support runs untransformed. Better precision far from the world origin (avoids large-coordinate cancellation), half the per-iteration transforms. Frozen NOW because changing the computation frame after the M1.1.14 determinism freeze would break validated bit-exactness. Closest points are re-expressed in world space on output.
- **`GjkResult` regimes.** `separated` iff `dist² > (r_a + r_b)²` strictly — exact touch (`dist == r_a + r_b`) is `.shallow`, consistent with the face-inclusive `Aabb.overlaps` convention (touching counts). `.deep` carries the terminal simplex only; any depth/normal computation is M1.1.3.
- **Determinism by construction (anticipates M1.1.14).** No hash containers, no trigonometry (dot/cross only), bounded iterations (`max_gjk_iterations = 32`, named constant), named relative tolerance on the squared-distance progress test, fixed support tie-breaks: capsule direction with `dir.y == 0` → the `+Y` endpoint; box direction component `== 0` → the `+half_extent` corner component. Termination is progress-based (distance no longer decreases beyond tolerance, or the new support vertex does not move the simplex closer), never an exact float equality.
- **Trap: normalization of the search direction.** Do not normalize `d` between iterations — GJK only needs directions, and normalizing adds a sqrt per iteration plus a divide-by-near-zero hazard when the origin is close to the simplex. Work with squared distances; take a single sqrt at the end for the reported distance.
- **Trap: initial direction.** Seed `d` from the relative position (`pos_rel`), falling back to a fixed axis if degenerate (zero vector) — fixed fallback = determinism.
- **Trap: `Quatr` rotate-by-conjugate.** `foundation` exposes `Quat.conjugate()` and `Quat.rotateVec3()`; inverse-rotating a direction is `q.conjugate().rotateVec3(v)` (unit quaternions). Do not call `inverse()` on the hot path (it divides by the squared norm).
