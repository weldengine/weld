## Context

Ninth sub-milestone of the M1.1 rigid arc (M1.1.0–15, `PhysicsModule` freeze at M1.1.15). The contact solver landed range-shaped on purpose: `solveRange` and `solvePositionRange` resolve `[from, to)`, and this milestone is what fills those ranges with meaning. It partitions the simulated bodies into independent islands, drives both solver passes per island, and puts a resting island to sleep so that it stops costing narrowphase, integration and solve work. It also settles the iteration-budget question M1.1.7 assigned here — by refuting its premise (see § Notes, inherited finding (d)).

The plan's acceptance line for M1.1.8 asks for independent groups and for a group at rest to fall asleep. The normative model is `engine-physics-forge.md` §1.8, authored and re-uploaded to the KB before this brief.

## Scope

- `pipeline/island.zig` — branch-neutral island core: union-find over **opaque** body indices (path compression + union by size), seeded per body so an unlinked body is a singleton group. Imports `std` only — no `weld_forge`, no `config.zig`, no `rigid/` type, mirroring the broadphase/narrowphase dependency discipline.
- `pipeline/sleep.zig` — `SleepConfig` (`allow_sleeping = true`, `point_velocity_threshold = 0.03` m/s, `time_before_sleep = 0.5` s, derived `maxDisplacement()` = product) with entry-asserted domain, plus the per-body sleep-window sweep and the eligibility predicate.
- Per-body sleep state on the SoA store: `BodyFlags.can_sleep` + `BodyFlags.sleeping` (two bits taken from the existing `_reserved: u7`, byte size unchanged), and four columns `sleep_time`, `sleep_ref_position`, `sleep_ref_rotation`, `sleep_radius`.
- `BodyDescriptor.can_sleep: bool = true` — closes the gap where the public `RigidBody` component carries `can_sleep` while the descriptor and the internal body drop it (same class as the `friction`/`restitution` drop closed at M1.1.6).
- Write-intent separation on `BodyManager` (§1.8.4): `setLinearVelocity`/`setAngularVelocity`/`setPosition`/`setRotation` are **non-activating by contract** (they are the solver's own write path); `addForce`/`addTorque`/`addImpulse` are **activating** (wake + reset the window even if the body was already awake); `wakeBody(id)` and `setCanSleep(id, …)` are the explicit primitives.
- `rigid/island_manager.zig` — the rigid adapter: seeds the core with every awake dynamic body, links dynamic↔dynamic contact constraints only, ranks islands by minimum member `BodyId`, sorts constraints by the composite key `(island rank, pair_key)` into contiguous ranges, records per island whether it touches a moving non-member, then arbitrates activation (W2, W3) and, at the end of the tick, the sleep transition (AND over members).
- Fixpoint in `contact_constraint.build`: skip a candidate pair whose two endpoints are both non-awake (recording it in a deferred list), wake a sleeping endpoint as soon as a manifold appears, re-scan the deferred list while a pass wakes at least one body. `build` takes `bm: *BodyManager` instead of `*const BodyManager` (no call site text changes).
- Sleep skips: `integrateVelocities`/`integratePositions` skip sleeping bodies (the force/torque accumulator reset stays uniform over all live bodies, §2); the harness skips the broadphase proxy update of a sleeping body.
- `velocity_solver.solveRangeReport(bm, constraints, from, to, cfg) VelocitySolveResult` — the sibling entry that returns `iterations_run`, plus the early-out: an iteration that applies no impulse (true-zero `Δλ` test) ends the pass. `solveRange` keeps its exact signature and becomes `_ = solveRangeReport(…)`.
- Test harness (`tests/solver_test.zig`) upgraded to the 11-step normative cycle of §1.7, driving both solver passes per island, and `allow_sleeping = false` on every inherited convergence test.
- Corrections carried by this milestone: the `solver_config.zig` doc comment repeating the refuted Jolt claim; the `position_solver.zig` §1.9 → §1.10 spec reference.

## Acceptance criteria

### Tests

`tests/island_test.zig`

- `test "island core seeds singletons and links only seeded indices"` — an added-but-unlinked index is its own group; linking is idempotent and symmetric.
- `test "island core grouping is invariant under link-order permutation"` — same partition for any permutation of the link sequence (purity of the core).
- `test "two separated stacks partition into two islands"` — disjoint contact groups, two ranges, every constraint assigned.
- `test "a static ground does not link the bodies resting on it"` — two boxes resting apart on one ground stay in two islands, and each ground contact belongs to its dynamic body's island (no constraint left unassigned).
- `test "a moving kinematic platform does not link but forces its islands awake"` — no fusion through the platform (W3 activation asserted separately in `sleep_test.zig`).
- `test "a dynamic body with no constraint is a singleton island"` — present in the island table with an empty constraint range.
- `test "island ranks are ordered by minimum member BodyId"` — ranks strictly increasing in min member `BodyId`; no tie possible.
- `test "constraint ranges are contiguous and pair-key ascending inside each island"` — the composite ordering holds without relying on sort stability.
- `test "per-island solve equals global solve bit-exactly on disjoint islands"` — both passes, two disjoint stacks, bit-for-bit equality of every body's pose and velocity against a single global range on the same constraint array.
- `test "island partition is invariant under body add-order permutation"` — the partition (the sets of bodies grouped together) is identical; bit-exactness is **not** asserted, because permuting add order changes `BodyId`s hence pair keys hence solve order.

`tests/sleep_test.zig`

- `test "the sleep window is a displacement bound, not an instantaneous velocity"` — a body kept within `maxDisplacement()` over the window becomes eligible; one crossing it resets the reference pose and the window.
- `test "rotation alone resets the window through the sleep radius"` — pure angular motion with zero linear displacement exceeds the bound and prevents eligibility.
- `test "solver writes never rearm the sleep window"` — a box resting on the ground reaches sleep **while both solver passes write its velocity and pose every tick**. This test fails if any solver write path is treated as an external mutation. RED-first: it must be shown failing against an activating variant of the four setters before the contract is in place.
- `test "can_sleep false never sleeps"` and `test "allow_sleeping false never sleeps"` — each independently.
- `test "a resting island sleeps and stops costing"` — after ~`time_before_sleep`, the constraint array is **empty** for that island and every member's position and rotation are bit-frozen over the following 60 ticks.
- `test "falling asleep zeroes both velocities exactly"` — exact zero, not an approximate comparison.
- `test "an external impulse wakes a sleeping body and resets its window"` — `addImpulse` on a sleeping body; `addForce` likewise.
- `test "a non-activating pose write does not wake, an explicit wake does"` — `setPosition` alone leaves `sleeping` set; `wakeBody` + `setPosition` clears it.
- `test "an impact wakes the whole sleeping stack in one tick with its internal contacts"` — five-box stack asleep, one dynamic body dropped on top: after **one** tick all five members are awake **and** the constraint count is back to its pre-sleep value plus the impactor's contacts. Penetration inside the woken island stays `<= 5 * penetration_slop` during the wake tick and the five following ticks, and returns to `<= penetration_slop + O(floatEps(Real)·coordScale)` within 30 ticks (envelope pre-registered here, §1.8.5 — not to be widened after measurement).
- `test "removing the support under a sleeping body wakes it"` — W4 at harness level (the harness owns the retained pair set).
- `test "sleeping and waking is bit-deterministic across two identical runs"` — two worlds built identically, same tick count, bit-identical poses, velocities, sleep flags and windows.

`tests/solver_test.zig` (inherited, modified)

- Every convergence test (five-box stack, resting box, mass ratio) runs with `allow_sleeping = false`. Envelopes are re-measured and reported with before/after values; the expectation, motivated but to be verified, is **no envelope movement** — the stack plus its ground is a single island, therefore a single range, therefore the same termination as today. Any movement is reported with both numbers.

## Notes

- **Inherited contracts, binding on this design.** (a) `solveRange` and `solvePositionRange` keep their exact signatures — the range shape is the seam this milestone consumes, and the iteration telemetry arrives through the sibling `solveRangeReport`, not through a changed return type. (b) `build` sorts constraints by ascending pair key and points are in manifold order; island ranks, membership and constraint order must be a **pure function** of the awake dynamic set and that sorted array (anticipates M1.1.14). (c) NGS termination is evaluated per range, never globally; for disjoint islands this is bit-exactly equivalent to a global range, which is what the equivalence test asserts. (d) **The premise of the inherited iteration-budget item is refuted.** M1.1.7 recorded that Jolt derives the velocity budget per island so a deep stack automatically gets more iterations, and designated this milestone as the owner of that mechanism. Read on the source: `PhysicsSettings.h` carries global defaults (`mNumVelocitySteps = 10`, `mNumPositionSteps = 2`) and `CalculateSolverSteps.h` aggregates a **maximum over author-supplied per-body/per-constraint overrides**, falling back on the global default — there is no topology-derived heuristic of any kind. What lands here instead is the mechanism that makes a high global floor affordable: the velocity-pass early-out (`PhysicsSystem.cpp`, `if (!applied_impulse) break;`). The override channel is recorded as additive with no Phase-1 consumer. (e) The warm-start cache evicts implicitly at `endTick`, so a woken island cold-starts for one tick — accepted, with the numeric envelope pre-registered in the acceptance criteria and in §1.8.5. If a measurement leaves the envelope, the answer is selective cache retention at `endTick` **inside this milestone**, not a widened envelope. (f) Candidate-pair retention is a correctness condition, not an optimisation: it is the persistent wake graph (§1.8.7). The harness must keep retaining every emitted pair. (g) The per-tick cycle is normative (§1.7, eleven steps) — activation at step 5, sleep transition and velocity zeroing at step 11, nowhere else. (h) `PositionSolveResult` stays telemetry and is never a sleep criterion. (i) Sleep thresholds are physical constants carried by the config (m/s and s), the same class as `restitution_threshold` and `penetration_slop`; `maxDisplacement()` is their named product, never a literal; every numerical guard stays at true zero. (j) Statics and kinematics never join an island.
- **Design points verified against the reference implementation** (read, not recalled): islands are built from the **active bodies** list, then constraints are attached (`IslandBuilder.cpp`, `Finalize(inActiveBodies, …)` → `BuildBodyIslands`); bodies are linked **only if both are dynamic**, with the stated reason that a constraint cannot affect the velocity of a kinematic body, and each contact is linked to its **first dynamic body** (`ContactConstraintManager.cpp`); a sleeping dynamic body is activated at constraint creation (`ActivateBodies` in the same function); the sleep test is a per-body **displacement** bound over a window — three tracked points, growing spheres, `max_movement = mPointVelocitySleepThreshold * mTimeBeforeSleep` — and never an instantaneous velocity (`Body.cpp`, `UpdateSleepStateInternal`; `PhysicsSettings.h`); the island sleeps only if **every** member can sleep (`PhysicsSystem.cpp`, `CheckSleepAndUpdateBounds`, `all_can_sleep &= …`), checked after the solve; island dispatch order is a job-balance heuristic on constraint count (`IslandBuilder.cpp`, `SortIslands`), unrelated to island identity.
- **Consequence of (j) plus the displacement criterion — the anti-masking rule.** A displacement-bounded criterion lets a slowly creeping body sleep. The M1.1.7 conclusion that a 0.047–0.075 m/s instantaneous residual was "above the Jolt threshold" and therefore could never have been masked by sleep compared an instantaneous velocity against a threshold that is not applied to an instantaneous velocity. It is false. Every convergence measurement in this repository runs with `allow_sleeping = false`, and this milestone measures and reports the 8-iteration case with sleeping enabled to document the masking explicitly.
- **Alternatives examined and rejected.** A persistent sleeping-group structure recorded at sleep time (re-persists an island identity §1.8.3 refuses to attach, needs invalidation on body removal, static teleport and shape change, and saves nothing — rebuilding a woken group's internal contacts goes through the narrowphase either way; the retained pair set already is the adjacency graph). Moving the island manager into `rigid/` because its first input is a rigid type (both `engine-physics-forge.md` §1.2 and `engine-directory-structure.md` place `island.zig` in the shared pipeline; the union-find core is genuinely neutral and the adapter is thin). Waking on the broadphase delta (the fat margin is 0.1 m, so a proxy re-emits only every 0.1 m of travel — a 1 m/s mover would emit once every six ticks, and mere fat-AABB proximity would wake sleepers spuriously). An instantaneous velocity criterion (resets on a single noisy tick, and never sleeps a jittering body — which is one of the things sleeping exists to kill). Jolt's three sleep-test spheres (a dozen accumulated scalars per body and a drifting sphere centre, for the same semantics a reference pose plus a radius gives without accumulation). Changing `solveRange`'s return type (a signature change on a frozen seam; Zig would reject the ignored value at every call site). A separate angular threshold in rad/s (a second constant with no unit relation to the first; the radius-scaled bound covers rotation in metres). Materialising a link array for the neutral core (the adapter calls `link()` directly, no allocation, no copy).
- **`build` signature change, authorised.** `bm: *const BodyManager` → `*BodyManager`, because waking a sleeping endpoint at constraint creation is intrinsically the pair-set consumer's business (Jolt does it in `CreateConstraint`). No call site changes textually: every existing call passes an address of a mutable `BodyManager`. This is not a range-seam change.
- **Determinism by construction (anticipates M1.1.14).** No hash container anywhere on the path. Union-find with path compression and union by size, seeded and linked in the sorted constraint order. Island ranks by min member `BodyId` — unique by disjointness, so no tie-break exists. Constraint order by the composite key `(rank, pair_key)`, so ordering never depends on the sort algorithm's stability. The wake fixpoint scans in sorted pair order and `build` re-sorts its output. Per-island solving preserves bit-exactness against the global range, and will still preserve it when islands run in parallel (disjoint body writes, merge in island order).

**2026-07-25 — E2 review fix: the aliasing limit of a pose-sampled criterion.** The
header claimed `d` over-estimates the displacement of every material point and that a
radius bound "sees every rotation". True of the NET displacement from the reference
pose, false read as a bound on MOTION: `2·|vec(Δq)| = 2·sin(θ/2)` is a CHORD — it peaks
at θ = π and returns to zero at θ = 2π. A body completing an exact revolution per tick
therefore samples as motionless and can sleep while spinning at 2π/dt ≈ 377 rad/s, and
the regime is not measure-zero (at r = 0.866, ±0.1 rad/s around a multiple of 377 stays
under 15 mm for the whole window). A wheel in the air on a stopped vehicle is exactly
that configuration, and vehicles are Phase 1 (M1.1.21).

This is NOT a design defect to fix: the aliasing is inherent to any pose-sampled
criterion, Jolt's three tracked points alias identically, and the only "correction"
would be to read ω — reintroducing the instantaneous quantity §1.8.3 rejects by name,
plus a second threshold in rad/s with no unit relation to the first. The defect was that
it went unwritten while the header asserted the opposite. Fixed by documentation only —
the aliasing paragraph in the header, the Jolt-divergence sentence bounded by it — plus
a limit test, `"a rotation aliased to a whole turn per tick is invisible to the window
(documented limit)"`, which asserts the REAL behaviour and says so in its name. It
carries its own sanity assertion (the sampled chord really is under the bound at every
tick) and a discrimination guard (the identical loop at a HALF turn per tick sweeps
2·r ≈ 1.73 m and never becomes eligible), so what is pinned is the aliasing of a
rotation that genuinely happened, not a test that rotates nothing. No RED-first staging:
it pins an existing regime and drives no design. **Zero production lines changed** —
`updateWindows` is untouched. Owed to `Closing notes` at close, under residual risks.

**2026-07-25 — E4 trap recorded now, not discovered later.** It follows directly from
the semantics just set: a static body NEVER has `sleeping == true`, because the window
sweep skips non-dynamic bodies entirely. So `build`'s skip filter cannot be written

**2026-07-25 — E3 finding, caught by its own test: the permutation convention.**
`applyPermutation` was written with the textbook in-place loop while the sort keys
carried the SOURCE convention ("position i takes from `source_index`"). That loop
implements the DESTINATION convention ("what is at s goes to `perm[s]`"), and fed a
source permutation it does not fail — it silently produces a different, wrong order.
Worse, it swapped the KEYS along with the constraints, so the sorted key array was
scrambled and the range scan that reads ranks from it ran off the end.

Both showed up as the same crash, on `"island ranks are ordered by minimum member
BodyId"` and `"constraint ranges are contiguous and pair-key ascending inside each
island"` (204/207, three crashes):

```
thread panic: reached unreachable code
   island_manager.zig:362: std.debug.assert(cursor == self.keys.items.len);
   island_manager.zig:173: try self.orderConstraints(gpa, bm, constraints);
   island_test.zig:392: try rig.partitionAll(gpa);
```

Fixed by inverting explicitly into a `destination` scratch array before permuting, which
also leaves `keys` sorted so the range scan is reading what it thinks it is reading. The
convention trap is now named in `applyPermutation`'s doc comment — it is the kind of
error that produces plausible output rather than a crash, and it only crashed here
because the corrupted keys tripped the tiling assert. The composite-key test was built
to discriminate: creation order `0,3,4,1,2` gives a chain `{0,3,4}` of rank 0 owning the
LARGEST pair key of the scene, and a far pair `{1,2}` of rank 1 whose key sits strictly
between the chain's two — so pair-key order and rank order genuinely disagree, and the
test asserts that ordering explicitly rather than trusting sort stability.

**2026-07-25 — E4 finding: an over-specified iteration count, caught by the f64 leg.**
The approaching-contact case asserted `iterations_run == 2` on the reasoning that a
sphere pair with its lever arm parallel to the normal solves in exact arithmetic. Green
at f32, RED at both f64 runs — `expected 2, found 3`. The reasoning was wrong: an exact
count of a float convergence is not a contract, it is last-bit behaviour, and it
legitimately differs by precision. Re-anchored on the contract itself: the pass stops
short of its budget, and once stopped the state is a FIXED POINT — solving the same
range again spends exactly ONE iteration, the one that finds nothing to apply, and
leaves every velocity bit-unchanged. That statement is precision-independent and says
more than the count did. The separating case keeps its exact `== 1`, which is structural
(the Catto clamp pins λₙ at zero and the friction cone has zero width) rather than
arithmetic.

**2026-07-25 — E4 review fix: the first pass was discarding its own wake signal.**
`build`'s first pass wrote `_ = try emitPair(…)`, throwing away the return value that
IS the fixpoint's progress signal, and compensated with a pessimistic
`var woke_someone = true`. Correct results, but it made a resting tick — the exact state
this milestone exists to make cheap — run one empty round: the loop condition was true,
every deferred pair was re-tested with `bothAsleep`, nobody woke, exit. So each sleeping
pair paid the awake predicate twice per tick, two `validate` calls plus the flag/type/
velocity reads each time, while the doc comment claimed "the second pass does not
happen: zero cost". The wrong place for a false claim, that one being the milestone's
central promise.

Fixed by carrying the signal instead of guessing it: the first pass sets
`woke_someone`, the loop starts from `false`. Safe because `bothAsleep` can only change
through a wake — if pass one woke nobody, no deferred pair became processable. Better on
both axes at once, and at rest the loop now does not run. The cost model in the doc
comment was rewritten to state what a resting tick actually pays (one awake test per
candidate pair, one `u32` per deferred pair, that list's allocation) against what the
skip removes (the narrowphase and `prepare` of all of them), with the per-tick buffer
flagged as movable to the orchestrator's scratch at M1.1.15 — `build` owns no state, so
it cannot be reused from here. No signature change.
