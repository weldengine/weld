## Context

M0.2 completes the Tier 0 of the Weld core: runtime reflection (native Weld RTTI), singleton resources, event bus, refactor of the separate `vk_gen`/`wayland_gen` bindgen into a unified `.api.zig` system, and Plugin loader skeleton. This milestone delivers the first step toward the C0.5 freeze of the Tier 0 interfaces (RTTI + Resources + EventBus marked "frozen" at the end of the milestone) and criterion C0.10 (unified bindgen operational), a Phase 1 prerequisite. It absorbs two Phase −1 debts: **D-S6-RTTI** (swapping the S6 comptime `std.hash.Wyhash` for the native Weld RTTI) and **D-S2-bindgen** (merging `tools/vk_gen` + `tools/wayland_gen` → `tools/bindgen/`).

## Scope

- **Native Weld RTTI** in `src/core/rtti/`: comptime registry of components/resources/events/messages with metadata (`type_id`, `type_name`, `size`, `alignment`, `schema_hash`, `fields[]`, `category`, `lifecycle?`). Deterministic hash `xxHash32(@typeName(T))` for `type_id`, `xxHash64` over `(typeName, [(field.name, kind, count, offset)])` for `schema_hash`. Idempotent registration (same `type_id` + same `schema_hash` = silent; same `type_id` + different `schema_hash` = `error.SchemaMismatch`).
- **S6 IPC swap**: `src/core/ipc/messages.zig` no longer imports `std.hash.Wyhash` directly; it consumes `core/rtti.computeSchemaHash(T)`. The call-site signature (`schemaHashOf(comptime T: type) u64`) is unchanged. The effective algorithm is strictly equivalent (same hashed tuple, same seed) — bytes emitted on the socket are identical.
- **Resource system** in `src/core/resources/`: singleton entities (consistent with `ARCH-006`), API `setResource`/`getResource`/`getResourceMut`/`hasResource`/`removeResource`/`resourceChanged`. `HashMap(TypeId, EntityId)` lookup in `World.singleton_entities`. Exclusion from normal queries via the `is_resource` archetype flag. Tick-based change detection (reuses the M0.1 mechanism). Lifecycle tags (`@config`/`@state`/`@transient`) declarable via RTTI metadata (category `.resource`).
- **Event system** in `src/core/events/`: one MPMC queue per event type, fixed ring buffer of 1024 entries by default (configurable via the `cap` parameter at registration), lifetimes `tick`/`phase`/`frame`, FIFO ordering per type (no cross-type guarantee), saturation = drop oldest FIFO + increment `drops: atomic.Value(u64)` + log warning if `drops/sec > 10`. Drain at the corresponding boundary, called by the scheduler.
- **Unified bindgen** in `tools/bindgen/`: refactor of `tools/vk_gen` + `tools/wayland_gen` into a single generator with a formalized `.api.zig` format, validator, cross-api import resolver, idiomatic Zig emitter with dlopen support for 4 strategies (`dlopen`, `dlopen_loader_pattern`, `framework`, `static_link`). Adapters `vk_xml.zig` and `wayland_xml.zig`. 1:1 port — emitted bindings bit-for-bit identical to those on current `main`.
- **Plugin loader skeleton** in `src/core/plugin_loader/`: `loadPlugin`/`unloadPlugin`/`lookupSymbol` wrapper on top of `platform.dynamic_loader`, `WeldAPI` struct with **final signatures** (consistent with `engine-c-api.md` §4), sub-APIs `WeldEcsAPI`/`WeldResourceAPI`/`WeldEventAPI`/`WeldMemoryAPI`/`WeldServiceAPI`/`WeldEditorAPI`/`WeldPlatformAPI` with final signatures and stub implementations returning `WELD_ERR_NOT_IMPLEMENTED`. Load-time validation: `weld_plugin_entry` symbol present, `api_version_min` compatible with `WELD_API_VERSION_MAJOR`.
- **Partial C0.5 freeze**: audit of the `RTTI`, `Resources`, `EventBus` interfaces; addition of a leading doc-comment `/// FROZEN — see engine-phase-0-criteria.md C0.5` on each public type; freeze checklist ticked in `engine-tier-interfaces.md`.
- **M0.1 non-regression**: all ECS benchmarks (S1 cold-isolated gate, C0.1 full load) and all `tests/ecs/` + `tests/ipc/` tests stay green, within baseline bounds ± 5 %.

## Out-of-scope

- **Functional implementation of the 7 C plugin sub-APIs** — `WeldEcsAPI`/`WeldResourceAPI`/etc. have their final signatures but their callbacks return `WELD_ERR_NOT_IMPLEMENTED`. The real wiring to the Tier 0 Zig is Phase 3 (depends on the complete IPC M0.6, the complete platform layer M0.3+, the inter-module service registry not frozen in Phase 0).
- **Runtime capability enforcement** — `WeldPluginCaps` (`reads_components`, `writes_components`, `needs_filesystem`, etc.) is read and logged at `loadPlugin` but no inline check is inserted into the accessors. Phase 3 (depends on the violation-response model, which is unspecified — error return vs deactivation vs sandbox process — and is only exercisable with real Tier 3 plugins, which do not exist in Phase 0).
- **Plugin hot-reload** — Phase 3+.
- **Plugin process sandboxing / isolation** — Phase 3+.
- **Exported C header `include/weld_api.h`** via the bindgen `output_only` mode — Phase 3 (coupled with the finalization of the plugin C-API v0.x in M0.8).
- **C keeper bindings (Opus, Assimp, etc.)** — Phase 1.
- **libobjc bridge (Cocoa/Metal for macOS)** — Phase 2.
- **Fixes for the S2 D1 (`vk_gen` enum closure whitelist) and S2 D2 (VkResult aliases in enum block) debts** — scoped to M0.4 in `engine-phase-0-plan.md`. Fixing them in M0.2 would make the "empty diff" criterion infeasible (the fixes would change the emitted bindings). Strict 1:1 port.
- **Advanced ECS observers** — already delivered in C0.1 within M0.1.
- **X11 backend + `Window` extension** — M0.3.
- **Vulkan renderer + GAL** — M0.4.

### E4 — Event system

**Local scope.** Implement the EventBus with one MPMC queue per event type, wired onto the RTTI, drained by the scheduler at each boundary.

**Deliverable.**
- `src/core/events/lifetime.zig`: `Lifetime` enum (`.tick`, `.phase`, `.frame`).
- `src/core/events/queue.zig`: parameterized `EventQueue(comptime T: type)`. Fixed ring buffer (configurable cap, default 1024). Multiple producers (workers) write via CAS on `head: atomic.Value(usize)`. Consumers read via an independent cursor. `drops: atomic.Value(u64)` incremented on saturation (drop oldest FIFO). No producer blocking.
- `src/core/events/cursor.zig`: `EventCursor` (a consumer's state: `last_read: usize`). Reusable cross-tick for persistent subscriptions.
- `src/core/events/bus.zig`: `EventBus { queues: HashMap(TypeId, *anyopaque), emit, subscribe, drainAtBoundary }`. `emit` routes to the queue for `TypeId(@TypeOf(event))`. `drainAtBoundary(.tick)` resets the `.tick` queues, likewise for `.phase` and `.frame`.
- `src/core/events.zig`: public re-export module.
- Edit `src/core/ecs/scheduler.zig`: call `bus.drainAtBoundary(.phase)` at each phase transition, `bus.drainAtBoundary(.tick)` at the end of the fixed tick, `bus.drainAtBoundary(.frame)` at the end of the render frame (alias of `.tick` in Phase 0 since fixed = render).
- Log warning emitted if `drops/sec > 10` on a queue (via the Tier 0 log function already in place).

**Local acceptance criteria.**
- `tests/core/events/queue_test.zig` — `test "emit then poll returns the event"`, `test "FIFO ordering per type"`, `test "MPMC concurrent: 4 producers × 1000 emits → 4000 events polled with no loss"` (with cap > 4000 to avoid saturation), `test "two different types = two independent queues"`.
- `tests/core/events/saturation_test.zig` — `test "overflow drops the oldest FIFO entry"` (cap=4, emit 6 → poll returns the last 4), `test "drops counter incremented"`, `test "log warning emitted beyond the threshold"` (captures the log output).
- `tests/core/events/lifetime_test.zig` — `test "drainAtBoundary(.tick) resets only the .tick queues"`, `test "a .phase queue survives a .tick drain"`, `test "a .frame queue survives a .phase drain"`.
- `tests/core/events/scheduler_integration_test.zig` — `test "events emitted in the Update phase are drained before the PostUpdate phase when lifetime=.phase"`, `test "events emitted in frame N invisible in frame N+1 when lifetime=.frame"`.

**E3 technical decision — exclusion of singletons from queries (option (a) chosen).** Three mechanisms considered (cf. E3 directive §3): (a) `is_singleton: bool` flag on the `Archetype` struct; (b) reserved high bit in the `ComponentBitset`; (c) separate `world.singleton_archetypes` list filtered query-side. **Option (a) adopted**: 1 bool per archetype (~1 byte, negligible memory cost given the archetype count is capped < 100), no bit reservation in the mask, modification localized to `Archetype` + a single `if (arch.is_singleton) continue;` check in `Query.maybeRescan`. No conflict detected with the M0.1 Archetype implementation.

**E3 technical decision — lifecycle inference (struct convention chosen).** Two mechanisms considered (cf. E3 directive §5): (i) explicit registration `try resources.register(T, .state)`; (ii) struct convention `pub const lifecycle: Lifecycle = .state;` read at comptime by `buildTypeInfo`. **Option (ii) adopted**: declarative, comptime, no possible omission at registration. `buildTypeInfo(T, .resource)` reads `T.lifecycle` if declared, otherwise defaults to `.transient`. For the other categories (component/event/message), `lifecycle` stays `null`.

**M0.2 repo convention (`root.zig` rename).** The brief lists the files `src/core/resources/{registry,api}.zig` + `src/core/resources.zig` (re-export). E1 already applied the rename `src/core/rtti.zig → src/core/rtti/root.zig` to align on the `ecs/root.zig` convention (cf. "Acted deviations" E1 / rename). E3 applies the pattern **from creation onward**: module entry at `src/core/resources/root.zig`, no parallel `src/core/resources.zig` file. No second deviation to act this time — repo-internal pattern. E4 applies the same pattern: `src/core/events/root.zig` directly.

**E4 technical decision — EventBus as a direct field of World.** Two mechanisms considered (cf. E4 directive §6): (i) EventBus injected into the scheduler via `ModuleContext` at init; (ii) EventBus as a direct field of `World`. **Option (ii) adopted**: consistent with `singleton_resources` E3 (same Tier 0 service pattern hosted on World) and with `engine-tier-interfaces.md §0`, which lists `event_bus` among the `ModuleContext` Tier 0 services. The scheduler accesses it via `world.event_bus.drainAtBoundary(...)`, no separate injection needed. No technical conflict detected.

**E5 technical decision (i) — M0.2 adapters short-circuit the intermediate `ApiDescription`.** The E5 brief describes the canonical pipeline (XML adapter → `bindings/generated/*.api.zig` → `tools/bindgen/core/emitter.zig` → `src/core/platform/*.zig`). The brief's non-negotiable mechanical criterion is however "empty diff": the regen produces byte-for-byte the same Zig as the old `tools/vk_gen/` / `tools/wayland_gen/`. Routing 1497 lines of Vulkan-specific emission + 697 lines of Wayland-specific emission through a common intermediate format and a generic emitter entails a very high risk of bit-for-bit divergence (whitespace, internal ordering, stable IDs, etc.). **Position adopted**: the `vk_xml` and `wayland_xml` adapters carry the pipeline 1:1 from the old gen tools (parser + extractor + direct Zig emitter), and `bindings/generated/{vulkan,wayland}.api.zig` are sidecar placeholders containing the minimal descriptive metadata (name, version, source, link). The skeleton `core/{api_description, validator, resolver, emitter}.zig` is in place, code-complete for the semantics but not exercised by the M0.2 adapters. The first Phase 1+ adapters (keepers Opus/Assimp/etc. via manual `.api.zig`) will be the first real consumers of the complete pipeline. Accepted consequences: (1) `core/emitter.zig` stays a skeleton in M0.2 with no empty diff to emit on the Vulkan/Wayland side; (2) the sidecar `.api.zig` are minimal and not roundtrip-able to the emitted Zig. The structure is in place, the contract will be exercised in Phase 1+. The brief's Technical decision (i) explicitly authorizes this pragmatism: "choose the split that minimizes the risk of divergence on the empty-diff criterion. Track your decision."
