## Context

`ARCH-005` posits archetype storage in SoA as the default and a second, opt-in `SparseSetStorage` mode for components whose add/remove frequency makes archetype migration the dominant cost. **The second mode does not exist.** `@storage` is recognised by the parser and its applicability to `component` declarations is validated; its *value* is read nowhere, so an annotated component is stored in a table like every other one, without a diagnostic. `@requires` is in the same state: recognised, validated for applicability, applied by no code — which is not a missing optimisation but a silent functional bug, since the required component is never added and the rule that assumes it simply does not match.

This milestone delivers the second storage mode, the mixed-query planner, the job split of dense ranges, and `@requires`. It runs **before M1.A** and the ordering is constrained at both ends: M1.A.0 creates the comptime view where the declared access set parameterises the context, under the written requirement that the view compile to the same pointer arithmetic as a direct access. A sparse access is an indirection. Delivered after M1.A, the second mode forces re-typing that view for two access modes and re-running the disassembly counter-proof; delivered before, the view is born with both, once.

## Scope

**Front-end — `@storage` consumed.**

- The storage mode of every component is recorded in the runtime registry at registration, sourced from the resolved annotation; absence of `@storage` yields `table`.
- `@storage` with a value outside the `StorageKind` domain is refused with `E0503`; a syntactically valid but non-constant argument is refused with `E0504`. The domain is `table | sparse` and is owned by `engine-ecs-internals.md` §2 — the resolver validates against it and does not define it.
- An invalid-corpus fixture exercises the refusal. Without it, `E0503` is activated with no witness that anything is refused.

**Backend — `SparseSetStorage`.**

- Dense entity array, a component array parallel to it, a sparse index keyed by entity index with a reserved absence marker, and `added_ticks` / `changed_ticks` parallel to dense. Add and remove in O(1) by swap-remove.
- The seven backend invariants of `engine-ecs-internals.md` §2 (*Invariants du backend sparse*) hold and are each asserted independently: swap-remove parity of the tick sidecars, absence of a per-block skip, despawn across all storages, observer firing order over the union, zero-sized components, entity generation, OOM rollback.

**Routing — the resolution funnel.**

- The **five** Tier-0 entry points that resolve an `(entity, component)` pair route by mode: typed read, typed mutable read (with its auto-mark), dynamic byte read, the dynamic change stamp, and the `dynamicLocation` + `dynamicArchetype` pair that hands the archetype-chunk-slot triple to its caller. The fifth is consumed at fifteen distinct production locations.
- The Etch component handle — today a chunk pointer plus a slot — becomes able to designate a sparse row. This is the type M1.A.0 will parameterise; it is bimodal here or twice there.
- Every structural mutator routes by mode: the three spawn paths, the typed and dynamic add paths, the batched add, the single and batched remove paths, the prepared-remove trio, the tag mutation path, despawn, and the frame boundary — which is **two** functions, `beginFrame` and `tickBoundary`, of which only `beginFrame` is on the component-storage path.
- Every command-buffer apply path carries the routing. There are **three** switches over the same six command kinds, in **two** files: `CommandBuffer.applyOne` (`command_buffer.zig`), `applyWithObservers` and `applyRawCommand` — the deferred drain — both in `observers.zig`. All three are reachable in production and none has an `else` arm. A change landing in one and not the others is the dominant defect shape of this milestone.
- Observer dispatch: the despawn enumeration covers the union of table and sparse components, add-on-present detection no longer relies on archetype membership alone, and the per-component `on_add` firing at spawn covers both storages.
- Scene and prefab load: an Archetype Block becomes a serialisation group by logical signature. Table components determine the runtime archetype; sparse columns feed their own storage. The bifurcation is entirely inside the spawn path — the codec is not reopened, no cooked scene is invalidated, and changing a component's mode requires no re-cook.

**Mixed-query planner.**

- A query combining both storages elects exactly one driver — the member of smallest population, ties broken by declaration order in the query — and reaches the other members by O(1) membership test. A query whose members are all table iterates archetypes exactly as today.
- `not has T` on a sparse `T` ceases to be an archetype-level filter and becomes a per-entity membership test. The disjunctive path, which today de-duplicates by ascending archetype id, de-duplicates by entity when a term is sparse-driven.
- The per-slot guards of the interpreter — field filter, tag predicate, change filter, expression guard — take a storage-agnostic locator instead of an archetype-chunk-slot triple.
- **The mixed iteration is a new type. The frozen surfaces are not modified.** `WELD_ECS_PROTOCOL_VERSION` stays at 1, and the milestone proves it rather than asserting it.

**Scheduler.**

- The dispatch consumes a range of the dense array as a unit of work at parity with an archetype chunk, including work stealing.
- The bound that makes the split safe: no job body receives a command buffer. This is a bound to establish, not a merge mechanism to invent — no call site passes one today, and nothing in the current types forbids it.

**`@requires`.**

- The annotation is **variadic**. Transitive closure computed once at resolution, never re-walked per add.
- A cycle is a resolution error, not a fixed point.
- The whole closure is added in one transaction, or none of it. Applies identically to a spawn carrying a component with a non-empty closure, and to both storage modes.
- Removing the requirer removes nothing else. Removing a still-required component is refused **at type-check** wherever the shape of the program allows the refusal to be static; what static analysis cannot see is tolerated at runtime with a warning. A deferred command turned into an unobservable tick failure is not an acceptable refusal channel.

**Codegen.**

- The Zig codegen prototype **explicitly refuses** any program exercising a sparse component, until Phase 2-3 parity. No silent table fallback.

**Bench.**

- A crossover bench that measures, on the validation configurations, where the sparse mode becomes profitable against the table mode. This bench produces the thresholds; no document grades them.

## Acceptance criteria

### Tests

Each entry names the property, not the scene. The scene belongs to whoever has the compile loop.

- **`@storage` value is refused outside the domain** — a component annotated with a value that is not in `StorageKind` produces `E0503`, and the diagnostic names the offending value. The fixture pins the expected code in the facade, as every fixture of that directory does. Counter-factual: widening the accepted set makes the test red.
- **`@storage` non-constant argument produces `E0504`**, and the two fixtures are distinguished by their pinned codes rather than by both merely failing.
- **The registry records the mode** — a component declared with the sparse mode is reported sparse by the registry, and one declared without `@storage` is reported table. This is the test that would have failed for the four months during which the annotation was a no-op.
- **Swap-remove parity** — removing an entry that is not the last one relocates the trailing entry, and its `added_tick` / `changed_tick` travel with it. A change filter must see a relocated entity exactly as it would have seen it un-relocated.
- **Despawn purges every storage** — after despawning, no sparse index entry designates the dead entity, and re-spawning at the same entity index with a new generation does not inherit the dead entity's component.
- **Zero-sized sparse component** — a sparse tag is added, tested, and removed with no component array allocated and no pointer derived from one.
- **OOM rollback** — an allocation failure on the sparse add path leaves the world exactly as before the add. The induced failure must be one-shot: an allocator that fails once and then recovers, so the assertion after the failure distinguishes the property from exhaustion.
- **Observer firing order at despawn** — the `on_remove` callbacks fire in ascending component id over the union of table and sparse components. Counter-factual: permuting the declaration order of the components does not change the firing order.
- **Add-on-present on a sparse component** fires the replacement observer, not the add observer.
- **Both apply paths route** — the property is asserted on the observer-dispatching apply *and* on the raw apply that drains the deferred buffer, with a check that enumerates the command kinds covered on each. A test covering one path only is the defect this entry exists to prevent.
- **Mixed query, two sparse members of opposite cardinality** — the driver is the smaller one, every matching entity is visited exactly once, and the visited set is identical whichever member is smaller. This is the case neither of the two previous conflicting rules covered.
- **Mixed query, equal cardinality** — declaration order decides, and the decision is stable across runs.
- **All-table query is unchanged** — the iteration path taken by a query with no sparse member is the one delivered today, and a check states which path was taken rather than inferring it from the result.
- **`not has T` on a sparse `T`** excludes the right entities, and the exclusion is per entity rather than per archetype.
- **Disjunctive selection with a sparse-driven term** dispatches each matching entity exactly once.
- **Frozen surfaces intact** — no existing signature of the frozen ECS files changed, and `WELD_ECS_PROTOCOL_VERSION` is still 1. The check enumerates the surface it inspected and reports its size.
- **Dense range dispatch at parity** — a sparse-driven query splits across workers with the same work-stealing behaviour as an archetype-chunk query, and the split covers every entry exactly once.
- **No job body receives a command buffer** — the bound is checked over the whole set of dispatch call sites, and the check reports how many it inspected.
- **`@requires` adds the transitive closure** in one transaction; a failure part-way leaves the entity as it was.
- **`@requires` cycle is refused** at resolution with a diagnostic naming the cycle.
- **Removing the requirer keeps the required component.**
- **Removing a still-required component is refused** at type-check where the shape allows it, and produces a warning rather than a tick failure where it does not.
- **Codegen refuses a sparse program** explicitly, with a diagnostic naming the construct. Counter-factual: a program with no sparse component still compiles.
- **The differential corpus reader is storage-agnostic** — the final-state comparison reads a component regardless of its storage mode, instead of failing on archetype membership.

## Notes

**The first gate writes the contract, and the site list it writes from is below.** M1.1.15.2 specified the physics authority regime at the same time as it implemented it: the contract named three paths, the delivered behaviour traversed nine, and the last six were found one per external review pass. The site list for hybrid storage was produced by reading the repository at `3fd5472`, and it is given here so that the contract can be written from it rather than discovered through it. The reading being done does not make it complete — a path this list misses is a finding, and finding one is expected.

**Three contract shapes, each measured on M1.1.15.2.** Quantify rather than enumerate when a rule must cover future sites — *any site that does X must do Y, and failing to is a defect of that site*. State what does **not** move as much as what does: a matrix silent on a stable state is what the implementer fills with the available fact, and the available fact was the wrong one. Name what a rule does **not** cover, and why, when it could be read wider than its domain — a correct enumeration does not make a correct rule.

**A guard has two ways of being wrong** — missing what it should catch, and catching what it should let through. The second is proved by a counter-factual that *widens* the guard: if the widening reddens nothing, the boundary is not guarded. And a counter-factual that does not fire proves nothing about the guard being useless; it proves the scene does not reach it. If a first scene does not suffice, ask *why* before trying a second.

**The freeze is on the path, and the chosen exit is the new type.** **Eight** files of `src/core/ecs/` carry the C0.5 `FROZEN` marker — `command_buffer.zig`, `entity.zig`, `query.zig`, `registry.zig`, `resources.zig`, `root.zig`, `scheduler.zig`, `world.zig` — so **six of the seven** existing ECS files this brief assigns for modification are among them, `observers.zig` being the exception; the ECS protocol constant is 1. The repository carries the precedent that arbitrates it in writing: `world.zig:1449` justifies `queryDynamic`'s addition to frozen `world.zig` on the ground that C0.5 covers the Tier-0 ↔ Tier-1 interfaces, not internal `World` methods. G7 cites that precedent rather than re-deriving the argument. C0.5 freezes the interface contract explicitly while allowing the implementation behind it to evolve, so routing an existing read through a second backend is implementation. What would genuinely break is the chunk-based dispatch protocol, since a sparse-driven query has no chunk — hence a distinct iteration type rather than a second mode of the existing one. The tail-rescan helper is already a module-scope function shared by both existing query types, so a third caller costs a call and not a copy.

**Two Etch corpora, and the codegen refusal touches neither existing fixture.** The parse-and-type-check corpus and the differential corpus have separate facades. The existing annotated fixture, which today consecrates the `@storage` no-op as a valid case, lives in the first and never reaches codegen; it stays valid, because the annotation becomes genuinely valid. What it lacks is its invalid twin.

**The `.sav` and `.scene.bin` schema identity is blind to a constant-size field change**, and this is a class of silent corruption independent of this milestone. Nothing here should add a field inside existing padding without treating it as an event.

**What is decided and not to be re-litigated:** the driver is cardinality, ties broken by declaration order; iteration order is deterministic, non-invariant and out of contract; the storage mode is a runtime registry property and never on-disk identity; the codec is not reopened; `@requires` refusal is static where possible and a warning where not.

**What is open and is a stop, not a judgement call:** any path this brief's site list does not cover; any requirement to change a frozen signature or the protocol constant; any case where the refusal channel for a `@requires` removal cannot be made static *and* cannot be made a warning.

### G3 — Tier 0 routing

**What the gate was to establish.** That every resolution entry and every structural mutator of
`World` answers for BOTH backends, that a sparse id never enters an archetype signature, that the
despawn path sweeps every store, that a World-level membership test exists, and — carried over from
the G2 verdict — the `World` half of the empty-archetype permission.

**The partition is carried by a TYPE, not by an assert.** `getOrCreateArchetype` is `fn` — private —
with **eleven** call sites, all inside `world.zig`, so the funnel is unique and already
module-private: the obligation could be made structural without touching one external caller. It now
takes a `TableIds`, whose ONLY constructor is `splitByStorage`, so a signature cannot be built from a
set nobody partitioned. Deliberately not a `std.debug.assert`: a sparse id reaching a signature would
not crash, it would give the component a table column the sparse store also owns, after which the
answer depends on which of the two a caller consulted — a wrong answer with no diagnostic, the H1
class of M1.1.15.1, and an assert is live only in the two matrix cells where a breach costs nothing.
An INDUCTION over `Archetype.component_ids` was considered and refused: it holds today and it is a
proof a future reader can break by adding one archetype constructor. Every site re-splits instead,
which on the remove paths re-checks a set already known table-only — one registry lookup per id,
against a migration that memcpys every column. The compiler then named all nine sites owing a
decision, which is the design working rather than a chore.

**And the funnel is not the mutator list.** `applyTagMutation` mutates **in place** and reaches
`getOrCreateArchetype` only indirectly, so an enumeration of the funnel's callers does NOT find it —
the set of structural mutators is strictly larger than the set of signature builders, and the verdict
was right to name tag mutation separately. On a sparse `TagSet` the pre-G3 body asked
`arch.componentIndex`, got null, and fell into `else if (set)`: a `set` would have double-added an
existing row and a **`clear` would have been a silent no-op**. Routed through `componentBytes`, which
preserves the behaviour and not merely the shape — that entry hands out mutable bytes WITHOUT
stamping, exactly as the previous body did.

**One authority per question.** Routing consults the REGISTRY for the mode and the backend for
presence. Routing on `isSparse` — "a store slot exists" — would answer correctly by accident for a
component declared sparse that nobody has populated, falling through to an archetype that says
"absent" for the right reason by chance. `storageOf` also re-establishes a BOUND the old code had for
free: `componentBytes` takes a caller-supplied `ComponentId` and answered `null` for an unknown one
because `componentIndex` merely failed to find it, while `Registry.componentStorage` indexes
directly — so routing without the bound would have turned that same call into an out-of-range index.
`.table` for an out-of-range id reproduces the old behaviour exactly.

**The presence question was a real defect, derived rather than assumed.** The batched add's
`DuplicateComponent` check asked `src_arch.hasComponent(c)`, which answers `false` for a sparse
component the entity carries — so a batched add of an already-present sparse component passed the
check and reached `SparseSetStorage.add`'s own assert, live in Debug and **compiled to nothing in
ReleaseFast**: a silent double insert in the mode a game ships. That is what `hasComponentDyn` exists
for, and why it is not a convenience over `componentBytes() != null`. The same routing was needed on
`prepareRemoveComponentsDynamic`, where the unrouted form refuses a legitimate sparse drop with

**Ordering rules, each with a reason and not a preference.** Spawn writes the SPARSE side first and
the table slot last, because the sparse undo is infallible (a swap-remove over allocated arrays) and
the table undo is not (`removeSwap` plus repairing the swapped-in entity's location) — the step with
the messier undo goes last and has nothing after it to unwind. The prepared trio drops its sparse
rows in **`commit`** and not `prepare`, and that one is semantic: `loader.deactivateExtension` fires
`on_detach` BETWEEN the halves and that hook may read what is being removed, so the sparse row must
still be there while the table columns still are. `PreparedRemove` therefore carries an OWNED,
in-place-partitioned copy of `cids`, and `commit`/`abort` gained an allocator to free it — one
external caller, three lines in `loader.zig`. A slice into the caller's buffer would work today and
would make the trio's correctness rest on a lifetime precondition no signature states.

### G7 — the mixed-query planner

**The driver is the contract before it is a mechanism, and the oracles are written on that.**
`engine-ecs-internals.md` §2 makes the iteration order **deterministic** (a pure function of world
state), **non invariant** (two states with different populations may visit differently), and **out of
contract** (each matching entity exactly once, in an order a rule must not read). Every oracle here
therefore asserts on the visited **SET** and never on a sequence: a test asserting an order would pin
a property the corpus explicitly refuses, and would then break for the right reason at the first
migration.

**The mandatory case, and the construction that makes its oracle mean something.** Two sparse members
of opposite cardinality: `A` on 3 entities, `B` on 10, so `A` drives; then `A` is padded past `B` and
`B` drives. **The padding carries ONE member only**, so `A ∩ B` never moves — had it carried both,
the test would have measured the matching set and not the driver. The oracle is
`expectEqualSlices(set1, set2)`: the visited set is IDENTICAL whichever member drove, which is what
distinguishes a correct driver from a walk of the wrong member — that walk would still have reported
three entities on the first half and ten on the second.

**A TABLE member may win the election, and the contract says so.** "Le membre de plus petite
population pilote" does not read "the smallest SPARSE member": a one-entity `Boss` beats a
21-entity sparse `Burning`, and the walk is then the archetype walk with the sparse member reached by
membership from the locator. That is why the planner has TWO arms and not one.

**`DynamicQuery` alone gets a sparse exclusion wrong, and the reason is structural rather than a bug
in it.** Its `without_ids` filter is evaluated at ARCHETYPE level, and since G3 a sparse component is
in no archetype's signature — so the exclusion matches nothing to exclude and every candidate
survives. Pinned before the fix, on two entities that share one archetype precisely because the
sparse member routes away, which is what makes the archetype-level answer indistinguishable.
`TableDrivenQuery` applies the sparse half of BOTH sets per entity.

**Two dedup keys on the disjunctive path, and which one is used is decided rather than chosen.** The
k-way merge de-duplicates for free by exploiting each term's ascending-`archetype_id` cache; a
sparse-driven term keeps no cache and has no archetype to order by. So the union switches to an
ENTITY key the moment ONE term is sparse-driven, over a reusable `merge_seen` set held beside
`merge_cursors` for the same reason — the steady state allocates nothing. Tested through the
interpreter on an entity matching BOTH disjuncts: **three visits, not four.**

### G8 — the dense range as a unit of dispatch, and the bound

**The tension the verdict flagged is settled AT THE OPENING and from the code, and the criterion is
not the one it expected.** The brief gives G8 both the split of a sparse-driven query and the bound
*no job body receives a command buffer*, which contradict each other unless the splittable set is
bounded. Measured: `forEachChunk` is declared **ONCE**, on the comptime `Query`; `DynamicQuery` has
none; **the interpreter has no reference to `JobBuilder` or `forEachChunk` at all**; and the seven
call sites are all in `tests/ecs/`, with **ZERO** passing a command buffer.
So **the splittable set is defined by the ITERATION TYPE, not by the body's behaviour.** An Etch rule
body is not splittable because it has no door to the job path — deferred effects or not. The
verdict's expected answer ("bodies that do not structurally mutate") is right about the OUTCOME and
wrong about the CRITERION, which is a stronger result than agreeing: the bound does not depend on
anyone classifying a body correctly.

**The bound is a COMPTIME REFUSAL, not a lint rule, and that is a choice with a reason.** A tokenizer
cannot see a type — it would flag a NAME, carrying a heuristic's false positives and, worse, its
false negatives. `refuseCommandBufferInArgs` inspects the dispatch entry's own `ArgsType` and fails
to compile. Counter-factual run by hand, since `@compileError` cannot be a passing test's subject —
its exact message, with the offending type named and the caller told what to do instead:

```
error: no job body receives a command buffer (M1.B/G8): argument of type
`*ecs.command_buffer.CommandBuffer` reaches a dispatched body. A worker owns its range and
nothing else; two workers recording structural changes would need a deterministic merge,
which has no producer. Record the change outside the dispatch, or dispatch a body that does
not record.
```

The walk is ONE LEVEL deep and that is stated rather than implied: direct and behind-a-pointer are
caught, a buffer buried in a caller's own struct is not, and closing that would cost a recursive
comptime traversal of every field of every argument for a shape no call site has. **And the
asymmetry is named**: `forEachChunk` does NOT carry the refusal, because adding it to a frozen file's
existing method changes what compiles for every caller and no caller needs it — the bound holds there
by measured FACT (0 of 7) rather than by construction.

**The dense range is a unit for the same reason a chunk is, and no other.** Both are index intervals
over storage no other worker touches, which is what makes the split safe WITHOUT a merge step. The
split is even with the remainder over the leading ranges, and its oracle is an interval COVER — every
index marked exactly once — rather than a sum, because a split that double-counted one index and
skipped another passes a sum. An empty driver yields NO range, not one empty range: a range is a unit
of work and an empty one is not one.

**MY OWN TEST FAILED THE VERDICT'S OWN RULE, AND THE COUNTER-FACTUAL IS WHAT SAID SO.** The
structural-effect test was written as "under a SPARSE driver, each matching entity records exactly
once" — and forcing `electDriver` to return `.table` left **every one of its assertions green**. The
reason is structural: with an all-sparse with-set the table-driven arm's archetype filter is EMPTY,
matches every archetype, and the per-entity membership test selects the same entities. The answer is
driver-independent BY DESIGN; only the cost is not. So the test was measuring the answer and not the
driver — the exact defect the verdict warned about for the two-sparse case, arriving in a different
test of the same gate. Repaired by asserting the ELECTION where it is decided
(`interp.rule_descs[0].selection[0]`) and by renaming the test to what it establishes. The
counter-factual now reddens THREE tests including this one; before, it reddened two.

**THE BOUND WAS ON THE WRONG PATH, AND THE REVIEW REFUSED THE GATE FOR IT.** The first version
called `refuseCommandBufferInArgs` at **one** production site — the new sparse-driven entry — and
justified the asymmetry against `Query.forEachChunk` with a count of "0 of 7". Measured at the
refusal: **`forEachChunk` is not a dispatch path at all.** Its body is
`for (matches) |m| for (m.archetype.chunks.items) |chunk| @call(...)` — a double loop on the CALLING
thread, where a command buffer is no hazard because there is no second worker. So the comparison was
against a path that never carried the danger and the denominator was the wrong one. The two entries
that DO dispatch across workers carried nothing: `Query.runChunkAt`, whose own doc says *"used by the
scheduler to dispatch chunks across workers"*, and `JobBuilder.addJob`, whose trampoline the pool
runs. **A guard on one of two points is the shape this milestone names as dominant, and this was the
gate whose deliverable IS the bound.**

Closed by putting the refusal on the TYPE — in `command_buffer.zig`, which owns what is refused —
so all three arg-passing dispatch entries reach it from their own imports rather than one carrying it
alone. The `frozen file` objection does not survive its own measurement, which is what the verdict
pre-empted: **`runChunkAt` has ZERO call sites in the entire repository** and **`addJob`'s
twenty-five mentions pass no command buffer**, so the narrowing breaks nothing that compiles, touches
no public signature, and the G7 surface guard (52 enumerated declarations) verifies that rather than

Both new guards counter-factualled BY HAND, since `@compileError` cannot be a passing test's subject,
and both give the same message naming the offending type:

```

argument of type `*ecs.command_buffer.CommandBuffer` reaches a dispatched body. …
```

**And the `runChunkAt` counter-factual took THREE apparatus forms before it reached its target** —

### G9 — `@requires`: the counter-factual list, written BEFORE the code

*This section is dated to G9's OPENING and is deliberately committed before the
implementation. The G8 lesson is that a counter-factual reddening fewer tests than expected is a
finding, and its corollary — reddening MORE says a test depends on something its name does not — is
only usable if the expected list exists in writing first. What follows is that list. Any gap between
it and the measured result is reported as a finding, in either direction.*

**The question asked of each guard, before its justification is written:** *what is the world state
in which this guard is the only thing preventing a silently wrong answer?* A guard whose state cannot
be named is in the wrong place — the diagnosis that closed G8's asymmetry, applied ahead of the code
rather than after it.

| # | Guard | The state where it is the only thing standing | Its CF must redden |
|---|---|---|---|
| 1 | Cycle refused at type-check | `A requires B`, `B requires A`. Without it the closure either does not terminate or reaches a fixpoint that makes `add(A)` and `add(B)` indistinguishable, coupling every carrier of one to the other with nothing able to undo it | the cycle fixture's diagnostic test |
| 2 | Closure added TRANSACTIONALLY | an allocation failure partway through a 3-deep closure. Without it the entity carries part of its closure — an invariant violation with no diagnostic and no caller able to see it | the failing-allocator sweep |
| 3 | Removing the requirer removes NOTHING | `Mesh requires Transform`, then `remove(Mesh)`. Without it a cascade destroys a `Transform` that may have been added independently, and nothing in the model distinguishes the two provenances | the survival test on `Transform` |

**The refusal channel, established at the file and not chosen from the spec's three options.**
`engine-ecs-internals.md` §3's open point lists refusal-at-type-check-only, frank tick failure, and
runtime-tolerated-with-a-warning, and says the choice comes from the flush's code. The verdict

The channel itself is the `syncIn` precedent, read at

**Expected to be measured, and reported as a measure rather than forced:** the STATIC refusal can
only catch a removal whose program form gives, at one place, both the removal and the requirer's
presence. The type-checker knows the closure GRAPH, not what an entity carries. So static coverage is
expected to be small and the runtime to carry nearly all of it — and if that is what the reading
says, it is rendered as a figure and not corrected by widening the static analysis past what it can
see.

### G10 / B1 — the dense range becomes a unit of DISPATCH, and the split's justification acquires its beneficiary

**Ruled at the G10 verdict: this is G8's undelivered half, and it delivers.** *"Le découpage seul ne
satisfait pas cette phrase. « À parité avec un chunk » veut dire qu'un worker consomme une plage
comme un worker consomme un chunk"* — and the exit was closed by my own measurement: absent, not
impossible, fifteen lines. **The G7 justification form does not cover an absent coverage**, only an
impossible one.

`JobBuilder.addDenseRangeJobs(world, sq, target, Body, args)` stages one job per dense range into
the same builder list `addJob` feeds, which `dispatchBatch` consumes at `ecs/scheduler.zig:648`. No
import cycle materialised — measured by trying it, `hybrid_query.zig` importing no scheduler.

**What "at parity" means was measured before it was implemented**, since it is the frozen word.
`forEachChunk`, `runChunkAt` and `addJob` all call `@call(.auto, Body, .{chunk} ++ args)` with the
same value, so ONE chunk body serves all three. `forEachDenseRange` calls `Body` with a `DenseRange`
**by value**, so the trampoline dereferences the arena record and passes the same value — one range
body serves both range entries. Parity is exact on that property and inexact on one stated point: a
chunk is a heap allocation and IS its own `chunk_ptr`, while a `DenseRange` is two integers with no
storage identity, so the ranges are materialised in the builder's arena, whose lifetime is the level
(`reset` is `.retain_capacity`) — exactly the lifetime `args` already has. Overflow is caught where
`addJob`'s is, at `dispatchBatch`'s `error.TooManyChunks`; staging does not check, and that is parity
rather than an omission.

**`rangeAt`'s comment is corrected in the same commit, as the verdict required.** It justified its
even split by *"the property that keeps a work-stealing scheduler from starving on a tail"* — a
beneficiary that did not exist from G8 until this entry. The note stays at the site because the claim
is only as good as the path that consumes it.

**THE ORACLE IS BUILT TO TELL "REACHED A WORKER" FROM "RAN HERE", and that is the whole difficulty.**
G8 already pins the split, including an interval-cover check that catches a double-count plus a skip.
So a test that merely re-summed the ranges would prove nothing new. Three assertions, and the
measurement that makes the strongest one exact: **`publishWaveAndWait` invokes no trampoline** — it
publishes, wakes and busy-yields — so a body running on the dispatcher's own thread means the wave
was never dispatched. The claim is therefore *no recorded thread id equals the caller's*, exact and
not statistical. Its non-vacuity is a separate assertion — every range's body ran — without which
"no body on the calling thread" is satisfied by no body running at all. And its mirror witness is
that the same-thread entry ran ALL of it on the caller, without which the test could not tell a
dispatched run from a harness that never touches the caller's thread.

**The parity differential is independent of the coverage property, and both counter-factuals prove
it.** Same `Body`, same probe shape, run through both entries, compared element-wise.

| counter-factual | changes | fires on | leaves passing |
|---|---|---|---|
| **CF-a** — stage one job for the whole population | the entry's per-range loop | job count (`expected 5, found 1`) and the second test (`expected 3, found 1`) | — |
| **CF-b** — every job points at `ranges[0]` | the record's payload | the parity differential alone (`01 01 01…` against `05 05 04 04 00…`) | the dispatch and non-vacuity assertions |
| **CF-c** — run the staged jobs inline in the test | the dispatch, not the code | the thread assertion at line 641 | everything else |

So each assertion is shown to discriminate on its own, and CF-b establishes what a differential
alone could not: a `rangeAt` overlapping identically on both paths would pass the differential and
fail G8's cover, while a trampoline passing the wrong value passes G8's cover and fails here.

**CF-b's first form did not run, and reading its exit code would have said it did.** Replacing
`&ranges[i]` with `&ranges[0]` left `i` unused, so the build died on `unused capture` at
`scheduler.zig:380` — a compile error BEFORE the mutation's target, exit 1 either way. Re-formed as
`&ranges[i * 0]`, it fires with **zero compile-error blocks in the log**, which is now the reported
quantity rather than the exit code. Fourth instance this milestone of the rule G8 wrote down.

**AND THE JOB-BOUND CONTROL WAS SHORT BY TWO — found by deriving it instead of appending to it.** It
enumerated FOUR arg-passing entries by hand and said *"3 dispatch across workers and are GUARDED"*.
Derived mechanically — every function in `src/` carrying both `comptime Body: anytype` and
`args: anytype` — the answer is **SIX**: `forEachChunk`, `runChunkAt`, `addJob`,
`forEachDenseRange`, the new `addDenseRangeJobs`, and `jobs.Scheduler.dispatch`, whose directory
G8's sweep did not cover. Four dispatch across workers and **three of those** carry the refusal; the
fourth is B2's subject and its absence is now printed rather than absorbed into a round number. The
predicate is written at the site so the next reader re-derives it in one pass, with the three prior
instances of a hand-kept enumeration coming up short cited beside it — the control moves again in
B2's commit, which is said at the site rather than left to be noticed.

### G9 re-render — the counter's reset had TWO frontiers, and neither covers the other's population

**The finding, Guy's, at the G9 NO-GO.** `requires_removals_skipped` was cleared in
`beginFrame` alone, and `stepOnce` calls `beginFrame` CONDITIONALLY —
`interp.zig:2131` is `if (self.has_changed) world.beginFrame();`, with its own comment
saying a `changed`-free program never advances the tick. So for a program carrying no
`changed` filter anywhere, the counter never reset: the once-per-tick warning fired once
per PROGRAM, and `first_requires_skip` froze on the first skip for the whole run. The
field therefore meant "per tick" or "cumulated over the run" **depending on whether the
program contained, somewhere else entirely, an unrelated `changed` filter**. That is not
a threshold to retune; it is a field with two semantics.

**What chose the remedy was a measurement, not a preference.** Three boundary populations,
read at the files:

| entry point | `beginFrame` | `tickBoundary` |
|---|---|---|
| tree-walker `stepOnce` | `interp.zig:2131`, **conditional** on `has_changed` | `interp.zig:1738`, `5231`, `5327`, unconditional |
| Zig host scheduler | `scheduler.zig:589`, unconditional | — |
| codegen | `lower.zig:6617` | `lower.zig:6678` |

Neither boundary covers the other's population: the scheduler reaches only `beginFrame`,
and a `changed`-free tree-walker program reaches only `tickBoundary`. So the reset is
extracted into `World.resetTickObservations()` and called from **both**, with the
measurement written at each site — the same shape as this gate's two cycle detectors,
where the static walk and the runtime walk each cover a population the other cannot see.
Picking one frontier would have left one population uncovered whichever I picked.

**The test runs on a program without a `changed` filter, and asserts that premise.** The
fixture is `component Transform` / `@requires(Transform) component Mesh` / a rule removing
`Transform` — no `changed` anywhere, so `has_changed` is false and only `tickBoundary`
resets. `try std.testing.expect(!interp.has_changed);` is asserted rather than assumed:
without it the test would pass on a program that DID carry one and would not distinguish
the two regimes, which is exactly the defect caught at G8 by forcing `electDriver`.

**Counter-factual.** Removing the `tickBoundary` reset reddens it at the FIRST boundary
read — `expected 0, found 1` — with the production warning visible in the log above the
