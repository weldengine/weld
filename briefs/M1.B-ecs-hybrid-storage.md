## Context

`ARCH-005` posits archetype storage in SoA as the default and a second, opt-in `SparseSetStorage` mode for components whose add/remove frequency makes archetype migration the dominant cost. **The second mode does not exist.** `@storage` is recognised by the parser and its applicability to `component` declarations is validated; its *value* is read nowhere, so an annotated component is stored in a table like every other one, without a diagnostic. `@requires` is in the same state: recognised, validated for applicability, applied by no code — which is not a missing optimisation but a silent functional bug, since the required component is never added and the rule that assumes it simply does not match.

This milestone delivers the second storage mode, the mixed-query planner, the job split of dense ranges, and `@requires`. It runs **before M1.A** and the ordering is constrained at both ends: M1.A.0 creates the comptime view where the declared access set parameterises the context, under the written requirement that the view compile to the same pointer arithmetic as a direct access. A sparse access is an indirection. Delivered after M1.A, the second mode forces re-typing that view for two access modes and re-running the disassembly counter-proof; delivered before, the view is born with both, once.

## Scope

**Front-end — `@storage` consumed.**

- The storage mode of every component is recorded in the runtime registry at registration, sourced from the resolved annotation; absence of `@storage` yields `table`.
- `@storage` with a value outside the `StorageKind` domain is refused with `E0503`; a syntactically valid but non-constant argument is refused with `E0504`. The domain is `table | sparse` and is owned by `engine-ecs-internals.md` §2 — the resolver validates against it and does not define it.
- An invalid-corpus fixture exercises the refusal. Without it, `E0503` is activated with no witness that anything is refused.

**Backend — `SparseSetStorage`.**

- Dense entity array, a component array parallel to it, a sparse index keyed by entity index with a reserved absence marker, and `added_ticks` / `changed_ticks` parallel to dense. Add and remove in O(1) by swap-remove.
- The seven backend invariants of `engine-ecs-internals.md` §2 (*Invariants du backend sparse*) hold and are each asserted independently: swap-remove parity of the tick sidecars, absence of a per-block skip, despawn across all storages, observer firing order over the union, zero-sized components, entity generation, OOM rollback.

**Routing — the resolution funnel.**

- The four Tier-0 entry points that resolve an `(entity, component)` pair to bytes route by mode: typed read, typed mutable read (with its auto-mark), dynamic byte read, and the dynamic change stamp.
- The Etch component handle — today a chunk pointer plus a slot — becomes able to designate a sparse row. This is the type M1.A.0 will parameterise; it is bimodal here or twice there.
- Every structural mutator routes by mode: the three spawn paths, the typed and dynamic add paths, the batched add, the single and batched remove paths, the prepared-remove trio, the tag mutation path, despawn, and the frame boundary.
- Both command-buffer apply paths carry the routing. There are two switches over the same six command kinds — the observer-dispatching apply and the raw apply that drains the deferred buffer. A change landing in one and not the other is the dominant defect shape of this milestone.
- Observer dispatch: the despawn enumeration covers the union of table and sparse components, add-on-present detection no longer relies on archetype membership alone, and the per-component `on_add` firing at spawn covers both storages.
- Scene and prefab load: an Archetype Block becomes a serialisation group by logical signature. Table components determine the runtime archetype; sparse columns feed their own storage. The bifurcation is entirely inside the spawn path — the codec is not reopened, no cooked scene is invalidated, and changing a component's mode requires no re-cook.

**Mixed-query planner.**

- A query combining both storages elects exactly one driver — the member of smallest population, ties broken by declaration order in the query — and reaches the other members by O(1) membership test. A query whose members are all table iterates archetypes exactly as today.
- `not has T` on a sparse `T` ceases to be an archetype-level filter and becomes a per-entity membership test. The disjunctive path, which today de-duplicates by ascending archetype id, de-duplicates by entity when a term is sparse-driven.
- The per-slot guards of the interpreter — field filter, tag predicate, change filter, expression guard — take a storage-agnostic locator instead of an archetype-chunk-slot triple.
- **The mixed iteration is a new type. The frozen surfaces are not modified.** `WELD_ECS_PROTOCOL_VERSION` stays at 1, and the milestone proves it rather than asserting it.

**Scheduler.**

- The dispatch consumes a range of the dense array as a unit of work at parity with an archetype chunk, including work stealing.
- The bound that makes the split safe: no job body receives a command buffer. This is a bound to establish, not a merge mechanism to invent — no call site passes one today, and nothing in the current types forbids it.

**`@requires`.**

- The annotation is **variadic**. Transitive closure computed once at resolution, never re-walked per add.
- A cycle is a resolution error, not a fixed point.
- The whole closure is added in one transaction, or none of it. Applies identically to a spawn carrying a component with a non-empty closure, and to both storage modes.
- Removing the requirer removes nothing else. Removing a still-required component is refused **at type-check** wherever the shape of the program allows the refusal to be static; what static analysis cannot see is tolerated at runtime with a warning. A deferred command turned into an unobservable tick failure is not an acceptable refusal channel.

**Codegen.**

- The Zig codegen prototype **explicitly refuses** any program exercising a sparse component, until Phase 2-3 parity. No silent table fallback.

**Bench.**

- A crossover bench that measures, on the validation configurations, where the sparse mode becomes profitable against the table mode. This bench produces the thresholds; no document grades them.

## Out of scope

- **Enableable components.** The third path was examined and rejected; nothing here reopens it.
- **An `Added<T>` filter.** The `added_tick` sidecar exists and is propagated across migrations, and no filter reads it — at comptime, in the interpreter, or in codegen. Adding a consumer is not this milestone's business, and the milestone must not add one incidentally while making the change filter storage-agnostic.
- **Bumping `WELD_ECS_PROTOCOL_VERSION`.** If the work appears to require it, that is a blocker and a return to Claude.ai, not a decision to take mid-milestone.
- **Changing a component's storage mode at runtime.** The mode is a property of the declaration.
- **Codegen parity on sparse programs.** Refusal is the deliverable; parity is Phase 2-3.

## Acceptance criteria

### Tests

Each entry names the property, not the scene. The scene belongs to whoever has the compile loop.

- **`@storage` value is refused outside the domain** — a component annotated with a value that is not in `StorageKind` produces `E0503`, and the diagnostic names the offending value. The fixture pins the expected code in the facade, as every fixture of that directory does. Counter-factual: widening the accepted set makes the test red.
- **`@storage` non-constant argument produces `E0504`**, and the two fixtures are distinguished by their pinned codes rather than by both merely failing.
- **The registry records the mode** — a component declared with the sparse mode is reported sparse by the registry, and one declared without `@storage` is reported table. This is the test that would have failed for the four months during which the annotation was a no-op.
- **Swap-remove parity** — removing an entry that is not the last one relocates the trailing entry, and its `added_tick` / `changed_tick` travel with it. A change filter must see a relocated entity exactly as it would have seen it un-relocated.
- **Despawn purges every storage** — after despawning, no sparse index entry designates the dead entity, and re-spawning at the same entity index with a new generation does not inherit the dead entity's component.
- **Zero-sized sparse component** — a sparse tag is added, tested, and removed with no component array allocated and no pointer derived from one.
- **OOM rollback** — an allocation failure on the sparse add path leaves the world exactly as before the add. The induced failure must be one-shot: an allocator that fails once and then recovers, so the assertion after the failure distinguishes the property from exhaustion.
- **Observer firing order at despawn** — the `on_remove` callbacks fire in ascending component id over the union of table and sparse components. Counter-factual: permuting the declaration order of the components does not change the firing order.
- **Add-on-present on a sparse component** fires the replacement observer, not the add observer.
- **Both apply paths route** — the property is asserted on the observer-dispatching apply *and* on the raw apply that drains the deferred buffer, with a check that enumerates the command kinds covered on each. A test covering one path only is the defect this entry exists to prevent.
- **Mixed query, two sparse members of opposite cardinality** — the driver is the smaller one, every matching entity is visited exactly once, and the visited set is identical whichever member is smaller. This is the case neither of the two previous conflicting rules covered.
- **Mixed query, equal cardinality** — declaration order decides, and the decision is stable across runs.
- **All-table query is unchanged** — the iteration path taken by a query with no sparse member is the one delivered today, and a check states which path was taken rather than inferring it from the result.
- **`not has T` on a sparse `T`** excludes the right entities, and the exclusion is per entity rather than per archetype.
- **Disjunctive selection with a sparse-driven term** dispatches each matching entity exactly once.
- **Frozen surfaces intact** — no existing signature of the frozen ECS files changed, and `WELD_ECS_PROTOCOL_VERSION` is still 1. The check enumerates the surface it inspected and reports its size.
- **Dense range dispatch at parity** — a sparse-driven query splits across workers with the same work-stealing behaviour as an archetype-chunk query, and the split covers every entry exactly once.
- **No job body receives a command buffer** — the bound is checked over the whole set of dispatch call sites, and the check reports how many it inspected.
- **`@requires` adds the transitive closure** in one transaction; a failure part-way leaves the entity as it was.
- **`@requires` cycle is refused** at resolution with a diagnostic naming the cycle.
- **Removing the requirer keeps the required component.**
- **Removing a still-required component is refused** at type-check where the shape allows it, and produces a warning rather than a tick failure where it does not.
- **Codegen refuses a sparse program** explicitly, with a diagnostic naming the construct. Counter-factual: a program with no sparse component still compiles.
- **The differential corpus reader is storage-agnostic** — the final-state comparison reads a component regardless of its storage mode, instead of failing on archetype membership.

## Notes

**The first gate writes the contract, and the site list it writes from is below.** M1.1.15.2 specified the physics authority regime at the same time as it implemented it: the contract named three paths, the delivered behaviour traversed nine, and the last six were found one per external review pass. The site list for hybrid storage was produced by reading the repository at `3fd5472`, and it is given here so that the contract can be written from it rather than discovered through it. The reading being done does not make it complete — a path this list misses is a finding, and finding one is expected.

**Three contract shapes, each measured on M1.1.15.2.** Quantify rather than enumerate when a rule must cover future sites — *any site that does X must do Y, and failing to is a defect of that site*. State what does **not** move as much as what does: a matrix silent on a stable state is what the implementer fills with the available fact, and the available fact was the wrong one. Name what a rule does **not** cover, and why, when it could be read wider than its domain — a correct enumeration does not make a correct rule.

**A guard has two ways of being wrong** — missing what it should catch, and catching what it should let through. The second is proved by a counter-factual that *widens* the guard: if the widening reddens nothing, the boundary is not guarded. And a counter-factual that does not fire proves nothing about the guard being useless; it proves the scene does not reach it. If a first scene does not suffice, ask *why* before trying a second.

**The freeze is on the path, and the chosen exit is the new type.** `query.zig`, `world.zig` and `root.zig` carry the C0.5 `FROZEN` marker and the ECS protocol constant is 1. C0.5 freezes the interface contract explicitly while allowing the implementation behind it to evolve, so routing an existing read through a second backend is implementation. What would genuinely break is the chunk-based dispatch protocol, since a sparse-driven query has no chunk — hence a distinct iteration type rather than a second mode of the existing one. The tail-rescan helper is already a module-scope function shared by both existing query types, so a third caller costs a call and not a copy.

**Two Etch corpora, and the codegen refusal touches neither existing fixture.** The parse-and-type-check corpus and the differential corpus have separate facades. The existing annotated fixture, which today consecrates the `@storage` no-op as a valid case, lives in the first and never reaches codegen; it stays valid, because the annotation becomes genuinely valid. What it lacks is its invalid twin.

**The `.sav` and `.scene.bin` schema identity is blind to a constant-size field change**, and this is a class of silent corruption independent of this milestone. Nothing here should add a field inside existing padding without treating it as an event.

**What is decided and not to be re-litigated:** the driver is cardinality, ties broken by declaration order; iteration order is deterministic, non-invariant and out of contract; the storage mode is a runtime registry property and never on-disk identity; the codec is not reopened; `@requires` refusal is static where possible and a warning where not.

**What is open and is a stop, not a judgement call:** any path this brief's site list does not cover; any requirement to change a frozen signature or the protocol constant; any case where the refusal channel for a `@requires` removal cannot be made static *and* cannot be made a warning.
