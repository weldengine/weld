## Context

M0.3 extends the Tier 0 platform layer shipped minimally in S2 (Win32 + Wayland with a 5-method `Window` interface) toward the full surface expected by C0.7 and by the M0.4 (Vulkan Renderer) and M0.6 (IPC) milestones that depend on it: extended `Window` interface (raw input, focus, minimize/restore, multi-monitor), Win32 thread safety for the window-class globals, `fs`/`time`/`threading`/`dynamic loader` platform layer, minimal Tier 0 input system (`@transient` `InputRawState` resource + raw event queue), and an Audio Dummy stub to unblock the headless CI tests ahead of the real audio backends in Phase 1. M0.3 advances C0.7 and closes it after the spec patches already applied pre-conversation (D-S2-x11 closed as abandoned — Weld Linux = native Wayland only Phase 0+).

## Scope

- **Extended `Window` interface** beyond the 5 minimal S2 methods (debt **D-S2-window-iface**). Added surface:
  - Keyboard events (key down/up, normalized physical scancode `KeyCode` enum common to both backends; no IME, no layout-aware XKB keymap — postponed Phase 1+).
  - Mouse events (absolute motion + delta, button down/up, horizontal + vertical wheel).
  - Gamepad state + events (max 4 slots, connect/disconnect, buttons, raw `[-1, 1]` sticks, raw `[0, 1]` triggers — no deadzone at this level).
  - Window lifecycle events (`focus_gained`, `focus_lost`, `minimize`, `restore`).
  - Multi-monitor: `enumerateMonitors`, `currentMonitor(window)`, per-monitor DPI with tracking on current-monitor change.
  - Per-monitor HiDPI / fractional scaling: extension of the existing S2 support (`wp_fractional_scale_v1` Wayland, `WM_DPICHANGED` + `GetDpiForMonitor` Win32) to track DPI per monitor instead of process-global DPI.

- **Win32 thread safety for the window-class globals** (debt **D-S2-win32-globals**). Migration of the 3 globals `class_atom`, `class_open_count`, `dpi_awareness_set` from unprotected `var` to atomic accesses. Mandatory pattern:
  - `class_atom`: once-init pattern via manual tri-state CAS on `std.atomic.Value(u32)` (`0=not_started`, `1=in_progress`, `2=done`). Concurrent threads in state `1` wait via `std.Io.futexWaitUncancelable` or bounded busy-yield. Document the manual-CAS choice in a comment (the absence of a dedicated `std.once` in Zig 0.16.x is to be verified at session start — if the primitive exists, prefer it to manual CAS).
  - `class_open_count`: refcount via `std.atomic.Value(u32)` with `fetchAdd`/`fetchSub` (acq_rel). Not a once-init.
  - `dpi_awareness_set`: once-init pattern identical to `class_atom`.

- **`fs` / `time` / `threading` / `dynamic loader` platform layer** (new deliverables, unblocks M0.4 + M0.6).
  - **fs**: `std.Io.File` propagated as-is for low-level operations. Weld adds a **VFS resolver** that decodes a scheme-prefixed path (`assets://...`) into a usable `(std.fs.Dir, relative_path)` pair. List of schemes to support in M0.3: `assets://` (resolves to `${project_root}/assets/`), `cache://` (to `${project_root}/.weld_cache/`), `user://` (to the OS-standard user directory: `%APPDATA%/Weld/<project>/` on Win32, `$XDG_DATA_HOME/weld/<project>/` or `~/.local/share/weld/<project>/` on Linux). Weld also adds an `mmapFile` helper (Win32 `CreateFileMapping`+`MapViewOfFile`, POSIX `std.posix.mmap`) since `std.Io` does not expose mmap and it is required for zero-copy cooked assets.
  - **time**: `std.time.Instant` propagated as-is for the monotonic clock. Weld adds a `sleepPrecise(ns)` wrapper that calls `timeBeginPeriod(1)` once on Win32 (once-init pattern shared with those above) then `std.time.sleep`; on Linux, a direct alias to `std.time.sleep` (already precise via nanosleep).
  - **threading**: `std.Thread`, `std.atomic`, `std.Io.Mutex`/`Condition`/`Semaphore`/`ResetEvent` propagated as-is (cf. `engine-zig-conventions.md` §11). Weld adds two OS-specific helpers: `setAffinity(thread, core_id)` (Win32 `SetThreadAffinityMask`, Linux `pthread_setaffinity_np`) and `setPriority(thread, .high/.normal/.low)` (Win32 `SetThreadPriority`, Linux `pthread_setschedparam`).
  - **dynamic loader**: unified `DynamicLib` surface with operations `open(path)`, `lookup(symbol)`, `close()`. Win32 backends (`LoadLibraryW` + `GetProcAddress` + `FreeLibrary`) and POSIX (`dlopen` + `dlsym` + `dlclose`). Consistent with the `engine-c-bindings.md` §4.6 per-strategy dlopen pattern.

- **Minimal Tier 0 input system**. `@transient` `InputRawState` resource (per-frame snapshot), fed by the Win32/Wayland/evdev/XInput events collected by the Window backend. Resource format:
  - `KeyboardState`: `pressed` bitset (256 scancodes), `pressed_this_frame` and `released_this_frame` bitsets (transitions this frame).
  - `MouseState`: `position` (client-area coords), `delta` (since previous frame), `wheel` (horizontal + vertical), `buttons` bitsets (8) + `_this_frame`.
  - `GamepadState[4]`: `connected`, `buttons` bitsets (32) + `_this_frame`, `sticks[2][2]` (L_x/y, R_x/y) raw `[-1, 1]` without deadzone, `triggers[2]` (L, R) raw `[0, 1]`.
  - Feed sources:
    - Win32: `WM_KEYDOWN/UP` (scancode via LParam bits 16-23), `WM_MOUSEMOVE`, `WM_LBUTTONDOWN/UP` and variants, `WM_MOUSEWHEEL` + `WM_MOUSEHWHEEL`, `WM_INPUT` (Raw Input API for high-frequency mouse delta), `XInputGetState` polled each frame for the 4 gamepad slots.
    - Wayland: `wl_keyboard.key`, `wl_pointer.motion/button/axis`, non-blocking read of `/dev/input/eventN` for gamepad (integrated into the mainloop via `std.posix.poll` on the Wayland + evdev fds). Gamepad hot-plug via periodic polling of `/dev/input/` every N seconds (udev monitoring postponed Phase 1+ if polling suffices).
  - No X11 source (cf. pre-conversation decision D-S2-x11 abandoned).
  - Clean boundary toward the Tier 1 Input Module (Phase 1): `InputRawState` is a public ECS resource consumed by the future Tier 1 Input module that will derive the `Action<T>` according to the active `input_mapping`. M0.3 does not invent an intermediate hook; the stable interface is the resource itself.

- **Audio Dummy stub**: no-op implementation of the Tier 0 `AudioModule` interface (cf. `engine-tier-interfaces.md` §2), registered as the default Phase 0 backend. Clean `init`/`deinit`, `play_sound` returns a valid dummy `VoiceId`, other operations return neutral values. No real audio state. Unblocks the headless CI tests for the modules that will consume audio Phase 1+. Consistent with `engine-audio-pulse.md` §1.1 (Dummy = backend #1 in writing order, ~50 lines).

## Out-of-scope

- **X11 backend**: definitively abandoned (cf. pre-conversation decision, debt D-S2-x11 closed. Spec patches applied pre-brief). `src/core/platform/window/stub.zig` X11 kept on `error.UnsupportedPlatform`. No `xcb_gen` generator, no xcb lib dlopen, no X11 tests.
- **macOS backend**: Phase 2. `src/core/platform/window/stub.zig` Darwin continues to return `error.UnsupportedPlatform`.
- **Complete Tier 1 Input Module** (Phase 1): `input_mapping`, typed actions (`trigger`/`bool`/`float`/`Vec2`/`Vec3`), modifiers (`deadzone`, `sensitivity`, `invert_y`, etc.), triggers (`on_press`, `on_hold`, etc.), activatable contexts, combos, runtime rebinding, haptic feedback, programmatic injection. M0.3 ships only the raw Tier 0.
- **Touch screen**: no mobile target Phase 0. No `wl_touch`, no `WM_POINTER` touch. Postponed Phase 2.
- **IME (Input Method Editor)**: composition events, candidate windows. Enormous complexity, not required Phase 0. Postponed Phase 2+.
- **Layout-aware XKB keymap**: M0.3 maps physical scancodes to a normalized `KeyCode` enum (implicit US layout). Layout-aware text input (required by Islandz) waits for Phase 1+.
- **Suspend / Resume**: mobile lifecycle (app in background). Postponed Phase 2.
- **Real audio backends** (WASAPI, PipeWire, PulseAudio, ALSA, CoreAudio): Phase 1 (cf. `engine-phase-1-criteria.md` C1.3 and `engine-audio-pulse.md` §1.1).
- **Network sockets**: Phase 2 (Relay); the IPC sockets are already covered by M0.6.
- **Complete process spawn / pipes**: covered by M0.6 (editor launches runtime). No duplication here.
- **Power, Accessibility**: Phase 2+.
- **Dedicated virtual memory allocation** beyond `mmap`: no concrete need identified Phase 0. Postponed Phase 1+ if a need emerges.
- **udev monitoring for Linux gamepad hot-plug**: replaced by periodic `/dev/input/` polling in M0.3. Native udev Phase 1+ if polling proves insufficient.
- **Clipboard, drag-and-drop**: Phase 1+ (Islandz need). Out of C0.7.

**Linux gamepad hot-plug — polling vs udev choice**: the M0.3 position is **periodic polling** of `/dev/input/` (interval ~1s, configurable). Justification: udev integration would require a netlink socket + udev event parsing + a dedicated loop — a cost > 200 lines for a rare use case (connecting/disconnecting a gamepad during play). If during the session polling proves insufficient (latency too high for the use case), Claude.ai conversation round-trip to switch to native udev (explicit re-scope).

**Wayland `callconv(.c)` callbacks**: the S2 hypothesis that Zig `callconv(.c)` is ABI-interchangeable with the C compiler at the Wayland call sites was validated in S2. M0.3 reuses this pattern for the new `wl_keyboard`, `wl_pointer`, `wl_seat`, `wl_output` callbacks. If a regression appears, the fallback documented in S2 = a `src/core/platform/window/wayland_callbacks.c` file compiled by `build.zig` — not to be implemented in spec here, to be activated only on a concrete blocker.

**Mandatory `Uncancelable` variants** (cf. `engine-zig-conventions.md` §11): every `std.Io.Mutex.lock`, `Condition.wait`, `futexWait` used in the M0.3 platform layer must use the `Uncancelable` variant. The platform layer is pure intra-process code — cancellation from the outside makes no sense. Includes the waits in the tri-state once-init pattern.

**No `threadlocal` variables**: the Phase 0.1 ECS scheduler (M0.1) set the pattern "context passed via the job system, no hidden TLS". M0.3 must respect this pattern — no `threadlocal var` in the platform layer except on absolute necessity (errno via libc as a documented exception).

## Closing notes

*To be filled in at the Status → CLOSED transition, just before opening the PR.*

- **What worked**:
  - 15 commits structured into 8 waves, each wave compile+test green before the next. Fine granularity (on average ~270 lines/commit) easing review and future bisect.
  - Systematic cross-compile to the non-native target (Windows via `-Dtarget=x86_64-windows-gnu`, Linux via `-Dtarget=x86_64-linux-gnu`) to validate the platform backends that native `zig build` does not touch. Identified and fixed: `std.posix.fstat` absent in 0.16 (→ lseek), `std.posix.close` absent (→ `std.c.close`), `pthread_t` opaque pointer vs usize, `std.fs.cwd` absent (→ `std.Io.Dir.cwd`).
  - Once.callBusyYield pattern introduced to avoid propagating `io` to the `Window.create` call site — a pragmatic decision on 3 once-init (class_atom, dpi_awareness_set, timeBeginPeriod) whose window contention is microsecond-scale.
  - Discovery that the 4 targeted Wayland protocols (wl_seat/keyboard/pointer/output) were already emitted by the M0.2 bindgen → Task #3 effectively no-op, ~500-1500 generated lines saved.

- **What deviated from the original spec**:
  - **Brief line estimate: 1800-2100. Actually shipped: 4049 lines** (+) — a factor 2× above target. Consistent with Guy's verbal decision 2026-05-25 to disable the reactive split (cf. § Acted deviations). The overrun comes mainly from: (a) the full surface of raw_state.zig + tests + win32_xinput + linux_evdev (>800 lines) where the brief underestimated the OS-specific glue; (b) the Win32 backend events (235 lines) + Wayland backend events (525 lines) more complete than the minimum requested; (c) the KeyCode enum with the full Win32 + evdev mapping table (~360 lines after `zig fmt` one-enum-per-line).
