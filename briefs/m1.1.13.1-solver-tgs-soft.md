## Context

The rigid contact solver moves from the big-step Sequential Impulses + NGS pair (M1.1.6–M1.1.7) to TGS Soft substepping — soft constraints + per-substep relax, restitution as a dedicated pass — per the decision in `engine-physics-forge.md` §1.6 and the rewritten normative model in `engine-physics-solver.md` §1.7. The reference implementation is pinned: `erincatto/box2d @ 56edae79f2949d86142b03450d5d60f63bcf5a6f` (main snapshot, project version 3.2.0 — no official v3.2.0 tag exists; latest release tag is v3.1.1). This milestone runs before M1.1.14 so cross-platform determinism validates the definitive solver exactly once. The E0 recon findings against the pinned source are frozen in the Notes below; the §1.7 recon markers are re-frozen in the KB at closure.

## Scope

- One substepped contact solver in `rigid/solver.zig` executing normative cycle step 6 and step 7: per substep — `integrateVelocities(h)` (tick accelerations + gravity + damping, `h = dt / substep_count`) → warm-start application → biased solve (normal points only) → `integratePositions(h)` → relax (normal points unbiased + friction); after the loop — restitution pass, then `storeContacts` (step 9). Exactly 1 biased sweep and 1 relax sweep per substep (compile-time constants, no config knobs).
- Warm start split into two named operations: cache seeding once per tick at `prepare` (cache lookup, world-tangent reprojection then clamp to `μ·λₙ`, hit/miss telemetry, `total_normal_impulse := 0`), and accumulator application every substep (current live `λₙ`, `λ_t1`, `λ_t2` values, including growth from earlier substeps of the same tick).
- `contact_constraint.zig` `prepare` extended: soft coefficients (`b2MakeSoft` form) from `(effective_hertz, contact_damping_ratio, h)`, effective-hertz clamp `min(contact_hertz, 0.125 · substep_count / dt)`, static-contact stiffening (2× hertz when either body is static — static only), per-point `total_normal_impulse` bookkeeping, cache seeding absorbed from the deleted `velocity_solver.warmStart`.
- `SolverConfig` rewritten: `substep_count = 4` (≥ 1 by type and assertion; 1 legal as degenerate big-step for A/B; 0 asserts), `contact_hertz = 30.0`, `contact_damping_ratio = 10.0`, `contact_push_max_speed = 3.0`, `restitution_threshold = 1.0` (unchanged), `penetration_slop = 0.005` (unchanged, consumed as dead-zone offset — see Notes N2). Removed: `velocity_iterations`, `position_iterations`, `max_penetration_correction`, `position_correction_factor`. Validation: all `Real` fields finite; `contact_hertz > 0`; `contact_damping_ratio ≥ 0`; `contact_push_max_speed ≥ 0`; `restitution_threshold ≥ 0`; `penetration_slop ≥ 0`.
- Restitution as a dedicated post-loop pass, per island: apply iff `v_n⁻ ≤ −restitution_threshold` AND `total_normal_impulse ≠ 0` (see Notes N6).
- NGS position pass removed: `position_solver.zig` deleted; no position authority inside the loop; penetration recovery paced by `contact_push_max_speed` only.
- Island lockstep preserved: solve, relax, warm-start application and restitution remain range-shaped `[from, to)` entries, one call per island interval per stage per substep; islands advance in lockstep. Telemetry sister entry reports substeps executed, solve/relax sweeps, minimum observed separation (§1.8.2, `get_solver_iterations_stats` surface).
- Test migration RED-first: solver oracles rewritten against the new model; the five-box stack at `substep_count = 4` replaces the 16-iteration floor; rest overlap re-measured and recorded for the closure KB patch (§1.7.2, replaces the SUPERSEDED `5.9e-7`).

## Notes

**N1 — Pinned reference and per-substep order (read on source, never deduced).** `erincatto/box2d @ 56edae79f2949d86142b03450d5d60f63bcf5a6f`. Per substep (`src/solver.c`, substep loop): integrate velocities (gravity + forces + damping, per substep with `h`) → warm-start application → biased solve (`useBias = true`, 1 sweep) → integrate positions (`h`) → relax (`useBias = false`, 1 sweep). After all substeps: restitution, then store impulses. Warm start is inside the loop, every substep, after velocity integration.

**N2 — Normal solve math (per point).** Separation `s` is re-derived each substep from the local anchors at the current poses against the frozen world normal (§1.7.1 anchors model). Three branches:

```
if s > 0:                                   # speculative — active in solve AND relax
    velocity_bias = s / h
    mass_scale    = 1
    impulse_scale = 0
else if biased pass (solve):
    error         = min(s + penetration_slop, 0)        # WELD DIVERGENCE: slop dead zone
    velocity_bias = max(softness.mass_scale * softness.bias_rate * error,
                        -contact_push_max_speed)
    mass_scale    = softness.mass_scale
    impulse_scale = softness.impulse_scale
else (relax, s <= 0):
    velocity_bias = 0 ; mass_scale = 1 ; impulse_scale = 0

delta = -normal_mass * (mass_scale * v_n + velocity_bias) - impulse_scale * lambda_n
lambda_n_new = max(lambda_n + delta, 0)                  # accumulated clamp: push, never pull
applied = lambda_n_new - lambda_n
total_normal_impulse += applied                          # algebraic, post-clamp
```

The source uses raw `s` (no dead zone); the `min(s + penetration_slop, 0)` offset is a documented Weld divergence: it preserves the frozen role of the 5 mm slop — a stationary overlap that keeps manifold and warm-start cache persistent — which the source obtains instead from speculative manifold margins (`4·slop`), out of scope here. Setting the offset to 0 restores exact source parity the day speculative contacts land. `mass_scale`/`impulse_scale` still apply throughout the dead zone (only the bias term is zeroed). Note the clamp floor sits outside `mass_scale` in the source form: the effective recovery cap is exactly `contact_push_max_speed`.

**N3 — Soft coefficients, clamp, static stiffening.** Once per tick at `prepare` (per-shape overrides do not exist in Weld):

```
f_eff = min(contact_hertz, 0.125 * substep_count / dt)   # 30 Hz exactly at 60 Hz × 4
omega = 2π·f_eff ; a1 = 2ζ + h·omega ; a2 = h·omega·a1 ; a3 = 1/(1 + a2)
bias_rate = omega/a1 ; mass_scale = a2·a3 ; impulse_scale = a3
static side present (either body_type == static): coefficients from (2·f_eff, ζ, h)
```

Kinematic bodies receive ordinary softness — source parity (the source keys on "no solver body", which only static bodies lack). `contact_hertz > 0` is validated, so the source's zero-hertz branch is unreachable and not ported. A/B gotcha: at `substep_count = 1` and 60 Hz, `f_eff = 7.5 Hz` — visibly soft contacts are the expected behavior of the lever, not a defect.

**N4 — Warm start: two operations, one hazard.** Seeding (once per tick, at `prepare`, absorbing the deleted `velocity_solver.warmStart`): cache lookup by full key, binary search point by point; world-space tangent impulse reprojected onto the new tangent plane THEN clamped to `μ·λₙ` (reproject before clamp, never the reverse); hit/miss telemetry counted here and only here; `total_normal_impulse := 0`. Application (every substep, immediately after `integrateVelocities`): inject `P = λₙ·n̂ + λ_t1·t̂1 + λ_t2·t̂2` from the CURRENT accumulators — including growth from earlier substeps — and add `λₙ` (current) to `total_normal_impulse`. HAZARD: re-calling a seeding-style function per substep would re-read the cache, reset `λ` to last-frame values and multiply hit/miss counters. The two operations must be distinct functions.

**N5 — Friction: relax-only, normals-first, mechanics unchanged.** In the pinned source, friction (and rolling resistance) runs only in the relax pass, after all normal points of the constraint. Ported as-is: biased solve = normal points only; relax = all normal points (unbiased), then all friction points. This is a measurable scheduling change (Gauss-Seidel points are coupled through body velocities), hence the revalidation entries in Acceptance. Weld's 3D friction mechanics are unchanged: two independent tangent axes driven to zero, circular clamp `‖(λ_t1, λ_t2)‖ ≤ μ·λₙ` against the point's CURRENT accumulated normal impulse, vector rescale never per-axis, no friction bias. The M1.1.7 "normal-first" divergence note retires at closure: the pinned source is normal-first too.

**N6 — Restitution pass (step 7, per island, once after the loop).**

```
apply iff  v_n_pre <= -restitution_threshold  AND  total_normal_impulse != 0
delta = -normal_mass * (v_n + e * v_n_pre)
lambda_n accumulate + clamp >= 0 ; total_normal_impulse += applied delta
```

`v_n_pre` (= `v_n⁻`) is captured at `prepare`, pre-gravity (source parity: the source captures `relativeVelocity` in prepare, before the first in-loop velocity integration). The `<=` follows the source and the closed-interval family convention; it supersedes §1.7.2's strict `<` wording at closure. `total_normal_impulse` is exactly: 0 at prepare; `+= λₙ` (current) at each per-substep warm application; `+= applied` (algebraic, post-clamp) at each solve/relax/restitution update. It is neither the final `λₙ` nor a boolean, and it is not stored to the cache (format frozen). `storeContacts` (step 9) runs after restitution, so cached impulses include the restitution correction — source parity.

**N7 — Frozen-at-prepare vs re-derived.** Jacobian arms `r_a`/`r_b`, world inverse inertias, effective masses (normal + both tangent axes) and the tangent basis are computed at `prepare` and frozen for the tick — source parity. Only the separation scalar is re-derived per substep, from local anchors at current poses (§1.7.1; worldspace noise class `floatEps(Real)·|x|` documented there; the f64 comptime flag is the escape hatch — the source's delta-tracking scheme is NOT ported). Do not "improve" by re-rotating Jacobian arms per substep: arms and frozen effective masses must stay consistent.

**N8 — Suites outside the solver.** Expected green with zero re-baseline: sleep/island wake-envelope tests assert clause bounds denominated in `penetration_slop`, which the dead zone preserves at the same order. If an exact-value SI+NGS transient baseline is discovered inside them, it joins the migration set with an execution-log entry (fix-as-you-go); it does not widen the envelope.

**N9 — Closure KB patches (produced by Claude.ai at closure; inputs = LIVING measurements).** §1.7 step 6 reworded: seed once at prepare, apply accumulators every substep (replaces "first substep only"); §1.7.1 solve formulas re-frozen per N2 (mass_scale inside the clamp; dead-zone divergence noted), clamp `0.125 · substep rate`, static 2× re-worded static-only, config table gains the `penetration_slop` row, five-box measured values re-recorded; §1.7.2 predicate `<=` + `total_normal_impulse` definition + re-measured rest overlap (replaces `5.9e-7` SUPERSEDED); `engine-physics-forge.md` §1.6 sweep count corrected `2n+1 → 3n+1` (13 at defaults, of which n are pure applications); M1.1.7 friction-order divergence note retired; §1.7 steps 3/6 rewording — step 3 is read-only (the accumulators, constant during `step()`, ARE the tick accelerations); the uniform reset runs once at the end of step 6, after the last substep, before step 7. Abort rule: if the acceptance gates fail, the branch is abandoned — the big-step solver stays, `main` untouched.

### B1 — `integrateVelocities` cannot be called once per substep as it stands: the force accumulator would deliver `1/substep_count` of its impulse

**Opened 2026-08-12, Gate B, before any implementation line.**

Scope says the substep loop calls `integrateVelocities(h)`, and the file list says
`pipeline/integration.zig` is untouched with "function bodies unchanged". Those two cannot both
hold, and the reason is arithmetic rather than stylistic.

`integrateVelocities` fuses three operations: it READS the force/torque accumulators, APPLIES them,
and CLEARS them (`integration.zig:91` reads `forces[i]`, `:109-110` zero both columns for every live
body). Called `n` times per tick with `h = dt/n`:

- **gravity** is applied `n` times over `h` ⇒ total `g·dt`, which is exactly what §1.7 step 3 asks
  for — a constant force over the tick delivers the same total impulse, applied in `substep_count`
  slices;
- **damping** becomes `(1 − d·h)^n` instead of `(1 − d·dt)` — substep-count-sensitive, anticipated
  by M1.1.5's own doc and wanted by §1.7 step 6, so this one is an intended change;
- **an accumulated force `F`** is applied on the FIRST substep only and cleared there, so the tick
  delivers `F/m·h` instead of `F/m·dt` — **a quarter of the intended impulse at the default
  `substep_count = 4`**.

This is not a reading of mine that needs a probe: `tests/integration_test.zig:201` already pins it,
in these words — "Second tick with no re-apply: no force contribution ⇒ velocity unchanged".

§1.7 step 3 settles the SEMANTICS and contradicts the file list, not the Scope: the accumulators are
read into the tick's accelerations and **reset at step 3**, once, uniformly over live bodies, while
the APPLICATION is per substep at step 6. `integrateVelocities` as written does the reset at step 6,
`n` times.

`addForce`/`addTorque` have no production consumer today (only `integration_test.zig` and
`body_manager_test.zig`), so the defect would be LATENT — which is precisely why it is worth
stopping for rather than discovering at M1.1.15 with the orchestrator on top of it.

**Recommended resolution, and it costs no re-baseline.** Decompose in `pipeline/integration.zig`,
purely additively:

- `integrateVelocitiesNoReset(bm, h, gravity)` — the current body minus the two clears;
- `resetForceAccumulators(bm)` — the uniform §2 clear over live bodies, dead slots untouched;
- `integrateVelocities` becomes their exact composition, so its behaviour is bit-identical and
  **every M1.1.5 pin stays green with zero re-baseline** — the same move M1.1.5 itself made when it
  split `integrate` into `integrateVelocities`/`integratePositions`, in this very file.

`rigid/solver.zig` then calls `resetForceAccumulators` once at step 3 and `integrateVelocitiesNoReset`
per substep. N8 is honoured exactly; what changes is the frozen "Explicitly untouched" clause for one
file, which is why this is not a call I make alone.

Two alternatives, both rejected and recorded so the choice is visible: keeping the file literally
untouched and accepting `1/n` of the force impulse (a silent physics error); or having `solver.zig`
snapshot and restore the accumulator columns around each substep (correct, but it duplicates the §2
reset rule in a second place and needs per-tick scratch).

**Status: awaiting arbitration. No implementation line written for Gate B.**
