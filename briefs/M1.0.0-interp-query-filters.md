## Context

M0.8 delivered the tree-walking interpreter over the full v0.6 grammar (three levels) with a working dynamic ECS bridge (runtime component registry, dynamic SoA archetype, resource store). At S4/M0.8, the interpreter walks `world.archetypes` directly; the M0.8 debt work added multi-`has_with_filter` per rule and an `or`-predicate bitset short-cut. Tier-0 ECS (M0.1) provides archetype-level filtered queries. The resolver already compiles each rule's `when` clause into a static `archetype_set` and an `ECSAccessMap` (`etch-resolver-types.md §12.2`).

This sub-milestone wires the interpreter's per-rule entity selection to that precomputed `archetype_set`, so a rule's `when` clause filters entities by archetype: presence (`has`), exclusion (`not has`), value field-filter (`has T { field op value }`), and full `and`/`or`/`not` composition. It is pure interpreter-side capability — no grammar and no resolver change. It is the first Phase 1 prerequisite for piloting any module from Etch.

## Closing notes

### What was delivered

L'interpréteur tree-walking (M0.8) sélectionne désormais les entités de chaque
règle entity-bound via un **set d'archétypes matchants caché par règle**
(`RuleDesc.matching_archetypes`) rescanné paresseusement sur la queue de
`world.archetypes` (`rescanMatching`, pattern option-β / `Query.maybeRescan` de
`engine-ecs-internals.md §4`). Cela remplace le scan linéaire global qui
ré-évaluait l'arbre de prédicat sur chaque archétype à chaque tick. Le mécanisme
généralise le short-cut bitset `or` livré en M0.8 (auparavant réservé aux règles
`or` au-dessus de 8 archétypes) à **toutes** les règles entity-bound ; le champ
`uses_or` et le seuil `or_bitset_threshold` sont retirés (devenus morts). Les
formes de filtrage de la clause `when` — présence `has`, exclusion `not has`,
field-filter valeur (`{ field == value }` via `field_filters` ; `{ field > value }`
et expressions générales via `expr_filters`), composition complète
`and`/`or`/`not` — transitent par ce chemin unifié, inchangées dans leur
sémantique (déjà délivrées en M0.8 ; consolidées sur la sélection cachée). Pure
capacité interpréteur : aucune modif grammaire / lexer / parser / resolver.

Observable per-rule : `RuleDesc.matched_entities` + accesseurs publics
`Interpreter.ruleCount` / `ruleName` / `ruleMatchedEntities`.

Tests : `tests/etch/v1/` (7 fixtures `.etch` + harness `query_filters_test.zig`)
couvrant chaque forme de filtre et la composition, le cas dynamique
never-matches→matches, et l'observable per-rule logué + asserté.
