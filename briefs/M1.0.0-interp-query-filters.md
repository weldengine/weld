## Context

This brief **supersedes** the first M1.0.0 brief. A repo audit established the real state of the code, which differs from the prior brief and from the specs as they stood:

- The resolver does **not** produce an `archetype_set` (an archetype is a runtime notion). It produces a `WhenComponentSet` (`components_in_when` / `resources_in_when` in `src/etch/types.zig`) used only to gate `entity.get(T)`. The specs were corrected accordingly (`etch-resolver-types.md §12.2`, `etch-ast-ir.md §4`, `etch-validation-ecs.md §7.2`, `engine-ecs-internals.md §4`).
- The Tier-0 comptime query engine (`src/core/ecs/query.zig`) is correct and complete for native Zig systems: `Query(Components, filters)` with `With`/`Without`/`Predicate`/`Changed`, archetype matching via `archetypeMatches(arch, required_ids, with_ids, without_ids)` (already runtime — it takes resolved `ComponentId`s), and lazy re-scan (option β) via `rescanIfStale` + `matching_archetypes` bitset.
- **But the interpreter cannot use it.** `world.query` / `world.queryFiltered` are `comptime`-typed (they take `comptime Components: []const type`). Etch components are dynamic (runtime registry), so the interpreter has `ComponentId`s, not Zig types. There is **no dynamic query entry point** on `World`.
- Consequently the interpreter (M0.8 + the first M1.0.0 pass on PR #25) **reimplements** archetype selection by hand: a per-rule `matching_archetypes` bitset + `last_seen_archetype_count` + tail re-scan in `src/etch/interp.zig` — a near-literal copy of `query.zig`'s option-β machinery.

This sub-milestone removes that duplication at the root (decision B): expose a **dynamic query entry point** on `World` (matching by `ComponentId`, reusing `archetypeMatches` + the shared lazy re-scan), route the interpreter's rule entity selection through it, and delete the interpreter's hand-rolled matching cache. Filtering semantics (presence, exclusion, field-filter, composition) are wired onto this single path. It is the first Phase 1 prerequisite for piloting any module from Etch, and it pays down the M0.8/S4 "interp reimplements the query engine" debt instead of extending it.

## Scope

- **Livrable 0 — audit (no gate, chained into implementation).** In the execution journal, record: the exact shape of the interpreter's current hand-rolled selection (`matching_archetypes`, `last_seen_archetype_count`, `or`-bitset threshold path, `has_with_filter`); the exact signature of `archetypeMatches` and whether it already accepts slices or fixed arrays; how `not entity has T` and field-filters are currently represented in the resolved AST (dedicated node vs `not(has)` expression pattern). Identify every file touched.
- **Dynamic query entry point on `World`** (Tier-0): a selection primitive matching archetypes by runtime `ComponentId` (a `with`/`without` id set), reusing `archetypeMatches` and the same lazy re-scan as the comptime `Query` (option β). `archetypeMatches` is generalized to slices (`[]const ComponentId`) if it is not already, so the comptime and dynamic paths share one matcher (comptime call sites coerce `*const [N]ComponentId` → slice).
- **Interpreter rerouting**: rule entity selection goes through the dynamic query primitive. The hand-rolled `matching_archetypes` / `last_seen_archetype_count` / `or`-threshold cache in `interp.zig` is **removed**.
- **Presence** (`has T`) → `with`; **exclusion** (`not entity has T`, recognized as the `not(has)` pattern) → `without`.
- **Field-filter** (`has T { field op value }`) → `T` in `with`; the `{ … }` predicate is evaluated **per-entity** at iteration (like `Predicate`), over the entities of the selected archetypes.
- **Composition** `and`/`or`/`not`: `and` of structural conditions → single `with`/`without` set; `or` → union of dynamic-query results over each conjunctive term (the `when` grammar is a flat `and`/`or` sequence, no parentheses — DNF is trivial); non-structural `ecs_condition = expression` terms (e.g. `entity.health > 0`) stay per-entity predicates, never reduced to archetype filters.
- Etch test cases under `tests/etch/v1/` + Tier-0 tests for the dynamic query primitive.

## Out-of-scope

- `Changed<T>` / `entity has T changed` (the `Changed` filter exists in `query.zig` but is **not** exposed to the interpreter here) → **M1.0.1**.
- Events, `emit`, observers → **M1.0.2**.
- Resources without receiver (`get(T)` / `resource T` in `when`) → **M1.0.3**.
- Tag conditions (`tag_op`) — no new tag work beyond keeping M0.8 behaviour green.
- `W1210 RuleNeverMatches` emission — the static criterion is now well-defined (`components_in_when ∩ excludes ≠ ∅`) but its implementation is **tracked as Phase 1 debt**, not done here.
- Inter-rule parallelism / `ECSAccessMap` / rules-as-systems scheduling (future, cf. `etch-resolver-types.md §12.3`).
- Zig codegen of filtered queries (Phase 2) — the comptime path stays as-is.
- Any grammar / lexer / parser / resolver change. `WhenComponentSet` is consumed as-is.

## Acceptance criteria

### Tests

- Tier-0 — `test "dynamic query matches comptime query"` — for a seeded world, the dynamic query (by `ComponentId`) returns the **same** archetype set as the equivalent comptime `Query(Components, filters)`.
- Tier-0 — `test "dynamic query lazy rescan"` — a dynamic query picks up an archetype created after its first iteration (option-β parity).
- `tests/etch/v1/` — `test "filter has only"` — `when entity has T` visits exactly the entities whose archetype contains `T`.
- `tests/etch/v1/` — `test "filter not has"` — `when entity has A and not entity has B` excludes entities carrying `B`.
- `tests/etch/v1/` — `test "field filter eq / ordered"` — `{ field == value }` and a `>`/`<` case visit only matching entities (per-entity predicate over selected archetypes).
- `tests/etch/v1/` — `test "compose or union"` — `when entity has A or entity has B` matches the union; cross-checked against a hand-computed entity list.
- `tests/etch/v1/` — `test "non-structural predicate"` — `when entity.<expr>` (no `has`) is evaluated per-entity, not turned into an archetype filter.
- `tests/etch/v1/` — `test "dynamic archetype appears"` — a rule with no matching archetype at first tick activates once the matching archetype is created at runtime.
- Differential interp↔codegen corpus stays green (parity preserved).
- Zero leak under `std.testing.allocator`.

### Benchmarks

- Non-regression of the S4 interpreter bench (`run-demo-etch-interp` / the entity×rule sweep) within +5 % on the reference hardware (ReleaseSafe, cold-isolated protocol). Removing the hand-rolled cache must not regress steady-state; the dynamic primitive's `rescanIfStale` no-op is a single compare-and-branch (cf. `engine-ecs-internals.md §4`).

### Observable behaviour

- An `.etch` file with mixed-filter rules (has / not-has / field-filter / `or` / non-structural predicate), run through the interpreter, emitting a per-rule matched-entity count to the log; counts match a hand-computed expectation for the seeded world.

## Notes

- The plan title uses Tier-0 nomenclature `With<T>`/`Without<T>`. There is no such Etch surface — filtering is the `when` clause. Do not add a turbofish filter syntax.
- One matcher, two callers: do **not** leave two copies of the archetype-matching / lazy-re-scan logic. The whole point of this sub-milestone is that `interp.zig` stops duplicating `query.zig`.
- `not entity has T` is grammatically the `expression` alternative of `ecs_condition` (a boolean `not entity.has(T)`), not a dedicated exclusion operator. Recognize the `not(has)` pattern to derive `without`; everything not matching a structural pattern stays a per-entity predicate.
- This brief touches Tier-0 (`world.zig`, `query.zig`). Keep changes additive and minimal; the comptime path must remain byte-behaviour-identical.
- PR #25 already implemented filtering on the hand-rolled cache. That work is not wasted: the filter semantics and tests carry over; only the selection engine underneath is replaced.
