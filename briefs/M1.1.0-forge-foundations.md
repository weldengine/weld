## Context

M1.1.0 opens M1.1 (Forge 3D / `forge_3d`), the largest Phase 1 milestone (~25 sub-milestones, criteria C1.0/C1.1). It delivers the three foundations every later sub-milestone builds on: the `src/foundation/math/` submodule (first consumer rule — `foundation/root.zig` explicitly defers `math` to its first consumer, which is this milestone), the public Forge API surface (`src/modules/forge/api/` — ECS components per `engine-physics-forge.md` §2 and descriptor types mirroring `engine-tier-interfaces.md` §1), and the `forge_3d` `BodyManager` (SoA, ECS-aligned layouts). Acceptance per plan: create N bodies, correct AABBs. Zero runtime wiring — no `step()`, no scheduler registration, no `ModuleContext`, no interface instantiation (interface freeze is M1.1.15).

**Branch base:** current `main` HEAD (`662f29a`, one docs commit ahead of the tag `v0.10.18-extension-additive-warning`). Branch from `main`, not from the tag.

## Scope

Organized in three gates (E1–E3). Gate protocol in the Claude Code prompt.

### E1 — `src/foundation/math/`

- New foundation submodule, sibling of `simd/`, **zero import of `foundation/simd/`** (sister-module rule, `engine-zig-conventions.md` §10, `engine-directory-structure.md` §620).
- Generic types, comptime scalar `T` (f32/f64 both instantiable from day 1):
  - `Vec(comptime N: usize, comptime T: type)` backed by `@Vector(N, T)`, method API (`a.add(b)` style per `engine-directory-structure.md` §612). Operations: add, sub, neg, scale, componentwise mul, dot, cross (N=3 only), lengthSq, length, normalize, lerp, min, max, abs, splat, eql, approxEql(tolerance). Constants: zero, one; unit axes for N=3 (x/y/z).
  - `Quat(comptime T: type)` — storage order `(x, y, z, w)`, identity = `(0,0,0,1)` (matches `core.ecs.components.Transform.rot` layout). Operations: identity, fromAxisAngle, mul (Hamilton product), normalize, conjugate, inverse (unit-quat inverse = conjugate), rotateVec3, add, scale (the last two required by future angular-velocity integration), approxEql.
  - `Mat3(comptime T: type)` — identity, fromQuat, mul (mat×mat), mulVec, transpose, fromDiagonal, determinant, inverse, scale.
  - `Aabb(comptime T: type)` — fromMinMax, fromCenterHalfExtents, merge, expand, contains(point), overlaps(aabb), center, halfExtents.
- f32 aliases exported: `Vec2`, `Vec3`, `Vec4`, `Quatf` → pick ONE naming scheme: plain `Vec2/Vec3/Vec4/Quat/Mat3/Aabb` aliases at `f32`, generics available for other scalars. No f64 aliases (consumers instantiate generics).
- Conversion helpers to bridge the ECS extern layout: `Vec3.fromArray([3]f32)` / `.toArray()`, `Quat.fromArray([4]f32)` / `.toArray()`, and `asFloatSlice(items: []const Vec3) []const f32` (per `engine-directory-structure.md` §620).
- Comptime layout pins: `@sizeOf(Vec3) == 16`, `@alignOf(Vec3) == 16` (f32 instantiation) — the property that makes BodyManager SoA arrays bulk-sync-compatible with `Transform.pos` (`[3]f32 align(16)` + pad = 16-byte stride).
- Handedness anchor: the coordinate system is right-handed, Y-up, −Z forward (`engine-coordinate-system.md`). `cross(unit_x, unit_y) == unit_z`. Rotating `(1,0,0)` by +90° about +Y yields `(0,0,-1)`.
- Wire `pub const math` into `src/foundation/root.zig` (+ comptime test pin per `engine-zig-conventions.md` §13).
- Uses `std.math` trig freely — foundation math is general-purpose; forge_3d pins deterministic trig at M1.1.14, inside the solver, not here.

### E2 — `src/modules/forge/api/`

- Public Forge API surface. Type definitions only — **no ECS registration** (that is runtime wiring, deferred to the milestone that instantiates the module).
- ECS components (extern structs, comptime size/align assertions, same discipline as `src/core/ecs/components.zig`), per `engine-physics-forge.md` §2:
  - `RigidBody` — body_type, mass (kg), linear_damping = 0.05, angular_damping = 0.05, friction = 0.5, restitution = 0.3, gravity_scale = 1.0, continuous_collision = false, can_sleep = true.
  - `CollisionShape` — shape_type tag (u8-backed `ShapeType`) + extern union of per-shape params, offset `[3]f32`, rotation_offset `[4]f32`, collision_layer: u8, is_trigger: bool.
  - `PhysicsForces` — force `[3]f32`, torque `[3]f32` (aligned/padded like `Velocity`).
  - `Velocity` — **re-export of `core.ecs.components.Velocity`** (no duplicate definition; see Notes, decision 2).
- Descriptor and ID types mirroring `engine-tier-interfaces.md` §1 (these are the day-1 interface contract; the file `src/interfaces/PhysicsModule.zig` will later become their canonical home and `api/` will re-export — zero call sites touched):
  - `BodyId = u32`, packed `index:24 | generation:8` (see Notes, decision 4). `ShapeId = u32`, same packing.
  - `BodyType = enum { static, kinematic, dynamic }`.
  - `ShapeType` enum, **C1.1-complete set**: sphere, box, capsule, cylinder, tapered_cylinder, convex_hull, plane, triangle_mesh, height_field, compound, mutable_compound, empty (see Notes, decision 3b — spec enum in `engine-tier-interfaces.md` §1 is a subset; extension recorded).
  - `ShapeDescriptor = union(ShapeType)` tagged union (the spec's flat struct self-describes as a simplification of a discriminated union — Notes, decision 3a). M1.1.0 payloads: `sphere: { radius: f32 = 0.5 }`, `box: { half_extents: Vec3 }` (default 0.5³), `capsule: { radius: f32 = 0.3, half_height: f32 = 0.5 }`. All other variants: `void` placeholder payloads for now (constructible variants extend at their sub-milestones, pre-freeze).
  - `BodyDescriptor` — entity (`core.ecs.EntityId`), body_type, shape (`ShapeId`), position (Vec3, zero), rotation (Quat, identity), mass = 1.0, friction = 0.5, restitution = 0.3, linear_damping = 0.05 (see Notes, decision 3c), angular_damping = 0.05, collision_layer: u8 = 0, gravity_factor = 1.0, continuous = false.
  - `Transform` pose type `{ position: Vec3, rotation: Quat }` — the physics pose, distinct from the ECS `Transform` component (no scale), verbatim per `engine-tier-interfaces.md` §1.
- Uses `foundation.math` types directly (not `core.math` — Notes, decision 3d).

### E3 — `src/modules/forge/solvers_3d/forge_3d/`

- `forge_3d` skeleton, in-tree per `engine-spec.md` §3.5 / `engine-directory-structure.md` §622. Depends ONLY on `foundation/math/` and `src/modules/forge/api/` (plus `core.ecs` public component/entity types re-exported through `api/`). Zero coupling with other modules.
- `Real` comptime scalar: build option `physics_f64` (default false → `Real = f32`). Local aliases `Vec3r = math.Vec(3, Real)`, `Quatr`, `Mat3r`, `Aabbr`. All forge_3d code written against `Real` from day 1.
- `ShapeStore`: `createShape(ShapeDescriptor) → ShapeId` / `destroyShape(ShapeId)` / getters. Free-list slot reuse (LIFO, deterministic), generation bump on destroy, stale-ID access rejected (safe getter returns null; debug assert on unchecked paths). M1.1.0 accepts sphere/box/capsule; any other variant → `error.UnsupportedShape`. Per shape, precomputes: local AABB, unit-mass local inertia diagonal.
- `MotionProperties`: inv_mass (`Real`), local inverse inertia (`Mat3r`), linear/angular damping, gravity_factor. Static and kinematic bodies: inv_mass = 0, inv_inertia = zero.
- Inertia formulas (solid, principal axes, computed at `addBody` from shape geometry + descriptor mass):
  - Sphere: `I = 2/5 · m · r²` (all axes).
  - Box (half-extents hx, hy, hz): `Ix = m/3 · (hy² + hz²)`, cyclic.
  - Capsule (axis Y, radius r, cylinder half-height h): closed-form composite cylinder + two hemispheres (mass split proportional to volumes).
- `BodyManager` (SoA): parallel unmanaged arrays — position (`Vec3r`), rotation (`Quatr`), linear/angular velocity (`Vec3r`), `MotionProperties`, `ShapeId`, `BodyType` + flags, entity (`EntityId`). `addBody(BodyDescriptor) → BodyId` / `removeBody(BodyId)` / safe getters. Free-list LIFO + generation packing identical to `ShapeStore`. **Deterministic ID allocation**: an identical operation sequence yields identical IDs (no hash-map ordering anywhere in the allocation path) — M1.1.14 constraint anticipated.
- World AABB per body, exact per primitive:
  - Sphere: center ± r.
  - Box: `extent_i = Σ_j |R_ij| · he_j` (absolute rotation matrix × half-extents).
  - Capsule: merge of the two end-cap sphere AABBs (endpoints = pos ± R·(0, h, 0), radius r).
- Build wiring: `forge` module in `build.zig` (imports `foundation`, `weld_core`), solver unit tests under `src/modules/forge/solvers_3d/forge_3d/tests/` (C1.1 verification path) compiled into `zig build test`.
- Local (non-CI) validation: `zig build test -Dphysics_f64=true` compiles and passes (mechanism proof; full f64 validation is M1.1.15).
- `CLAUDE.md` §3.4 update applied in Étape 4 — editions delivered in the E3 GO payload.

## Acceptance criteria

### Tests

Math (inline tests in the math files, per `engine-zig-conventions.md` §13):

- `vec.zig` — vector algebra: dot/cross identities, `cross(unit_x, unit_y) == unit_z` (handedness pin), normalize on known vectors, lerp endpoints, approxEql tolerance behavior
- `vec.zig` — layout pins: `@sizeOf(Vec3) == 16`, `@alignOf(Vec3) == 16`; `fromArray`/`toArray` round-trip
- `quat.zig` — `fromAxisAngle(+Y, π/2)` rotates `(1,0,0)` to `(0,0,-1)` (tolerance 1e-6); mul composition vs sequential rotation; normalize; conjugate/inverse round-trip
- `mat3.zig` — `fromQuat` parity with `Quat.rotateVec3` on ≥3 known cases; `inverse(m).mul(m) ≈ identity`; transpose of orthonormal = inverse
- `aabb.zig` — merge/contains/overlaps truth table (disjoint, touching, nested)
- comptime instantiation of `Vec(3, f64)`, `Quat(f64)`, `Mat3(f64)`, `Aabb(f64)` compiles (generic proof)

API (inline tests in `api/`):

- `components.zig` — comptime size/align assertions on RigidBody, CollisionShape, PhysicsForces; `Velocity` re-export identity (`api.Velocity == core.ecs.components.Velocity`)
- `types.zig` — descriptor defaults match this brief's values; BodyId pack/unpack round-trip (index 24 bits, generation 8 bits)

Forge (in `solvers_3d/forge_3d/tests/body_manager_test.zig` + inline):

- `test "create 1000 bodies yields valid unique ids"` — 1000 dynamic bodies, all ids valid, all distinct
- `test "create 10000 bodies smoke"` — capacity growth, no invariant break
- `test "slot reuse is LIFO and generation-checked"` — remove then add reuses the freed index with bumped generation; the stale id's safe getter returns null
- `test "id allocation is deterministic"` — identical add/remove sequence run twice yields identical id sequences
- `test "sphere world aabb"` — position offset, exact bounds
- `test "rotated box world aabb"` — box rotated 45° about Z, bounds vs hand-computed `Σ|R_ij|·he_j` values (tolerance 1e-5)
- `test "rotated capsule world aabb"` — capsule rotated 90° about Z, bounds vs the two end-cap spheres
- `test "static body has zero inverse mass and inertia"`
- `test "inertia matches analytic values"` — sphere 2/5·m·r², box m/3·(hy²+hz²) cyclic, capsule vs closed-form composite (tolerance 1e-4 relative)
- `test "unsupported shape rejected"` — cylinder descriptor → `error.UnsupportedShape`

## Notes

Decisions taken at scoping (ground-truth recon on `main @ 662f29a`, 2026-07-12):

1. **Branch base = `main` (662f29a)**, one docs commit ahead of `v0.10.18-extension-additive-warning`. Branching from the tag would conflict on `CLAUDE.md`/`README.md` at merge.
2. **`Velocity` stays in `core.ecs.components`**; `forge/api` re-exports it. Moving it into forge would invert the dependency direction (core → Tier 1, forbidden) and touch ~10 core test files. All physics call sites go through `api.Velocity`; a future relocation flips only the re-export.
3. **Recorded deviations from `engine-tier-interfaces.md` §1** (spec patch to produce at milestone close):
   - (a) `ShapeDescriptor` implemented as a tagged union — the spec's flat struct is annotated "Union discriminée par shape_type — simplifié ici"; the union IS the specified design.
   - (b) `ShapeType` extended to the C1.1-complete shape set (the spec enum omits plane, tapered_cylinder, height_field, mutable_compound, empty while C1.1 requires those shapes). Enum extension is additive and pre-freeze.
   - (c) `BodyDescriptor.linear_damping` default aligned to **0.05** (spec says 0.01 in §1 but 0.05 in `engine-physics-forge.md` §2; Jolt default is 0.05; the component and descriptor must agree).
   - (d) Math types come from `foundation.math` (module import), not `core.math` (the spec alias predates the foundation split; asset_pipeline already imports `foundation` directly — same pattern).
   - Field-name divergences between the Etch component surface (§2: `gravity_scale`, `continuous_collision`) and the descriptor surface (§1: `gravity_factor`, `continuous`) are kept as each spec writes them — two different surfaces, mapping is documented at `addBody`.
4. **BodyId/ShapeId = u32 packed `index:24 | generation:8`** (16.7M live bodies cap, 256-generation ABA window). The interface type stays `u32` per spec; packing is internal semantics. Stale-handle detection from day 1 avoids silent corruption once removeBody exists in gameplay paths.
5. **Interface file + `ModuleContext` deferred** — instantiating `PhysicsModule(Impl)` requires `core.ModuleContext`, which does not exist and whose spec has an unresolved Tier-0→Tier-1 reference (`asset_loader: *AssetLoader`). The day-1 contract is carried by the descriptor types (mirrored verbatim); when `src/interfaces/PhysicsModule.zig` lands, declarations move there and `api/` re-exports — zero call sites touched. Repo precedent check: RenderModule froze via its module root namespace + `WELD_RENDER_PROTOCOL_VERSION`, and `src/interfaces/` does not exist yet; the location decision belongs to the interface-landing milestone.
6. **Determinism anticipated (M1.1.14)**: no hash-map iteration order may leak into id allocation or any observable result; free-lists are LIFO. `std.math` trig is allowed in `foundation/math` (general-purpose); the solver pins its own deterministic trig at M1.1.14.
7. **SoA "ECS-aligned"** means: position/rotation arrays use the same 16-byte-aligned element layouts as `core.ecs.components.Transform` fields (`@sizeOf(Vec3) == 16` pin), so the M1.1.15 Transform sync can be bulk/memcpy-friendly.
8. Gotcha: `@Vector(3, f32)` padding to 16 bytes is what the layout pins assert; if a future target breaks the assumption, the comptime assert fails loudly — do not remove it.
