## Context

The repository carries 46 963 comment lines against 114 631 code lines across the 275 files of `src/` — 29.1 %, with 75 files at 50 % or above. The cause is not one milestone: the instruction "the reason goes to the site" was issued at every milestone and at nearly every M1.B verdict, and a removal was never asked for. This milestone applies a conservation criterion to the whole tree, installs the four mechanical rules that make the recurrence detectable, and reports the density without ever gating on it.

**A first attempt at this milestone was opened and cancelled.** Its brief set a per-file density ceiling, blocking in the linter. Under a ceiling the executed question stops being *does this comment deserve to exist* and becomes *how do I get under the threshold*: 1 082 of 2 192 comment blocks in `src/core` were shortened, the payload being lost on the fourth line of a block whose first three were kept, and two verified concurrency facts disappeared — one of them a named race. The branch and PR were abandoned; nothing reached `main`; none of those commits is a base. The form and its rule are `engine-audit-checklist.md` §3, `D31` — a quantitative constraint substituting its own optimum for the question it was meant to raise.

**This milestone has no ceiling, no target, and no linter rule on any ratio.** Introducing one — for a file, for a diff, for a fix — reproduces the cancellation. Density is a number that gets reported, never a gate.

**Three oracle regimes that do not overlap**, and that is what sets the gate boundaries. Writing the rules necessarily changes the tokens of `tools/`, so no fingerprint runs during G0–G1. Removing an identifier from a **test name** changes a `string_literal`, so no fingerprint at G10 either. Only G2–G9 run under fingerprint.

**Load-bearing comments — three known files, and the sweep is a G0 deliverable.** `src/interfaces/PhysicsModule.zig` asserts, from a test, that the string `**THIS FILE IS FROZEN.**` is present in its own source — and that string lives in a header doc comment; rewording it reddens a test with no code moved. `src/etch/descriptor_types.zig` has its text spliced into generated code by `etch/zig_codegen/lower.zig`, which filters only `//!` — its `//` and `///` lines **are** code. `tests/physics/forge_module_test.zig` reads its own source to confront its table with the tests that exist. For these three, unchanged fingerprint does not imply unchanged behaviour. G0 sweeps for a fourth: every `@embedFile` whose target is a `.zig` source, every line-count or file-hash over a source path.

**On the criterion, and the one thing that makes it work.** A comment survives if **its removal would make a false statement possible that no test catches**. It arbitrates *internal* comments. A `///` on a public declaration is required by the doc-comment rule regardless — its reader is the caller, and the caller does not run the test.

The block is the unit of judgement: kept whole, replaced by **the shortest wording that preserves the complete contract**, or removed whole. Shortening by cutting the end is the fourth outcome and it is forbidden. A concurrency fact — named race, memory ordering, non-atomic access, acquisition order — is kept or carried **word for word**, never paraphrased; a concurrency fact that is *false* is a defect and gets corrected, which is a content change and goes through the criterion.

**Do not automate the pass.** The previous attempt established, by measurement, that a script optimises the number and not what survives. Per gate, per added or reworded block, one answer: *which false statement would its removal make possible?* No answer, no block.

**Density is reported per gate and gates nothing.** Report it; do not act on it. A gate that comes out at 39 % is information, not a failure.

**What does not go into a file, and where it goes instead.** Design rationale, measurements, milestone history go to this brief's execution log or to the commit body. That is the rule that produced the 46 963 lines when it was inverted; `engine-development-workflow.md` §5.3 now binds the verdict side of it too.
