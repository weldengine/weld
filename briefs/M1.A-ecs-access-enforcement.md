## Context

`ARCH-030` requires that a system reach only the components and resources it declared, and that the restriction be carried by the TYPE of the view it receives. Today `SystemDescriptor` carries an `accesses` field and a body that receives an unrestricted `*World`: two neighbouring fields that nothing relates. A system may declare `Reads(T)` and write `T`; the scheduler, reading only the declaration, posts no edge, places both systems on the same topological level and dispatches them to two workers. No diagnostic fires, at build time or at run time.

This milestone closes that class in Zig and brings the Tier 3 C surface to the form its owning document specifies. It delivers no gameplay capability: it is a safety barrier, and its cost is linear in the number of registered systems, hence growing with every Tier 1 module delivered.

## Scope

- A `comptime` view type parameterised by a declared access set. `get` and `getMut` carry a `comptime` membership test; an undeclared component, or a mutable access to one declared read-only, is a `@compileError`.
- A monomorphic trampoline generated per system. `AccessDescriptor` is a runtime, type-erased value and `SystemFn` a single function pointer, so a context parameterised by the declared set cannot be stored by the scheduler directly. The trampoline builds the view from the world and hands the scheduler an erased pointer. The view and the DAG edges derive from ONE declaration; no second list exists.
- Removal of the empty default on `SystemDescriptor.accesses`. Registering a system without a declared set is a registration error, never an implicit empty set.
- Removal of the `world` field from `CommandBuffer`. Its only use is `ensureComponentRegistered` at record time; resolution moves to `flush`, carried per command on the `AccessDescriptor` pattern. `flush` takes the world as a parameter. Without this, the restricted view is bypassable through the neighbouring field, and `flush` / `applyOne` make the effect immediate.
- Structural mutation from a system goes through the command buffer and nowhere else. No third access category: `Structural(T)` would be exploitable only by serialising every structural system against every system touching the archetypes involved, which annuls the parallelism `ARCH-010` requires.
- Migration of the one registered production system and of its call chain (`forge/sync.zig`, `sync_in.zig`, `services/physics.zig`), with `*World` removed from the system entry point.
- Migration of the 51 registration sites in `tests/` and `bench/`.
- Tier 3 alignment on `engine-c-api.md` §5.5, whole chain: `query_create` declares reads and writes separately, `WeldQueryChunk` receives its two index spaces and its `struct_size`, and a witness C plugin fails to compile the moment a read column becomes assignable.
- Counter-proofs distributed from the gate that introduces each guarantee, each paired with a POSITIVE witness in the same harness.

## Closing notes

- **What worked:**
  - **Deriving the view and the DAG from ONE `spec` removed the failure the milestone exists to close, rather than detecting it.** `SystemDescriptor.of(phase, name, spec, body)` produces the descriptors AND the type of the context; there is no second list, so nothing can disagree. It also retired a hazard nobody asked it to: `registerSystem` stores the caller's `accesses` slice without duplicating it, and `forge/sync.zig` documents a real crash from an inline `&.{ … }` temporary dangling — a derived set is a comptime constant and cannot.
  - **Erasing the world's TYPE instead of trying to hide it.** Zig has no private field and the brief says so; what the view does is store the pointer as `*anyopaque`, so the bypass costs an explicit cast at the call site instead of a field access. Pairing that with the job-bound marker was necessary rather than decorative: the erasure makes `carriesMarked` blind, and a view in a worker's arguments is exactly the hazard the marker exists for.
  - **The counter-proofs shipping WITH the guarantee, not after it.** Both halves of the harness were shown to redden before either was believed, and one of those counter-factuals found a defect in the harness itself.
  - **Reading the diff after a mechanical pass.** Two separate regressions from one regex — an eaten allocator parameter in every multi-line signature, and a real argument removed at every call whose receiver was a `World` — were caught by reading the diff pair by pair, not by the compiler, which was happy with several of them.
- **What deviated from the original spec:**
  - The FROZEN SECTION's registration count is refuted by measurement: **55 sites across 11 files**, not 51 across 10. Recorded above; the frozen text is a Claude.ai round-trip and was not edited here.
  - `WELD_ECS_PROTOCOL_VERSION` 1 → 2. Not named by the brief; prescribed by `root.zig`'s own doc comment for exactly this case.
  - Three additive `World` accessors (`changedTick`, `resourceBytes`, `currentTick`) outside the brief's file list, and `observers.zig` likewise — both justified in the Execution log.
  - The instruction-for-instruction comparison is `zig build ecs-access-zero-cost`, not a `test` block: a test cannot disassemble the binary it lives in, and the repository's only precedent for reading a claim in emitted code is a build step feeding a Zig scanner (`forge-asm-inventory`). `tests/core/ecs/access_view_test.zig` pins the structural precondition and names the step as the oracle.
- **What to flag explicitly in review:**
  - **The protocol bump.** Three shapes `root.zig` names as versioned changed, all breaking for a Tier 1 caller. If the intent was to keep the surface at 1, that is a decision to take before merge, not after.
  - **`FrameContext.user` is the residual the view cannot close**, and it is the path every system in the tree actually uses to reach its query. The enforcement is real on the view's own surface and silent on that one. Stated rather than implied.
  - **The Tier 3 C mirror is hand-written** because no binding generator exists in this tree. It is pinned on both sides, but the pin is a layout pin: the day `weld_api.h` is generated, this header should be deleted rather than reconciled.
