## Context

`ARCH-030` requires that a system reach only the components and resources it declared, and that the restriction be carried by the TYPE of the view it receives. Today `SystemDescriptor` carries an `accesses` field and a body that receives an unrestricted `*World`: two neighbouring fields that nothing relates. A system may declare `Reads(T)` and write `T`; the scheduler, reading only the declaration, posts no edge, places both systems on the same topological level and dispatches them to two workers. No diagnostic fires, at build time or at run time.

This milestone closes that class in Zig and brings the Tier 3 C surface to the form its owning document specifies. It delivers no gameplay capability: it is a safety barrier, and its cost is linear in the number of registered systems, hence growing with every Tier 1 module delivered.

## Scope

- A `comptime` view type parameterised by a declared access set. `get` and `getMut` carry a `comptime` membership test; an undeclared component, or a mutable access to one declared read-only, is a `@compileError`.
- A monomorphic trampoline generated per system. `AccessDescriptor` is a runtime, type-erased value and `SystemFn` a single function pointer, so a context parameterised by the declared set cannot be stored by the scheduler directly. The trampoline builds the view from the world and hands the scheduler an erased pointer. The view and the DAG edges derive from ONE declaration; no second list exists.
- Removal of the empty default on `SystemDescriptor.accesses`. Registering a system without a declared set is a registration error, never an implicit empty set.
- Removal of the `world` field from `CommandBuffer`. Its only use is `ensureComponentRegistered` at record time; resolution moves to `flush`, carried per command on the `AccessDescriptor` pattern. `flush` takes the world as a parameter. Without this, the restricted view is bypassable through the neighbouring field, and `flush` / `applyOne` make the effect immediate.
- Structural mutation from a system goes through the command buffer and nowhere else. No third access category: `Structural(T)` would be exploitable only by serialising every structural system against every system touching the archetypes involved, which annuls the parallelism `ARCH-010` requires.
- Migration of the one registered production system and of its call chain (`forge/sync.zig`, `sync_in.zig`, `services/physics.zig`), with `*World` removed from the system entry point.
- Migration of the 51 registration sites in `tests/` and `bench/`.
- Tier 3 alignment on `engine-c-api.md` §5.5, whole chain: `query_create` declares reads and writes separately, `WeldQueryChunk` receives its two index spaces and its `struct_size`, and a witness C plugin fails to compile the moment a read column becomes assignable.
- Counter-proofs distributed from the gate that introduces each guarantee, each paired with a POSITIVE witness in the same harness.

## Out of scope

- Deriving a rule's access set from its body (the Etch rules → scheduler bridge). Inter-rule parallelism is not implemented in Phase 1; rules run sequentially in the interpreter.
- Making `doc_comments` blocking on nested declarations, and writing the 512 nested doc comments (`M1.D.28`). Measured: 43 of them fall inside this milestone's eleven files, and writing that share does not make the rule blocking.
- The conservation pass on `tests/` (`M1.D.25`) and the re-derivation of the AST partition (`M1.D.26`). Neither overlaps this milestone's object; touching 51 registration sites in `tests/` is not a comment pass.

- Implementing those stubs.

## Acceptance criteria

### Tests

- `tests/core/ecs/access_view_test.zig` — `test "a declared read is reachable and a declared write is mutable"` — the POSITIVE witness without which every counter-proof below is vacuous
- `tests/core/ecs/access_view_test.zig` — `test "the view compiles to the same pointer arithmetic as a direct access"` — disassembly of a witness system, compared instruction for instruction
- `tests/core/ecs/access_counterproof/` — three cases — undeclared access, mutable access on a read-declared component, registration without a declared set. The harness distinguishes an EXPECTED compilation failure from a failure for any other cause: a counter-proof log shares its exit code with an ordinary compile error, so the expected diagnostic text is matched, and a control case that must COMPILE runs in the same execution.
- `tests/core/ecs/command_buffer_test.zig` — `test "a system reaches no world through its command buffer"` — the type carries no field of that shape, asserted structurally and not by name
- `tests/core/ecs/command_buffer_test.zig` — `test "a deferred add resolves its component id at flush and not at record"` — with the counter-factual that resolving at record time is unreachable
- `tests/physics/*` — the existing suites, migrated, green unchanged
- `tests/c_api/read_column_constness/` — the witness plugin compiles as published, and FAILS to compile with a one-line patch assigning through a read column; both directions asserted in the same step

## Notes

**The gate order, and why it is this one.**

- **G1** — the view type and the monomorphic trampoline, old path kept alive. Its three counter-proofs ship WITH it, not at the end: a guarantee no test exercises is a declaration.
- **G2** — the empty default removed, registration without a declared set made an error.
- **G3** — `world` removed from `CommandBuffer`, resolution deferred to `flush`. Placed before any migration because it decides what a migrated system can still reach.
- **G4** — the production system and its chain. The body does not consume `ctx.world` directly, it PASSES it to `resolve`, `syncIn` and `syncOut`; ten functions of `sync.zig`, three of `sync_in.zig` and one of `services/physics.zig` take `*World`. The view propagates through the chain.
- **G5** — the 51 sites in `tests/` and `bench/`. `stepAndPublish` is realigned on the shape the registered system drives: its doc comment claims the tests exercise that shape, and it diverges from it on the direct-versus-deferred path, which is the point at issue here.
- **G6** — the Tier 3 chain. Aligning the chunk alone would produce two index spaces that no declaration populates.
- **G7** — zero-cost disassembly, determinism replay, C0.1.

**Two measurements that shape the work, taken at `251db05`.**

One registered system exists in production across the whole tree, `forge/sync.zig:747`. The core registers none: the two calls in `scheduler.zig` are inline tests. The remaining 51 sites are tests and benches. The early placement of this milestone remains justified by the growth curve; the word "mechanical" does not survive the measurement.

`syncOut` removes and adds `Sleeping` — an archetype migration — and `step_accesses` expresses it as `Writes(Sleeping)`, the comment at the site saying it is the closest the access model can express. The same body performs `ecs.get(Sleeping, entity)`, a per-entity random access. The view therefore covers random access and not only chunk iteration.

**Traps recorded.**

Zig has no private field. An interface wrapping the command buffer leaves `cmd.inner.world` reachable; encapsulation here is achieved by REMOVING the datum, not by enveloping it.

A counter-proof suite is green when nothing compiles at all. Every non-compilation case is paired, in the same execution, with a case that must compile and whose success is asserted.

`is_singleton` is NOT filtered by the initial scan of `World.queryFiltered` (`M1.D.23`). This milestone builds the view over that path. If the view is constructed such that the gap is promoted into the new type rather than left where it is, stop and report — it is a Claude.ai round-trip, not a judgement call at the gate.
