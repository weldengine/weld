# Comment report, per file

> Regenerate with `zig build comment-report -- --markdown` rather than editing the
> table: these are the numbers the `comment_density` rule enforces, and a table
> maintained beside the rule would drift from it.

**Reading this report, not the diff, is how the pass is reviewed.** A diff of
thousands of removed comment lines is unreadable. What is reviewable is, per file,
the count before, the count after, and — where the criterion made a judgement call —
what was kept and why.

## The measurement, and its definition

A **comment line** is a line whose first non-blank token is `//`. A **code line** is
any other non-blank line. Blank lines are in neither term, and a trailing comment is
part of its code line. The density is `comment / (comment + code)`; the ceiling is
**25 %**, a house rule written down rather than derived from what this pass produces.

That definition was not chosen, it was **identified by measurement**. Four candidate
denominators were computed over the tree; only this one reproduces the recorded
baseline to the digit. `comment / total_lines` gives 26.76 % over `src/`, so a report
written on it would measure a different quantity under the same name.

**Two independently written implementations agree on every figure below** — the Zig
rule that will enforce the ceiling, and a Python probe written from the definition
alone before it. Agreement of two computations of one quantity is what authorises the
number. The only divergence is display: the tool truncates the ratio to hundredths
where the probe rounds, so one prints 28.49 % and the other 28.50 % for the same
51 077 / 179 251.

**The minimum-to-remove figure is a lower bound on removal, not an estimate of the
work.** Removing a comment line shrinks the denominator as well as the numerator, so
a file may keep one comment line per three lines of code; the excess over 25 % of the
current total understates it by a third. The criterion may remove more than the
bound, and a file whose every survivor meets it takes an allowlist entry instead.

applied first to the gate that writes the rules.

**What went, by category.** Every identifier, including the provenance of the
declared test total. Design justification: why the allowlist check is bilateral, why

And three test names that carried history or narration.

## The counter-factuals

A rule seen only green is indistinguishable from a rule that judges nothing. Each was
mutated in its own body, the mutation shown present, the run shown to have compiled
and RUN tests, and the mutation reverted.

| probe | mutation | tests run | reddened |
|---|---|---:|---:|
| CF-A | the ceiling comparison becomes inclusive | 81 | 1 |
| CF-B | `commentStart` returns 0, so every line is a comment | 81 | 3 |
| CF-C | the orphan arm returns immediately | 81 | 6 |

- **CF-A** reddens *the boundary is exact — at the ceiling passes, one line above
  fails*, and nothing else: the counting tests stay green, so the probe establishes
  the boundary rather than the counter.
- **CF-B** reddens *the rule reads comments, not code*, *a `//` inside a string
  literal does not open a comment* and *a multiline string literal line is not a
  comment* — the required control that an identifier in a string literal is not a
  comment.
- **CF-C** reddens all six tests where the arm decides. *A doc block directly
  attached is green* and *a `//!` container header followed by a blank line is not an
  orphan* stay green: they assert an absence, which a silent arm also produces. They
  are non-vacuity controls for the other six, not probes of the arm.

**Four defects were found in this probe apparatus, and none in the rules.** `zig
test` on a rule file fails with *import of file outside module path* — a compile
error — so the first two runs reported red on assertions over a run that compiled no
test; the fix is to drive the probe through the module's test root and require
positive evidence that tests RAN. The failure marker sits on the line AFTER the
progress line when a diff is printed. A three-line window bled a neighbour's failure
onto a passing test, over-counting CF-A at three and CF-C at eight. And the probe's
`git checkout --` restored from the index, destroying the unstaged reduction of the
three rule files: commit before running a counter-factual.
