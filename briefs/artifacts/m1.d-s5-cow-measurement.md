written before each run (`g17/cow/pred_*.md` in the session scratchpad, reproduced in
the tables below). Spec read at:

| File | sha256 | Read |

The ruling (§5.2): every value is a value type, copied at assignment, structs and
collections included; a collection or a string is held by a shared handle and copied on
write, the first write on a shared handle copying it first (memory-model §4.4).

Every write the interpreter can perform on a shared value aliases. No in-place write of
a fixed-array element exists at all: an index is not an assignment target, and a
`mut self` method on an indexed element is refused.

**What the interpreter holds today**, read and then checked adversarially:

| Representation | Count | Write barrier |
|---|---|---|
| `struct_ref`, rule-arena `array_ref`/`map_ref`/`set_ref`, `optional` entries, closures | none; copied bit for bit at every copy point | none |
| persistent `*_persistent` blocks | refcount in the 16-byte header | none: push, pop and insert write whatever the count |
| strings | immutable or counted | none needed: no in-place string write exists |

- **95 copy points**, of which structs alias at 57 and rule-arena collections at 55.
- **9 in-place write sites**: one struct field write, four rule-arena collection
  methods (push, pop, map insert, set insert), the same four on persistent blocks. Plus
  the two `mut self` receiver bindings (sync and async).
- Every write receiver goes through `evalExpr` today. A barrier needs the PLACE, with
  five roots: a local, a struct field, a `get_mut` ref, an optional's payload through
  `?.`, and a closure's captured binding.
- **The persistent count cannot serve as a barrier as it stands**: `evalExpr` adds a
  deferred +1 to every non-call result holding a persistent handle, returned only at the
  arena reset, so `rc > 1` holds at essentially every write. Dropping that +1
  wholesale frees blocks at 9 transfer points (block value, fn and method trailing
  values, return, closure result, break value, async trailing and return, throw).
- **Six holds** are uncounted and would stay wrong under a count on bindings alone: the
  sync `for` iterable (re-read live each iteration), the async `for` frame, argument
  arrays held across later arguments (three call paths), and the optional `m[k]`
  returns.

- **The two backends diverge in OPPOSITE directions.** Structs: the codegen already
  copies (Zig values) and the interpreter aliases. Dynamic arrays: both share, but not
  the same thing — the interpreter shares the whole list, the codegen shares the buffer
  and keeps two headers, so a length is private and the storage is not. In B the codegen
  reads the `undefined` Zig 0.16's `pop` writes into the vacated slot of the shared
  buffer.
- **B2 agrees and is wrong in both**: the differential would pass it if its sidecar
  carried the observed value. Parity across backends does not measure §5.2; only a
  sidecar carrying the spec value does.
- **A fixed-array slice is a view in the codegen** and a copy in the interpreter (C).
- **No corpus program has a copy point** (two greps, zero matches): the differential
  has never exercised §5.2.

**What does not reach the comparison.** A second probe program copied a map, a set and

| Rule | Measured |

## 4. What the alignment takes

**Interpreter.**
1. A count on every store handle — struct, rule-arena collection, optional entry —
   kept by the holders (`Locals.put` and `leave`, the container stores, the 6 holds),
   never by `evalExpr`.
2. The persistent `evalExpr` +1 replaced by holds scoped to their consumer, the 9
   transfer points kept counted.
3. A place resolver for the 9 write sites, five roots, unsharing top down (a shared
   level is copied, the parent slot rebound, the copied children counted).
4. `mut self` as the mutable reference part1 l. 1386 defines: the receiver place is
   unshared before `self` is bound.
5. `[v; n]` counts its handle n times.

**Codegen.** One prelude type wrapping a list with a `u32` count, `share()` at a copy
from a place, a uniqueness check before the four writes (so `pop` gains the arena), a
copy for a fixed-array slice, a shared hold for the `for` iterable, and the map and set
element types named once so their copies compile. Structs need nothing.

## 5. Questions for Guy

1. **Where the count lives in the arena zone.** §4.4 triggers the copy on `refcount > 1`
   but §5.1-5.3 give an arena value no header. The interpreter's rule-arena collections
   and every codegen collection are arena values. A count beside the handle, or an
   eager copy at the copy points where no count exists?
2. **A struct copied at assignment.** Read literally, every one of the 57 struct copy
   points copies. A count with a barrier at the one struct write site is observably the
   same. One mechanism for structs and collections, or the literal copy for structs?
3. **`for x in xs` while the body writes `xs`.** Value semantics implies the loop runs
   over a copy; no text says so, and the interpreter fails today when the collection
   shrinks.
4. **Defect 3**: is `a[i] = v` Phase 1? If it is, it is a tenth write site, with a
   nested unshare.
5. **The order.** V19 leaves an `int[3]` at length 4. A `T[N]` map key (ruling 3) can
   then change inside its map, and a fixed length (ruling 5) holds nothing. Copy on
   write comes before both.
