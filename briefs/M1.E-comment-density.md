## Scope

**The conservation criterion, applied to every comment in `src/`.** A comment survives if its removal would make possible a false statement that no test catches. Three forms pass: a precondition the type cannot express; a bound that must turn red the day it falls; the wrong fix a hurried reader would write. Everything else goes — narration of what the adjacent code does, design reasoning for a decision no longer contested, measurements copied from the brief journal, milestone history. A sentence that passes does not justify the paragraph it opens. When a comment is false, it is replaced, not doubled.

**Three lint rules in `tools/weld_lint/rules/`, following the one-file-per-rule shape already there.**

- `comment_density` — per-file ceiling on the fraction of comment lines. A comment line is a line whose first non-blank token is `//`; trailing comments do not count toward the ratio and are covered by review. The ceiling is **25 %**. A file that cannot pass — every remaining comment meets the criterion — is listed in an allowlist file inside `tools/weld_lint/` with a one-line reason per entry, and the allowlist is reviewed at closure. Report mode first, blocking at the last gate.
- `no_milestone_ids` — no milestone, gate or review identifier in a comment (`M1.B`, `M1.1.15.1/H1`, `G7`, `P1-3`, `RD-1`). History lives in `git log`. Blocking from the first gate on new lines, on the whole tree at the last.
- `doc_comments` extended — a `///` block separated from its owner by an inserted line is an orphan, and the current guard does not see it (six instances in M1.B). One `///` per public declaration, one line unless the contract does not fit the signature.

**A per-file report, committed under `briefs/artifacts/`.** For every file touched: comment lines before and after, and what was kept with its reason under the criterion. The report is the deliverable as much as the removal; the criterion is reviewable only through it.

**Two items M1.B left here.** The documentary pass A — 498 candidate doc sentences over the 29 files of `3fd5472..v0.11.18` that assert a universal or a negative about a path or mechanism the milestone moved — is read as part of the pass over those files, not as a separate task. And `CLAUDE.md` names `M1.D.17` for the chunk-fragmentation debt where the plan numbers it `M1.D.18`; the plan owns the table, `CLAUDE.md` is corrected.

## Out of scope

- **Any change to a line that is not a comment.** Production code, tests and benches change only in comment lines. The suite at an identical floor is the counter-factual of every gate, and a test that turns red means code was removed, not a comment.
- **Rewriting comments that pass.** A comment that meets the criterion is kept as written; this pass removes and replaces false sentences, it does not edit style.
- **Deriving a new ceiling from the pass.** 25 % is a house rule, not a measurement. It is not adjusted to fit the result.
- **The corpus.** The five rules enter `engine-development-workflow.md` at closure through Claude.ai; this milestone touches no specification.
- **Tests and benches beyond comment lines.** Their density is not measured and not ceilinged here.

## Acceptance criteria

### Tests

- **The suite is green at an identical floor after every gate.** 2174 collected on `ubuntu-24.04` and macOS, 2172 on `windows-2025`, re-derived from the suite each time, never from the closing arithmetic. Any movement of the floor is a defect of the gate.
- **`comment_density` measures what it names.** A counter-factual file with a known line count and a known comment count reports the expected ratio; a file at the ceiling passes and one line above fails.
- **`no_milestone_ids` catches every identifier shape** listed in Scope and does not catch the same tokens outside comments — a string literal containing `M1.B` is not a comment.
- **The orphan detector reddens on a `///` block separated from its owner by one inserted line**, and stays green on a block directly attached. Counter-factual: the six orphans M1.B produced, reconstructed, are all caught.
- **The allowlist is not a bypass.** Every entry names a file that actually exceeds the ceiling and carries a reason; an entry for a file under the ceiling is a lint error.

## Notes

**The work is concentrated, and the gates follow the concentration.** Minimum lines to remove to reach 25 % per file: 7 501, of which 4 899 in `src/modules/forge`, 2 000 in `src/core`, 540 in `src/foundation` and `src/interfaces`, and under 600 in everything else. `src/etch` is already at 21 %. `forge_3d` alone carries 3 240 and `forge/api` sits at 64 %.

**This pass is the one M1.B could not finish.** M1.B's reduction took 52 % to 49 % on its own files because it kept whole paragraphs whenever the first sentence passed. Rule five exists for that. When in doubt about a paragraph, remove all of it but the sentence that passes, then ask whether that sentence still needs to be there.

**Falsifiable prose caught five defects in M1.B; narrative prose caught none.** Three comments at G3 that asserted the opposite of their code, a "snapshot by length" that claimed a guarantee the code lacked, and a file header that denied a path the file was on. Those are the comments this pass keeps. A comment that cannot be false cannot catch anything.

**Reading the report, not the diff, is how this milestone is reviewed.** A diff of 7 000 removed lines is unreadable. The report per file — before, after, kept and why — is what the gate review reads, and the diff is checked mechanically for the absence of non-comment changes.

**What is a stop, not a judgement call:** a file whose every remaining comment meets the criterion and still exceeds 25 % — that goes to the allowlist with its reason, not to a rewrite; any non-comment line the pass wants to touch; any comment whose removal the pass cannot decide under the criterion.
