# FROZEN SECTION

*Produced by Claude.ai. Not modifiable by Claude Code outside a Claude.ai round-trip (cf. § Acted deviations).*

## Context

Final Phase 0 milestone. M0.0–M0.8 delivered every Phase 0 brick in isolation (ECS, RTTI/Resources/Events, platform + input, Vulkan forward renderer, asset pipeline, IPC, Etch full-grammar). M0.9 proves the bricks hold together: an end-to-end vertical slice in `examples/vertical_slice/` exercising ECS + Etch + render + assets + input + IPC simultaneously, plus the final C0.5 interface freeze, the CI restructuring debt due since M0.1, the two nominative M0.8 inherited debts, and the formal Phase 0 closure procedure. Canonical scope: `engine-phase-0-plan.md §M0.9`. Advances and closes C0.5, C0.8, C0.9.

**Cardinal rule of this milestone: the slice exercises the existing engine, it does not extend it.** Any gap discovered in a brick (ECS, render, IPC, Etch, assets, input) is a finding requiring STOP + ruling — never a license for silent extension or a local shim in `examples/`.

## Scope

Execution is staged E1–E7 with stop gates (see Notes § Staged execution). Deliverables:

- **E1 — CI restructuring** (debt tracked since M0.1, due at M0.8 close; advances C0.9):
  - Split test and bench into distinct workflows/jobs.
  - Zig cache keyed on `(os, optimize mode, zig version, build.zig.zon hash)`, with before/after CI wall-time measurement archived as a CI artifact (optimization validated by measurement, not presumed).
  - The 4 `build-and-test (os × mode)` cells carry stable, nominative job names; the exact required-check names are documented in the brief journal and PR description (Guy applies the branch-protection settings — repository settings are out of Claude Code's hands).
- **E2 — M0.8 inherited Etch debts** (nominative, cf. Closing notes `briefs/M0.8-full-grammar-v0.6.md`):
  - **Tranche A** — triple-quote `"""` multiline string at the lexer (`etch-grammar.md §1.4`), token lift neighboring DURATION/COLOR (M0.8 precedent). Covered by lexer tests, ≥ 1 new interpreter↔codegen differential, and EBNF harness block(s).
  - **Tranche B** — cross-file scene/prefab validation for `E1782 DuplicateUUID` (cross-scene), `E1786 PrefabRefNotFound`, `E1791 PrefabBaseNotFound` (cf. `etch-validation-ecs.md §23–24`, `etch-diagnostics.md §18.2–18.3`). Built on the intra-file resolution delivered in M0.8, over a minimal multi-file project graph **dimensioned by the slice's needs** — not a generic asset graph.
- **E3 — Vertical slice core (headless)** in `examples/vertical_slice/`: multi-file Etch content (≥ 1 `*.scene.etch` + ≥ 1 `*.prefab.etch`, exercising E2-B; slice text content uses triple-quote strings, exercising E2-A), 100 entities spawned via Etch with Zig POD components, ECS simulation ticking at 60 Hz, no rendering.
- **E4 — Slice render + asset + input**: Vulkan forward rendering of the scene (mesh + texture + camera), 1 asset cooked and loaded through the M0.6 pipeline (source → intermediate → `.bin` → runtime load), 1 input action mapped through the M0.3 input path with an observable effect on the simulation.
- **E5 — Slice IPC editor stub**: runtime ↔ editor stub over the M0.7 IPC channel; a component modification issued by the stub is applied to the live world and visible in the viewport in real time. Closes the C0.8 end-to-end loop.
- **E6 — C0.5 final freeze**: cross-module audit of the 9 Tier 0 interfaces (`World`, `Scheduler`, `Allocator`, `RTTI`, `Resources`, `EventBus`, `PluginLoader`, `IpcServer`, `PlatformLayer`) and the 3 Tier 1 interfaces exercised by Phase 0 code (`RenderModule`, `InputModule`, `AssetPipeline`). Each interface marked frozen (doc-comment marker + `*_PROTOCOL_VERSION` rule reference). Audit runs **after** E5, on the post-slice state.
- **E7 — Phase 0 closure**: full non-regression pass (S1/S3/S4/S5/S6 within baseline ± 5 %, C0.1 mode ≤ 16.6 ms/frame); runnable demo + documented 30 s capture procedure (recording performed by Guy on the reference machine, archived as tag artifact); in-repo copy of `engine-phase-0-criteria.md` header marked `[CLOSED]`; closure PR material. The written decision "Phase 0 close, ouverture Phase 1" is Guy's exclusively.

- macOS/mobile/console/web/VR, CRDT collaboration, and everything under `engine-phase-0-criteria.md` § Hors scope.

## Notes

**Staged execution (E1–E7).** One stage = one pass, reviewed once at its end gate (M0.8 E3 grain). At each stage end, Claude Code emits `étape E<n> terminée, prêt pour review` and waits for an explicit GO from Guy before continuing. No cross-stage chaining without GO. Order is fixed: E1 (CI) → E2 (Etch debts) → E3 (slice headless) → E4 (render/asset/input) → E5 (IPC) → E6 (freeze) → E7 (closure). Rationale: E1 first so all later stages run on the restructured CI; E2 strictly before E3 (the slice's Etch content consumes both debts); E6 strictly after E5 (audit on post-slice state). Calibrated estimate: E1 ¼ d, E2 ½ d, E3 ½ d, E4 ½–1 d, E5 ¼–½ d, E6 ¼ d, E7 ¼ d — total 2.5–3.25 days (Guy + Claude Code workflow).

**Highest-risk stage: E4.** The render ↔ asset ↔ ECS seam has never been exercised end-to-end (M0.4 and M0.6 were validated in isolation). Expected behavior on any gap: STOP + ruling. A local workaround in `examples/` that masks an engine deficiency is the specific failure mode this milestone is designed to catch.

**E2-B sizing guard.** The "project graph" is the minimal structure needed to resolve the three diagnostics across the slice's files (enumerate project Etch files, index prefab IDs and scene UUIDs, resolve references). Anything resembling a general dependency graph, file watching, or incremental cross-file invalidation is out-of-scope.

**E6 freeze mechanics.** Freeze = audit + marker + versioning rule, not refactoring. If the audit surfaces an interface inconsistency that *should* be fixed before freezing, that is a Cas 2 STOP — the fix decision belongs to Claude.ai/Guy, not to the audit pass.

**Known non-issue.** The `failed command` build-runner noise on `zig build test` is cosmetic, deterministic, cross-platform, tracked since M0.5. Do not re-raise, do not fix.

**Context, no action.** A post-M0.8 audit conversation (EBNF mirror corpus, `lower.zig` inline tests, diagnostic coverage) is pending off-critical-path. Mentioned here so its scope is not accidentally absorbed.
