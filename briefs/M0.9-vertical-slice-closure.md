## Context

Final Phase 0 milestone. M0.0–M0.8 delivered every Phase 0 brick in isolation (ECS, RTTI/Resources/Events, platform + input, Vulkan forward renderer, asset pipeline, IPC, Etch full-grammar). M0.9 proves the bricks hold together: an end-to-end vertical slice in `examples/vertical_slice/` exercising ECS + Etch + render + assets + input + IPC simultaneously, plus the final C0.5 interface freeze, the CI restructuring debt due since M0.1, the two nominative M0.8 inherited debts, and the formal Phase 0 closure procedure. Canonical scope: `engine-phase-0-plan.md §M0.9`. Advances and closes C0.5, C0.8, C0.9.

**Cardinal rule of this milestone: the slice exercises the existing engine, it does not extend it.** Any gap discovered in a brick (ECS, render, IPC, Etch, assets, input) is a finding requiring STOP + ruling — never a license for silent extension or a local shim in `examples/`.

Execution is staged E1–E7 with stop gates (see Notes § Staged execution). Deliverables:

## Notes

**Staged execution (E1–E7).** One stage = one pass, reviewed once at its end gate (M0.8 E3 grain). At each stage end, Claude Code emits `étape E<n> terminée, prêt pour review` and waits for an explicit GO from Guy before continuing. No cross-stage chaining without GO. Order is fixed: E1 (CI) → E2 (Etch debts) → E3 (slice headless) → E4 (render/asset/input) → E5 (IPC) → E6 (freeze) → E7 (closure). Rationale: E1 first so all later stages run on the restructured CI; E2 strictly before E3 (the slice's Etch content consumes both debts); E6 strictly after E5 (audit on post-slice state). Calibrated estimate: E1 ¼ d, E2 ½ d, E3 ½ d, E4 ½–1 d, E5 ¼–½ d, E6 ¼ d, E7 ¼ d — total 2.5–3.25 days (Guy + Claude Code workflow).

**Highest-risk stage: E4.** The render ↔ asset ↔ ECS seam has never been exercised end-to-end (M0.4 and M0.6 were validated in isolation). Expected behavior on any gap: STOP + ruling. A local workaround in `examples/` that masks an engine deficiency is the specific failure mode this milestone is designed to catch.

**E2-B sizing guard.** The "project graph" is the minimal structure needed to resolve the three diagnostics across the slice's files (enumerate project Etch files, index prefab IDs and scene UUIDs, resolve references). Anything resembling a general dependency graph, file watching, or incremental cross-file invalidation is out-of-scope.

**E6 freeze mechanics.** Freeze = audit + marker + versioning rule, not refactoring. If the audit surfaces an interface inconsistency that *should* be fixed before freezing, that is a Cas 2 STOP — the fix decision belongs to Claude.ai/Guy, not to the audit pass.

**Known non-issue.** The `failed command` build-runner noise on `zig build test` is cosmetic, deterministic, cross-platform, tracked since M0.5. Do not re-raise, do not fix.

**Context, no action.** A post-M0.8 audit conversation (EBNF mirror corpus, `lower.zig` inline tests, diagnostic coverage) is pending off-critical-path. Mentioned here so its scope is not accidentally absorbed.
