## Context

An external full-repo review (Codex, 2026-07-13) surfaced 6 P1 and 1 P2 defects, all verified against `main` at `v0.11.1-broadphase-bvh` by direct source inspection. They are transverse (core/scene, core/ecs, core/ipc, asset_pipeline) and none touches forge. This standalone hotfix fixes all 7 before M1.1.2 opens, per the zero-deferred-debt rule. Defects are referenced below as D1–D7 in the order of the review.

## Scope

- **D3 — `EntityIdentityStore.release` atomicity** (`src/core/ecs/entity.zig`): reserve free-list capacity (`ensureUnusedCapacity(gpa, 1)`) *before* mutating the slot; append with `appendAssumeCapacity` *after*. Contract: on `OutOfMemory`, no observable mutation — the slot stays alive, `liveCount` unchanged, the call is retryable.
- **D7 — `World.despawn` purges extensions** (`src/core/ecs/world.zig`): remove the entity's `entity_extensions` entry, freeing the owned name slices and the list, in the same call that releases the identity.
- **D4 — `Registry` release atomicity** (`src/modules/asset_pipeline/registry/Registry.zig`): same no-mutation-on-error pattern. When `refcount == 1`, reserve free-list capacity first; only then decrement, invalidate, and append. On `OutOfMemory` the slot keeps `refcount == 1` and stays alive. `Loader.release` then never propagates an error after the slot died, so the payload-free path in `Loader.release` is reachable exactly when it must be — no change needed there beyond what the registry fix implies.
- **D6 — `.bin` validation** (`src/modules/asset_pipeline/format/runtime_bin.zig` + `loader/Loader.zig`): add a `RuntimeHeader.validate(bin_len: usize)` check called from `readBin` after `read`: `version == current_version`; `data_offset >= header_size`, `data_offset + data_size <= bin_len` (overflow-safe arithmetic); same bounds for the metadata section; `hash == hash.u64Of(data section)`. Any failure → new `error.MalformedAsset` added to `LoadError`. `LoadError` is a pinned named set (C0.5): bump `WELD_ASSET_PIPELINE_PROTOCOL_VERSION` from 1 to 2 in `src/modules/asset_pipeline/root.zig`.
- **D5 — `sendWithHandles` short-write handling** (`src/core/ipc/transport_posix.zig`): capture the `sendmsg` return value; when `0 <= n < bytes.len`, send the remainder `bytes[n..]` through the same short-write loop `send()` already implements (factor that loop into a shared helper rather than duplicating it). Ancillary data (fds) travels with the first successful segment; the remainder carries none. POSIX backend only — the Windows backend's `sendWithHandles` is `error.Unimplemented` by contract until Phase 3 (`engine-ipc.md` §4.7).
- **D1 — scene loader string ownership** (`src/core/scene/loader.zig`): interned resource strings are allocated **refcounted** (refcount 1, owned by the written `StringSlot`), not immortal. The loader adopts the `ecs_bridge` write discipline: read the old slot → write the new slot → `decref` the old block. `LoadResult.resource_strings` and its `deinit` destroy-loop are **removed**; `LoadResult` shrinks to `spawned` + `uuid_to_entity` + `mmap`. Teardown parity with interp-written strings — no new mechanism.
- **D2 — scene load rollback** (`src/core/scene/loader.zig`): `loadFromBytes` becomes loader-transactional. Before any resource field write, snapshot the full resource value bytes. On any error after the first spawn: (a) `decref` every string block the loader installed and restore the snapshotted resource bytes; (b) despawn every spawned entity in reverse spawn order (which, post-D7, also purges their extension entries). The contract covers the loader's own mutations only; side effects of user `on_attach` / `on_spawned` hooks that ran before the failure are explicitly outside it. Rollback is best-effort under `OutOfMemory` (log and continue); the guaranteed path targets non-OOM failures (malformed scene, unknown component, resolver failure, hook error).

## Notes

**Gate plan (STOP+GO, one push + review per gate):**
- **E1 — ECS** : D3 + D7.
- **E2 — Asset pipeline** : D4 + D6 (registry atomicity, header validation, `LoadError` + protocol version bump).
- **E3 — IPC posix** : D5.
- **E4 — Scene loader** : D1 + D2, then Étape 4 (CLAUDE.md §3.4, audits, brief closure, PR).

E4 comes last deliberately: the rollback path relies on D7 (despawn purges extensions) and D3 (release semantics) being merged into the branch first.

**D1/D2 write discipline (normative):** for each resource the loader touches: (1) snapshot the full resource value bytes; (2) per string field: read old slot → alloc refcounted block, copy → write new slot; (3) after the whole load succeeds: decref each old slot block (`decref` is a no-op on immortal defaults). On rollback: decref each *new* block, then memcpy the snapshot back — the old blocks were never decreffed, so no incref is needed and no double-free is possible. This ordering is load-bearing; do not reorder.

**D2 aggravation being fixed (context for review):** on current `main`, the `errdefer` over `res_strings` destroys blocks that `loadResources` may already have installed into live `StringSlot`s — the error path dangles even before any `LoadResult.deinit`. The D1 ownership change removes that `errdefer` entirely.

**D5 testability:** a partial `sendmsg` on a blocking `SOCK_STREAM` socket cannot be forced portably in a unit test (it occurs on signal interruption after a partial transfer). Acceptance for D5 is therefore: the remainder loop is the *same shared helper* as `send()` (no duplicated loop), plus the existing handle round-trip tests staying green. Do not add a flaky signal-based test.

**D6 hash cost:** verifying `hash.u64Of` over the data section adds one linear pass per asset load. Accepted: the scene loader already verifies its post-header hash (`verifyHash`), and asset loads are I/O-bound; consistency wins.

**D3/D4 pattern name for commit messages:** "reserve-then-mutate" — reserve every fallible resource before the first observable mutation.
