## Notes

- **Tokenizer vs AST split.** Rules 1–3 (`@cImport`, `usingnamespace`, `*_c` isolation) operate at the token level — they match specific identifiers/builtins/keywords without needing semantic context. `std.zig.Tokenizer` is the right tool: avoids false positives from naive string matches inside comments, string literals, or doc comments. Rule 4 (doc comments on `pub`) requires attached-trivia → declaration mapping, which is what `std.zig.Ast` provides natively. Reimplementing trivia attachment is wasted work.
- **Canonical `*_c` isolation rule.** `engine-c-bindings.md §9.2` defines the rule as *"any `@import("<lib>_c")` outside a generated file fails the build"*, where "generated file" = carries `// AUTO-GENERATED — DO NOT EDIT` header. The brief encodes this header-based formulation. A directory-adjacency formulation would be brittle and inconsistent with the canonical rule.
- **Doc comment edge cases.** `std.zig.Ast`-based detection may produce false positives on advanced patterns (generic functions returning types, type aliases, anonymous struct fields, comptime decls exported via `pub const X = struct { ... }`). Strategy: start strict in M0.0. If real false positives surface during implementation on actual production code, iterate via *Déviations actées* with a Claude.ai roundtrip — do not invent opt-out annotations on the fly.
- **`§22.4` resolution.** Section §22.4 *"Carte par module"* does not exist in the current `engine-spec.md`. The content it referred to (likely a per-module map) has been refactored into `§1.6` (Tier 0/1 catalog) or dispersed across §1.x and §25.3. The brief instructs Claude Code to perform a line-by-line audit during implementation and either (a) repoint each occurrence to the relevant current section identified at reading time, or (b) remove the reference if it is purely decorative in the document header. If the choice is ambiguous on a given occurrence, this is a Cas 2 blocker — return to Claude.ai.
- **Pre-PR cross-doc audit.** Before closing the milestone, Claude Code performs the local cross-doc audit per `engine-development-workflow.md §3.6.1`: `grep -rn` on `/mnt/project/` (NOT `project_knowledge_search` — semantic indexing is structurally insufficient for literal occurrence audit) for the following terms introduced or modified by M0.0:
  - `tools/weld_lint/`
  - `zig build lint`
  - `zig build lint-commit`
  - `scripts/check-commit-msg.sh`
  - `§22.3` and `§22.4` (must have disappeared from the three patched files)
  - `tag pending merge` (must have disappeared from `README.md`)

  Result documented in the PR description.
- **Lefthook installation.** Lefthook is not in the repo (installed via system package manager). The migration here only changes the `lefthook.yml` configuration. ## Déviations actées

- **Exemptions structurelles du `doc_comments` rule — rétractation partielle.** À l'origine quatre exemptions structurelles auto-appliquées (`isPureReExport`, `isTypeAlias`, `isGenericReturningType`, `isEntryPoint`) étaient implémentées comme reconnaissances de patterns AST des « faux positifs anticipés » par les *Notes* du brief. La review Claude.ai post-PR #12 a identifié que cette interprétation contournait la directive *strict-by-default* du brief : encoder structurellement les mêmes catégories que l'opt-out annotation explicitement listée *Out-of-scope* aboutit au même résultat avec un niveau d'indirection en plus. Surtout, `isTypeAlias` exemptait les composants ECS `pub const Transform = extern struct { ... }` — précisément les decls qu'`engine-zig-conventions.md §16` impose de documenter — et `isGenericReturningType` exemptait les type factories qui *sont* la surface API. `83ae2e4` retire les trois exemptions et conserve uniquement `isEntryPoint` (`pub fn main` / `pub fn build`), justifiée par sémantique Zig fixe + couverture par le `//!` file-level. 202 violations remontées en production tree ; doc comments ajoutés systématiquement (commits `f249e03`, `307c67d`, `d0380f6`). Aucune opt-out annotation introduite.
- **Match du marqueur AUTO-GENERATED.** Le brief écrit canoniquement `// AUTO-GENERATED — DO NOT EDIT`, mais les fichiers générés Phase −1 (`vk.zig`, `wayland_protocols/*.zig`) utilisent `//! AUTO-GENERATED — do not edit.`. Le linter accepte les deux : préfixe `//` ou `//!`, contient le substring `AUTO-GENERATED`. Cohérent avec la formulation plus large de `engine-c-bindings.md §9.2` ("//-AUTO-GENERATED header").
- **Citation `engine-zig-conventions.md` dans le doc comment de `doc_comments.zig`.** À l'origine `§12, §19` ; corrigé en `§19` seul (`83ae2e4`). Le brief m'a fait lire §13/§14/§17/§18/§19, pas §12 — citer §12 c'était référencer une section non couverte par la session de spec ingestion.
- `b6f4ade` — Politique anti-tautologie ajoutée en cours de révision. Un `///` qui paraphrase la decl n'est pas un doc valide (le brief impose strict-by-default sur la *présence* du `///`, pas sur du remplissage tautologique). Audit rétroactif des quatre commits docs précédents (`ef1c488`, `f249e03`, `307c67d`, `d0380f6`). Treatment par decl, pas par catégorie : 24 decls supprimées (re-exports orphelins, dead code), ~35 démotées de `pub` à `const` (re-exports internes sans consommateur externe), le reste réécrit en explication du contrat (invariants, lifetime, fonction surfaçante pour les error sets, raison d'exposition au surface). Aucune opt-out annotation introduite ; la règle reste appliquée, on traite par le contenu pas par l'exception.
