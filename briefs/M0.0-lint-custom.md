## Notes

- **Tokenizer vs AST split.** Rules 1–3 (`@cImport`, `usingnamespace`, `*_c` isolation) operate at the token level — they match specific identifiers/builtins/keywords without needing semantic context. `std.zig.Tokenizer` is the right tool: avoids false positives from naive string matches inside comments, string literals, or doc comments. Rule 4 (doc comments on `pub`) requires attached-trivia → declaration mapping, which is what `std.zig.Ast` provides natively. Reimplementing trivia attachment is wasted work.
- **Canonical `*_c` isolation rule.** `engine-c-bindings.md §9.2` defines the rule as *"any `@import("<lib>_c")` outside a generated file fails the build"*, where "generated file" = carries `// AUTO-GENERATED — DO NOT EDIT` header. The brief encodes this header-based formulation. A directory-adjacency formulation would be brittle and inconsistent with the canonical rule.
- **Doc comment edge cases.** `std.zig.Ast`-based detection may produce false positives on advanced patterns (generic functions returning types, type aliases, anonymous struct fields, comptime decls exported via `pub const X = struct { ... }`). Strategy: start strict in M0.0. If real false positives surface during implementation on actual production code, iterate via *Acted deviations* with a Claude.ai roundtrip — do not invent opt-out annotations on the fly.
- **`§22.4` resolution.** Section §22.4 *"per-module map"* does not exist in the current `engine-spec.md`. The content it referred to (likely a per-module map) has been refactored into `§1.6` (Tier 0/1 catalog) or dispersed across §1.x and §25.3. The brief instructs Claude Code to perform a line-by-line audit during implementation and either (a) repoint each occurrence to the relevant current section identified at reading time, or (b) remove the reference if it is purely decorative in the document header. If the choice is ambiguous on a given occurrence, this is a Case 2 blocker — return to Claude.ai.

## Acted deviations

- **Structural exemptions of the `doc_comments` rule — partial retraction.** Originally four self-applied structural exemptions (`isPureReExport`, `isTypeAlias`, `isGenericReturningType`, `isEntryPoint`) were implemented as AST pattern recognition of the "anticipated false positives" from the brief's *Notes*. The Claude.ai post-PR #12 review identified that this interpretation bypassed the brief's *strict-by-default* directive: structurally encoding the same categories as the opt-out annotation explicitly listed *Out-of-scope* yields the same result with one more level of indirection. Above all, `isTypeAlias` exempted the ECS components `pub const Transform = extern struct { ... }` — precisely the decls that `engine-zig-conventions.md §16` requires documenting — and `isGenericReturningType` exempted the type factories that *are* the API surface. `83ae2e4` removes the three exemptions and keeps only `isEntryPoint` (`pub fn main` / `pub fn build`), justified by fixed Zig semantics + coverage by the file-level `//!`. 202 violations surfaced in the production tree; doc comments added systematically (commits `f249e03`, `307c67d`, `d0380f6`). No opt-out annotation introduced.
- **AUTO-GENERATED marker match.** The brief canonically writes `// AUTO-GENERATED — DO NOT EDIT`, but the Phase −1 generated files (`vk.zig`, `wayland_protocols/*.zig`) use `//! AUTO-GENERATED — do not edit.`. The linter accepts both: `//` or `//!` prefix, contains the substring `AUTO-GENERATED`. Consistent with the broader formulation of `engine-c-bindings.md §9.2` ("//-AUTO-GENERATED header").
- **`engine-zig-conventions.md` citation in the `doc_comments.zig` doc comment.** Originally `§12, §19`; corrected to `§19` alone (`83ae2e4`). The brief had me read §13/§14/§17/§18/§19, not §12 — citing §12 meant referencing a section not covered by the spec-ingestion session.
