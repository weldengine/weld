## Scope

- **R1 (critical) — structural validation of `.scene.bin` before any accessor exposure** (`src/core/scene/validate.zig` new, `src/core/scene/loader.zig`). Root cause: `Accessor.open` validates only length/magic/version; every getter then trusts file-controlled offsets and counts (`stringAt` unbounded ref+len, `schema` unchecked index, `archetypeAt` behind a `debug.assert` stripped in ReleaseFast, `column` unchecked `stride × entity_count`, `uuidCount` unchecked subtraction). `verifyHash` is no defense — XxHash64 is trivially recomputed by an attacker. Fix — a **standalone validator** `validate.structure(bytes, header) StructureError!void` that walks the raw bytes directly and **never calls the existing accessor getters**. All arithmetic via `std.math.add`/`std.math.mul` (overflow → `error.MalformedScene`). Checks, in file order per `engine-scene-serialization.md` §4: (a) section offsets monotonically ordered and within `bytes.len` (`header_size ≤ string_table ≤ uuid_table ≤ schema_table ≤ resources ≤ archetypes ≤ extensions ≤ crossrefs ≤ bytes.len`); (b) UUID table span 16-divisible; (c) schema table span = `schema_count × 8` within its section; every `name_ref` a valid string ref (length prefix readable, `ref + 4 + len` within the string table); (d) resources: exactly `resource_count` sequential blocks fitting their section, `schema_index < schema_count`, string-field refs valid; (e) archetypes: block walk fits its section, `component_count ≤ 256`, schema indices `< schema_count`, per-entity name/uuid/parent refs valid (`uuid ordinal < uuidCount`, parent ordinal `< uuidCount` or `no_parent`), column offsets computed with checked arithmetic and ending within the section; (f) extensions table walk within bounds, prefab-id indices valid; (g) crossrefs: ordinals `< uuidCount`, `schema_index < schema_count`, `field_offset + 8 ≤` that schema's `size`. `openVerified` becomes header → hash → `validate.structure` → return accessor; its error set gains `MalformedScene` (already declared in `StructureError`). `uuidCount` keeps its formula, now backed by check (a)+(b); add a comment stating the validator invariant it relies on. The `debug.assert` in `archetypeAt` stays, now provably backed.

- **R3 (high) — PNG: output-bounded inflation, dimension budget, checked arithmetic** (`src/modules/asset_pipeline/codecs/png/decode.zig`, `src/modules/asset_pipeline/codecs/deflate/zlib.zig`, `src/modules/asset_pipeline/codecs/deflate/inflate.zig`). Root cause: `zlib.decompress` inflates unboundedly before any size check (decompression bomb), and `width × height × channels` / `× 4` are unchecked — `parseHeader` caps neither dimension, so `0xFFFFFFFF × 0xFFFFFFFF × 4 ≈ 2^66` wraps `usize` in ReleaseFast → undersized allocation → out-of-bounds writes. **This is corruption, not merely OOM.** Fix — (a) `parseHeader` rejects `width > max_dimension` or `height > max_dimension` with new `error.DimensionsTooLarge`; `max_dimension = 16384` as a named decoder constant (aligned with common `maxImageDimension2D`); (b) all size computations (`sample_count`, RGBA size, per-scanline sizes, Adam7 per-pass sizes) via `std.math.mul`/`add`, overflow → `error.BadHeader`; (c) the exact expected inflated size is computed **before** inflation from IHDR (per scanline: 1 filter byte + ceil(width × channels × bit_depth / 8); Adam7: the sum over the 7 passes, empty passes contributing 0); (d) `inflate` and `zlib.decompress` gain a `max_out: usize` parameter — production exceeding it → new `error.OutputLimitExceeded`; (e) after inflation, output length must **equal** the expected size exactly, else `error.Truncated`. Chunk CRC32 stays out (documented M0.6 choice, unchanged).

- **R4 (high) — glTF: bounds-checked table access and semantic accessor validation** (`src/modules/asset_pipeline/codecs/gltf/decode.zig`). Root cause: `readFloats`/`readIndices` index `accessors[…]`, `bufferViews[…]`, `buffers[…]` directly (panic in safe builds, OOB in ReleaseFast), and `base + i × stride + c × 4` can wrap in ReleaseFast, defeating the per-element bounds check. Fix — (a) checked access helpers (`accessorAt`, `viewAt`, `bufferAt`) returning new `error.MalformedGltf` on out-of-range indices; (b) checked arithmetic on all offset/size formulas; (c) semantic validation before reading: componentType matches the call's expectation (already partially present), `stride ≥ elem`, checked `byteOffset + count × stride ≤ view.byteLength` and view span within its buffer — this also bounds the output allocation by the input buffer size, no separate budget needed; (d) `readIndices` validates every index `< vertex_count` (passed by the caller) → `error.MalformedGltf`.

- **R6 (medium-high) — extension activation/deactivation atomicity; fabricated spec reference removed** (`src/core/ecs/world.zig`, `src/core/scene/loader.zig`). Root cause: `activateExtension` performs N sequential fallible `addComponentDynamic` calls, then the record insert, then the hook — a mid-loop failure leaves the entity partially extended; `deactivateExtension` is symmetric; `total == 0` extensions are silently accepted. Additionally, loader comments justify the reject-on-conflict policy as "§30.5 reject policy" — **§30.5 contains no such policy** (fabricated reference; the normative text at `engine-scene-serialization.md` §"Note sur l'ordre des extensions" describes cook-time last-wins, whose *runtime* semantics are unspecified). Fix — (a) new grouped Tier-0 ops on `World`: `addComponentsDynamic(gpa, entity, cids: []const ComponentId, values: []const []const u8)` and `removeComponentsDynamic(gpa, entity, cids: []const ComponentId)` — compute the target archetype once, perform a **single migration** (reserve-then-mutate: the migration either completes or leaves the entity untouched in its source archetype), then write all values (infallible memcpy). (b) `activateExtension` becomes: prevalidate everything with zero mutation (open+validate ext bytes, `total == 1` strict — reject 0 as well as >1 with `error.MalformedScene` or a dedicated error, resolve all `ComponentId`s, size checks, conflict check) → reserve the extension-record capacity (`ensureUnusedCapacity`) → grouped add (single fallible step) → record extension (`assumeCapacity`, infallible) → fire `on_attach`. The activation is **committed before the hook**; hook side effects are excluded from rollback (same contract as HF1/D2 for load-time hooks — a hook error propagates but the activation stands). (c) `deactivateExtension`: prevalidate (active record present, ext bytes valid, all declared components resolvable) → fire `on_detach` (existing semantic: hook reads components; post-hook, no fallible step may strand the entity) → grouped remove (single migration) → drop record. (d) Delete every "§30.5 reject policy" comment; replace with: *reject-on-conflict is the provisional runtime policy recorded in `briefs/m1.1.1-hf3-core-robustness-hotfix-3.md`; last-wins runtime semantics (masking, restoration, out-of-order deactivation) are an open design surface scheduled for a dedicated spec session.* No behavioral change to the reject policy itself in this hotfix.

- **R2 (high) — IPC socket must enforce 0600 and verify peer identity** (`src/core/ipc/transport_posix.zig`). Root cause: `Backend.listen` binds with no `chmod`; permissions depend on process umask, contradicting `engine-ipc.md` (§ Sécurité: "permissions du système de fichiers (POSIX 0600)"). The socket path `/tmp/weld-<pid>.sock` is **spec-pinned** (`engine-ipc.md` references it in at least three places) — the path does not move in this hotfix. Fix — (a) `chmod(path, 0o600)` immediately after `bind`, before `listen`; failure is a hard error (`error.BindFailed` or a dedicated error); (b) the authoritative check: on every `accept`, verify the peer's UID equals ours — `SO_PEERCRED` (`getsockopt`) on Linux, `getpeereid` on macOS/BSD — mismatched UID → close the fd, reject the connection. The peer-cred check closes the bind→chmod TOCTOU window: even a connection sneaked in during the window is rejected at accept. (c) Test: bind under `umask(0o000)`, assert the socket file mode is `0600`. `umask` is **process-global**: the test must be serialized against other tests (no parallel umask mutation) and must restore the previous umask in a `defer` unconditionally.

- **R5 + R8 (medium) — Vulkan lifetimes and input guards** (`src/modules/render/gal/vulkan/command_encoder.zig`, `texture.zig`, `pipeline.zig`, `swapchain.zig`, `device.zig`). Verified sub-items: (a) **command buffers are never freed** — no `resetCommandBuffer`/`resetCommandPool`/`freeCommandBuffers` call exists anywhere; the `destroy` comment claiming pool-reset recycling is false; the shared pool grows monotonically per encoder. Fix: `destroy` calls `device.vk_device.waitIdle()` unconditionally (an encoder may have been submitted and still be in flight — freeing an in-flight CB is invalid; conservative Phase-0-style wait, per-encoder fence retirement stays Phase 1+) then `freeCommandBuffers(pool, 1, &cb)`; rewrite the comment to state the actual behavior. (b) `texture.createView`: `errdefer destroyImageView` between creation and the map `put`. (c) `pipeline.createRender` / `createCompute`: `errdefer` destroying the just-created `vk.Pipeline` before the map `put` (layout/render-pass errdefers already exist — verify they cover the whole tail). (d) `swapchain.create`: the raw view-creation loop leaks `views[0..i]` on mid-loop failure, and the adoption-rollback `errdefer` only does a map `remove` — adopted entries are `swapchain_owned = true`, so their registry destroy **skips the native handle**; native `VkImageView`s therefore leak on any failure from adoption through `swapchains.put`. Fix: a `views_created: usize` counter + a single `errdefer` that destroys `views[0..views_created]` natively and removes any registered handles — one native-cleanup path covering the whole function. (e) `Device.init`: `errdefer` destroying the debug messenger (if non-null) so instance-teardown paths don't leak it. (f) `Device.deinit`: destroy `texture_views` **before** `textures` (reverse dependency order). (g) R8 — `createRender` writes `attachments: [9]`/`color_refs: [9]` unguarded: add the same guard as `render_pass.begin` (`color_targets.len + (depth != null) > 9` → `error.Unsupported`) **and** check `color_targets.len` against `physical_device.getPhysicalDeviceProperties().limits.max_color_attachments` (the query pattern already exists in `device.zig`).

- **R7 + R9 (medium/low) — asset hot-reload type check, refcount guard, generation-wrap retirement, protocol bump** (`src/modules/asset_pipeline/loader/Loader.zig`, `registry/Registry.zig`, `root.zig`). (a) R7: `reload` compares `raw.header.asset_type` (as `u16` via `@intFromEnum`) to `handle.type_tag` **before** any payload mutation; mismatch → free `raw.bin`, return new `error.AssetTypeMismatch`. This widens the reload error set, which is **pinned** (doc-comment: change = `WELD_ASSET_PIPELINE_PROTOCOL_VERSION` bump). (b) R9: `retain` guards `refcount == maxInt(u32)` → new `error.ReferenceCountOverflow` (widens `Registry.Error`, same pinned regime). (c) R9: generation stays `u16` — `AssetHandle` is a **FROZEN C0.5 `packed struct(u64)`** with zero spare bits; widening is impossible without breaking the frozen layout. Instead, `freeSlot` **permanently retires** a slot whose generation would wrap: if `slot.generation == maxInt(u16)`, mark the slot dead and do **not** push it to the free list (bounded, documented leak of one slot per 65 535 reuses; the ABA hazard is eliminated, not deferred). (d) One single protocol bump `WELD_ASSET_PIPELINE_PROTOCOL_VERSION: 2 → 3` in `root.zig` covers both error-set widenings; doc-comment records both. AssetHandle layout untouched.

**Gate-review addendum (normative, carried over from HF2).** At every gate, the reviewer crosses the **reserve-then-mutate invariant** against *every composite call surface that reaches the changed leaf*, not the gate's deliverable in isolation. E3 is the paradigm case: HF2's review declared the invariant crossed "against every composite call surface" and still missed `activateExtension` — a composite surface sequencing N fallible mutations. E3's review must confirm no fallible step follows the first observable mutation in both activate and deactivate, including the hook-ordering constraint on deactivate.

**R6 policy record (normative, replaces the fabricated reference).** Runtime extension-conflict policy in this codebase is **reject** (`error.ExtensionComponentConflict`), recorded here as *provisional*. `etch-reference-part2.md §30.5` does not define a reject policy; `engine-scene-serialization.md` (extensions note) defines cook-time last-wins whose runtime semantics (masking, restoration on deactivate, ordering) are unspecified. Reconciliation is a dedicated Claude.ai spec session scheduled immediately after HF3; its output will be updated KB spec files plus, if the policy changes, an implementation milestone. Code comments must point at this brief, never at §30.5.

**R6 hook contract (normative):** activation commits before `on_attach`; hook errors propagate but do not unwind the activation (hook side effects are outside the rollback contract, consistent with HF1/D2). On deactivate, `on_detach` fires first by design (the hook reads the extension's components); everything after the hook must be infallible or single-step-atomic — that is what the grouped remove provides.

**R2 rationale (why the path stays in `/tmp`):** the socket path is spec-pinned in `engine-ipc.md` (referenced at least three times, including the orphan-cleanup scan). The authoritative security boundary after this gate is the peer-UID check at `accept`; `chmod 0600` is the spec-conformance layer. Moving to a `0700` per-user directory would require a spec change plus `cleanup.zig` and editor-launch changes — additive hygiene, not required to close the hole.

**R5a rationale (why `waitIdle`):** an encoder may be destroyed right after `device.submit` while its command buffer is still executing; `vkFreeCommandBuffers` on an in-flight CB is invalid. The unconditional `waitIdle` mirrors the existing Phase-0 pattern already used for `active_pass` teardown. Per-encoder fences are the Phase 1+ replacement, already noted in the code.

**R9 retirement semantics:** a retired slot is a deliberate, bounded leak (one slot index per 65 535 reuses of that same slot). It permanently removes the ABA hazard within the frozen `u64` handle layout. If Phase-2+ ever revisits `AssetHandle`, a wider generation rides that (protocol-bumped) change.

**Checked-arithmetic idiom (E1/E2):** `std.math.add`/`std.math.mul` with `catch return error.<Malformed*>` — never bare `+`/`*` on file-controlled quantities, including quantities that "cannot" overflow on 64-bit; the review verifies this property per gate on the diff.
